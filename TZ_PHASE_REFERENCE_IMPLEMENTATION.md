# TZ_PHASE_REFERENCE_IMPLEMENTATION — реализация независимой фазовой референции `y` (E1…E6)

**Статус:** docs-only ТЗ. Ничего в прошивке, профиле, safety-модулях, allow-list и порогах не меняется
до явного GO владельца. Реализация — отдельным пакетом автора.

**Зависимость и порядок влития:** это ТЗ базируется на tip ветки контракта
`ai2/tz3-map-phase-reference-contract` @ `3183faf5d16383295c09e4ae28f9a733afaf2030`.
Вливать СНАЧАЛА контракт `3183faf5`, ЗАТЕМ это ТЗ. Ветка контракта, ожидающая приёмки, этим ТЗ не изменяется.

**Зачем этот пакет.** B1 закрыт как `PASS / ACCEPTED` с ограничением: относительная фазовая зависимость `I1`
в разрешении B1 (`≤0.8 мкс` span при шаге S&H `≈13.3 мкс`, одно звено 24–36 В) не наблюдаема — при
**пройденном** контроле повторяемости (`Δ 9.5 мА` при пороге `128.32 мА`), что делает отрицательный результат
интерпретируемым. Контракт §9 оставлял развилку (а) ingest-привязка / (б) reference-тракт; решение владельца —
**один пакет, покрывающий и привязку, и измерительный тракт**, без правки прошивки, на существующем
оборудовании (ACS712-20A: CH1 = фаза U, CH2 = фаза V).

## 1. Задача

```text
1.1 ingest: привязка reference к `capture.frame.sequence` по ОБЪЯВЛЕННОМУ воспроизводимому признаку — fail-closed.
1.2 reference-тракт: два РАЗНЫХ фазных тока с независимого датчика в фазном проводе; измеренный Δt
    относительно момента выборки АЦП; объявленное ЧИСЛОМ окно допустимого Δt.
1.3 обязательные негативные контроли: ±1 sample (E4) и отключённый/зашунтированный датчик (E5).
1.4 отчёт E1…E6 с предъявлением сырых данных (не только итоговых чисел).
```

## 3. Схема reference-CSV (обязательные новые поля)

| Поле | Обяз. | Смысл | Правило отказа (fail-closed) |
|---|---|---|---|
| `sample_id` | да | `capture.frame.sequence` той записи, к которой отнесён этот scope-фрагмент | нет поля ⇒ REJECT (не «порядковая привязка») |
| `assoc_feature` | да | значение признака привязки (метка/таймстамп/идентификатор события), по которому фрагмент отнесён к `sample_id` | пусто/`None`/дубликат ⇒ REJECT |
| `assoc_feature_kind` | да | тип признака: `la_marker` \| `scope_edge` \| `other` (обосновать) | неизвестный тип ⇒ REJECT |
| `ref_u_mv`/`ref_v_mv` (+`ref_w_mv`) | да | сырые милливольты датчиков U/V (опц. W) | mV без `--calib` ⇒ REJECT (уже реализовано) |
| `dt_us` | нет | измеренный сдвиг времени фрагмента относительно момента выборки АЦП | вне объявленного окна ⇒ REJECT |
| `pulse` | нет | сохраняется для совместимости, **но доказательством привязки не является** | — |

Правила: смешение `ref_*_ma` и `ref_*_mv` — запрещено (как сейчас); `ref_w` без физического третьего
датчика — KCL, помечается явно и в доказательство привязки не идёт.

## 4. Признак привязки (§3 контракта)

```text
4.1 Признак объявляется ДО прогона (в шапке CSV/в протоколе) и обосновывается как воспроизводимый.
4.2 Допустимые варианты (выбрать один и обосновать): маркер времени на ЛА, записанный ОДНОВРЕМЕННО со
    скопом (общий знаменатель времени); фронт ШИМ на отдельном канале скопа; иной воспроизводимый признак.
4.3 Запрещено: порядок строк, номер `pulse`, совпадение длин/индексов, подстановка «по ближайшему».
4.4 Fail-closed: отсутствие, неоднозначность (несколько кандидатов), дубликат или коллизия признака
    ⇒ строка REJECT. «Допустим с оговоркой» не существует.
4.5 Признак объявляется И ДЛЯ ИЗМЕРИТЕЛЬНОЙ ЧАСТИ (что именно на скопе соответствует какому `seq`),
    и для ingest-проверки (как tool это проверяет), иначе E2 не предъявляем.
```

## 5. Синхронность (Δt) — §4 контракта

```text
5.1 Δt между моментом выборки АЦП (апертура инжектированной конверсии) и эталонной записью ИЗМЕРЯЕТСЯ,
    способ измерения объявляется заранее; оценка погрешности обязательна.
5.2 Окно допустимого Δt объявляется ЧИСЛОМ до прогона; записи вне окна отклоняются, а не «уточняются».
5.3 `trigger id = 0x4F455731` фиксирует идентичность триггерной конфигурации, но синхронность НЕ доказывает.
5.4 EXT TRIG осциллографа как данность НЕ предполагается. Если механизм привязки недоступен — контракт
    не выполнен, и это фиксируется как таковое, а не заменяется предположением.
5.5 Опора на `ts` запрещена: в текущих прогонах `ts = 0` во всех записях (период=0).
```

## 6. Обязательные негативные контроли

```text
E4 (сдвиг ±1 sample): взяв те же реальные данные, привязать reference со сдвигом +1 и −1 sample;
   конвейер ОБЯЗАН отклонить строку. В отчёте указывается, КАКОЙ именно гейт отклонил
   (residual / hold-out / KCL / согласованность). Если сдвиг не отклоняется — привязка НЕ доказана.
E5 (non-tautology): датчик отключён/в упоре (y → 0 или в упор) ⇒ строка REJECT. Идеально точный residual
   сам по себе считается признаком тавтологии и требует разбора, а не приёмки.
Оба контроля выполняются на ТЕХ ЖЕ данных, что и основной прогон, и предъявляются в отчёте.
```

## 7. E1…E6 → исполняемые проверки

| # | Что предъявляется | PASS | REJECT |
|---|---|---|---|
| E1 | тип датчика, точка установки (до/после какого разъёма), калибровка `v0_U/v0_V`, фактический `Vcc`, чувствительность, дата и условия | всё заявлено, калибровка на месте | нет калибровки |
| E2 | 100 % использованных samples: `sample_id == frame.sequence` + признак привязки для каждого | 100 % и признак предъявлен | порядковая привязка, дыры, дубликаты |
| E3 | измеренный Δt + погрешность + окно числом; все использованные samples в окне | все в окне | выход за окно, Δt «по предположению» |
| E4 | сдвиг ±1 sample | строка отклонена (гейт назван) | строка НЕ отклонена |
| E5 | датчик отключён/в упоре | REJECT | приём при «нулевом» y |
| E6 | повтор reference-сессии и смена p1-блока | те же гейты в пределах объявленного допуска | вердикт строки меняется |

## 8. CLI-контракт ingest (предлагаемый)

```text
--calib FILE                  (существует) калибровка ACS712; mV без --calib — отклонять (уже так)
--require-sample-id           (новый) требовать `sample_id` в каждой строке; для reference-режима ВКЛ по умолчанию
--require-assoc-feature KIND  (новый) требовать признак привязки заданного типа
--dt-window-us MIN MAX        (новый) окно Δt; строка вне окна — отказ
--neg-shift {0,+1,-1}         (новый) САМОПРОВЕРКА: умышленный сдвиг привязки (E4) на тех же данных
exit: 0 — PASS · 1 — REJECT по данным (причина в stderr/stdout) · 2 — ошибка прогона/нечитаемые входные
Никаких «мягких» режимов: отсутствие требуемого поля — отказ, а не warning.
```

## 9. Что должно быть предъявлено в возврате

```text
· сырой reference-CSV (как собрано), сырые метки признака привязки (файл ЛА/скопа), лог с `seq`;
· калибровка: v0_U/v0_V, Vcc, sens, дата, условия, источник эталона;
· расчёт Δt: как измерен, погрешность, окно;
· вывод E4 (обе полярности сдвига) и E5 с указанием отклоняющего гейта;
· сводка E1…E6 (таблица из §7) + явные отклонённые строки с причинами;
· selftests инструмента (включая негативные) — но см. §10 о синтетике.
```

## 10. Запреты

```text
· менять прошивку, safety-модули (foc/pwm/protect/vf/adc/adc_dispatch), `.ioc`, allow-list, CCR, апертуру/SMPR/MMS;
· получать `ia/ib` (или `y`) арифметически из `idc1/idc2`, по KCL, из модели FOC/V/f или из предыдущей карты;
· ссылаться на KCL как на доказательство привязки/синхронности (при двух датчиках KCL формален);
· менять окно Δt, допуск, пороги или состав данных ПОСЛЕ получения данных;
· «дотягивать» Δt, подставлять номиналы датчиков, переносить синхронность «по прошлой кампании»;
· спасать старый `Autotune_LsStep` поднятием VBUS до 60 В: B1 дал отрицательный результат для его
  наблюдаемого I1 relative-phase response, а рост SNR не устраняет вопрос «что именно измеряют I1/I2»;
· считать PASS на синтетике доказательством: E2–E5 предъявляются только на РЕАЛЬНЫХ данных;
· смешивать этот пакет с Ls-контуром или с TZ-REF-01 (масштаб).
```
