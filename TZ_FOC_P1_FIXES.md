## P1-1: потеря encoder в FOC_STATE_RUN не останавливает FOC (самый важный)

**Текущее поведение:**
- `src/foc.c:713` — единственный контакт с энкодером: `enc_rpm_raw = ENC_GetSpeed_rpm();` → IIR (718). `ENC_GetError()` в foc.c **не вызывается нигде**.
- `src/encoder.c` корректно публикует `enc_error` (ENC_ERR_TIMEOUT/BAD_PERIOD) и `enc_speed_rpm = 0` при потере сигнала (BAD_PERIOD:146/160, overcapture, timeout).
- RUN продолжается: slip-модель вращает фазу, токи подаются — закрытый контур без реальной обратной связи по скорости.

**Требуется:** в `FOC_RunFrame` (RUN-секция) — детект потери энкодера с гистерезисом:
- `ENC_GetError() != 0` **или** `enc_speed_rpm == 0` непрерывно **N циклов** (N = 5..10, ~1-2 мс при 5 кГц — защита от дребезга/пропуска одиночного кадра; энкодер на 920 Гц периода — пропадание сигнала даёт BAD_PERIOD сразу) → `FOC_Stop()` + причина.
- Причину выводить в телеметрию по образцу существующего handoff-fail (смотри `FOC_GetStartupFailReason`/FAIL= механизм): добавить `FOC_STOP_ENC_LOST` (или переиспользовать существующий enum причины, если подходит).
- Сброс счётчика consecutive при восстановлении (`ENC_GetError()==0 && speed!=0`).
- Стоп из ISR безопасен (PWM_Disable снимает CEN → TRGO исчезает — как в handoff-timeout ветке, foc.c:794-797).

**Не менять:** поведение STARTUP (там потеря энкодера = handoff не пройдёт — уже закрыто).

## P1-2: реверс в RUN — нет контролируемой политики

**Текущее поведение:** `FOC_SetSpeed` (foc.c:314-318) — только clamp к ±max и запись `speed_ref_rpm`. Смена знака target на лету: speed loop инвертирует ток, current limit (FOC_I_MAX_MA) ограничивает момент. Работает, но резко; для АД нет контролируемого перехода через ноль.

**Требуется (минимальный вариант — политика + rate limit):**
1. Задокументировать политику реверса в `foc.h` (комментарий к FOC_SetSpeed): реверс на лету допустим, момент ограничен current limit, двигатель проходит через ноль под током — для стендовых прогонов это приемлемо; полноценный «контролируемый реверс» (ramp через ноль с фиксированным jerk) — отдельная задача, НЕ в этом ТЗ.
2. Опционально (если дёшево): rate limiter на `speed_ref_rpm` в `FOC_RunFrame` (max Δrpm за цикл, константа `FOC_SPEED_RAMP_RPM_PER_S` ≈ 1000..2000 rpm/s) — чтобы и GUI, и команды не могли мгновенно инвертировать скорость. Если вводишь — документируй и не ломай поведение рампы V/f (STARTUP цель обновляется на лету через VF_SetTarget, foc.c:322-326 — там limiter НЕ нужен).

## P1-3: handoff/RUN при невалидном Tr — slip fallback 100 мс опасен

**Текущее поведение:** foc.c:848-863 — при `Tr_rotor_us < 1000`: одноразовое предупреждение (UART_TrySendStr, ISR-safe) + `tr_us = 100000` (fallback 100 мс). Для АД slip = (Iq/Id)/(2π·Tr): реальный Tr ≠ 100 мс → ошибка скорости под нагрузкой в разы (например Tr=300 мс → slip завышен в 3 раза).

**Требуется:** при невалидном Tr (`tr_us < 1000`) — **slip-компенсацию отключить** (`slip_dt = 0`), а не подставлять fallback 100 мс:
- Закрытый контур работает на encoder-скорости без slip — нагрузочная ошибка скорости (проскальзывание), но НЕ ошибка в разы.
- Предупреждение один раз оставить (уже есть, tr_fallback_warned → переименовать/оставить как есть, текст поправить: "Tr not measured — slip compensation disabled").
- НЕ блокировать вход в RUN (иначе мотор не поедет до автотюна — это осознанное решение, не менять).
