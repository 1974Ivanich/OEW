# map_scope_ingest.py — merge scope evidence into the BOAR campaign

`map_scope_ingest.py` объединяет UART-логи `@MC:REC` со scope-слоем стендовой сессии в каноническую кампанию (`manifest.json` + `samples.jsonl`), которую принимает `map_bench_dataset.py`. Инструмент работает fail-closed и не синтезирует измерения.

## Scope reference на ACS712

Для новой схемы используются два независимых датчика **ACS712-20A**, включённых последовательно в фазные провода между инвертором и мотором: CH1 осциллографа подключается к фазе U, CH2 — к фазе V. Это токовая петля датчика, а не DC-link shunt. ACS712 питается от внешних 5.0 В; на J2 платы нет подходящего 5 В питания (J2-25 — 3.3 В, J2-28 — VDD_m). GND датчиков соединяется с GND осциллографа, а силовая сторона остаётся гальванически отделённой. Фактический Vcc записывается в calibration JSON.

Входной FILTER должен быть не более 1 нФ, чтобы сохранить полосу около 80 кГц. **CF=47 нФ устанавливать нельзя**: полоса падает примерно до 2 кГц, ШИМ-пульсации сглаживаются, и показание перестаёт соответствовать точке ADC sample.

ACS712 имеет типовую чувствительность 100 мВ/А при 5 В, ратиометрический выход и нулевой уровень около Vcc/2. Ожидаемый шум около 110 мА pp; при чтении с плато его следует усреднять.

> **НЕ ПОДТВЕРЖДЕНО (15.09.2026).** Оценка «~110 мА pp» (≡ ≈11 мВ pp при
> 100 мВ/А) противоречит измеренному на стенде значению **~100 мВ pp**
> (`docs/STEP_A_ACCEPTANCE.md`). До выполнения контролируемого замера нулевого
> шума (`docs/TZ2_P0_P1_BENCH_PROTOCOL.md` §2.1) обе цифры считаются
> неподтверждёнными; для расчётов SNR брать консервативную (100 мВ pp). Gain имеет заводской разброс, а нулевой уровень температурно дрейфует, поэтому перед каждой кампанией и после изменения питания/прогрева нужно выполнить шаг протокола 0b: при обесточенном моторе измерить Vout обоих датчиков и записать `v0_U`/`v0_V` в calibration JSON. Нельзя полагаться на номинальные 2500 мВ.

## CSV-схемы

Режим определяется по заголовку CSV. Legacy-файл использует `ref_u_ma,ref_v_ma,ref_w_ma` и не требует calibration. Новый ACS712-файл использует сырые показания осциллографа `ref_u_mv,ref_v_mv,ref_w_mv`; `ref_w_mv` обычно оставляется пустым и выводится по KCL. Смешение `*_ma` и `*_mv` в одном заголовке отклоняется.

```csv
pulse,ref_u_mv,ref_v_mv,ref_w_mv,margin_ticks,blanking_ticks,scope_qualified,note
1,2510,2495,,110,15,1,ACS712 CH1=U CH2=V
```

`scope_qualified` должен быть равен 1, `margin_ticks` — не менее 110, а число строк должно совпадать с числом `@MC:REC` записей. Если `ref_w` пуст, инструмент устанавливает `w=-(u+v)` и KCL-проверка формальна. Если `ref_w` заполнен, проверяется `|u+v+w|<=100 мА`.

## Calibration JSON и запуск

Пример calibration-файла:

```json
{
  "vcc_mv": 5003,
  "sensors": {
    "U": {"v0_mv": 2498, "sens_mv_per_a": 100.0},
    "V": {"v0_mv": 2504, "sens_mv_per_a": 100.0}
  }
}
```

`vcc_mv` по умолчанию равен 5000. Если `sens_mv_per_a` не указан, используется `100.0*vcc_mv/5000`; если `v0_mv` не указан, используется `vcc_mv/2`. Явные поля перекрывают эти значения. Конверсия выполняется по формуле `I_ma=(Vout_mV-V0_mV)/sens_mv_per_a*1000`, после чего сохраняется действующий предел `|I|<=10000 мА`. mV-режим без `--calib` отклоняется.

```bash
python3 tools/map_scope_ingest.py \
  --logs DIR --scope DIR --out DIR --calib acs712_calibration.json [--pipeline]
```

Legacy-режим запускается без `--calib`. Для grid-кампании инструмент поддерживает четыре точки на сектор/окно и ожидает восемь импульсов на точку; для одиночной раскладки ожидаются шестнадцать импульсов на регион.

## Fail-closed проверки

До записи результата отклоняются отсутствующий или неполный лог, несовпадение CCR с ожидаемым вектором, отсутствие scope CSV, неверное число строк, `scope_qualified != 1`, margin ниже 110, насыщение ADC, ток за пределом 10000 мА, нарушение KCL для заполненного `ref_w`, а также любая ошибка официального `map_bench_dataset.validate_campaign`. При пустом `ref_w` формальный KCL выполняется самим derived-значением.

Выход 0 означает, что кампания записана и прошла официальный валидатор; выход 1 означает REJECT; выход 2 зарезервирован для ошибки использования CLI.

## Reference-режим: строгая привязка (TZ_PHASE_REFERENCE_IMPLEMENTATION)

CLI по умолчанию работает в СТРОГОМ режиме: привязка reference к записи — только по
`sample_id == capture.frame.sequence` плюс признак из карты (тождество, не корреляция).
Порядок строк доказательством не является (в прежнем тракте было именно так:
`zip(records, scope)` — позиционная привязка).

Обязательные колонки reference-CSV в строгом режиме:

```text
pulse,sample_id,assoc_feature,assoc_feature_kind,ref_u_mv,ref_v_mv[,ref_w_mv],dt_us[,scope_qualified,margin_ticks,blanking_ticks]
```

Карта привязки (снимается на том же прогоне — например, с логического анализатора):

```text
seq,assoc_feature[,assoc_feature_kind]        # assoc_feature_kind ∈ {la_marker, scope_edge, other}
```

Флаги:

```text
--assoc-map FILE                  карта привязки (обязательна в строгом режиме)
--dt-window-us MIN MAX            объявленное окно Δt (мкс); запись вне окна — REJECT
--no-dt-window                    явный отказ от окна (в манифесте null; E3 не предъявляется)
--saturation-margin-mv N          E5: reference обязан лежать в [N, vcc-N] мВ
--neg-shift {0,+1,-1}             E4-самопроверка: сдвиг привязки ОБЯЗАН быть отклонён;
                                  если не отклонён — прогон считается несостоявшимся
--allow-legacy-order-association  ЯВНО разрешить порядковую привязку (штамп positional_legacy)
```

Гейты отказа (каждый отказ называет СВОЙ гейт, а не «числа не сошлись»):

```text
sample_id_coverage · sample_id_unique · assoc_feature_identity · dt_window · reference_saturation
```

Манифест кампании получает блок `association`:

```text
mode ∈ {reference_verified, positional_legacy, shunt_waiver} · independent_reference ·
assoc_map_sha256 · dt_window_us · saturation_margin_mv · neg_shift_gates_used
```

`shunt_waiver` (G0 v4) и `positional_legacy` НЕ являются независимым референсом — это прямо
видно в манифесте, и подменять одно другим не позволяет ни один режим.

Границы: PASS на синтетике доказательством не является — E1…E6 предъявляются на РЕАЛЬНЫХ
данных (см. `TZ_PHASE_REFERENCE_IMPLEMENTATION.md`). KCL при двух датчиках формален и
доказательством привязки не служит.
