# TZ_FOC_REGION_TOO_NARROW — карта BOAR не совместима с FOC

**Дата диагностики:** 2026-09-09
**Стенд:** ПК-3, STM32G474RE, STEVAL-IPM20B×2, 60 В DC-link
**Прошивка:** origin/main@e0148ae (с mapload admission от 194409c)
**Карта:** BOAR 60V campaign (oew_map_v2.bin, 497 байт, CRC 0x0A8A9FAB)

## Наблюдение

`FOC_START` возвращает OK (rc=0), но на первом же цикле FOC тихо останавливается:

```
> foc start
@FOC:START:OK
> status
@FOC:STATE=0 RUN=0 SPD=0 VBUS=0 FAULT=0
```

Мотор стоит, fault нет, но RUN=0 (`foc_running` сброшен).

## Корень проблемы

**FOC_RunFrame (foc.c:1023-1032) требует, чтобы каждый PWM-вектор модуляции лежал ровно в одном регионе карты:**

```c
if(!CurrentMap_SelectNextContext((int16_t)mod_u, (int16_t)mod_v,
                                 (int16_t)mod_w, &next_context) ||
   !next_context.valid || !PWM_SetControlVector(...)) {
    FOC_Stop();   // ← тихий стоп без fault
    return;
}
```

`SelectNextContext` → `region_contains` требует `matches == 1` (вектор в одном регионе).

**Карта BOAR содержит 12 узких «пятен» ±261 Q15 (~±0.8% шкалы) вокруг сертифицированных опорных векторов:**

```
s0w0: mu[7930, 8454] mv[-262, 262] mw[-8454, -7930]   ← ±261 вокруг (8192,0,-8192)
s0w1: mu[8978, 9503] mv[-262, 262] mw[-9503, -8978]   ← ±261 вокруг (9241,0,-9241)
...
12 регионов: 6 направлений (30°, 90°, 150°, 210°, 270°, 330°) × 2 амплитуды
```

Разброс modulation из съёмки (48 точек × 32 импульса = 1536 сэмплов):
- `mu`: ±262 вокруг опорного вектора (Q15 ±261 из CCR ±4 при ARR=999)
- `mv`: ±262 (переключательная фаза, разброс из съёмки)
- `mw`: ±262

Это **естественный разброс съёмки** (grid sweep ±4 CCR), а не геометрическое покрытие сектора.

**Покрытие круга модуляции регионом ≈ ±1.8° из 60° (~3% сектора).**

V/f-разгон (STARTUP) вращает вектор модуляции по окружности (θ от 0, модуляция от 0 до целевой). На каждом цикле `VF_Update` → `Park(θ)` → модуляция (mu, mv, mw). Гарантированно, на большинстве углов вектор находится **вне «пятен»** → `SelectNextContext` возвращает false → тихий `FOC_Stop()` на первом же цикле (~0.2 мс после старта).

**Почему STATE=0 остаётся:** `FOC_Stop` (foc.c:610) **не сбрасывает** `foc_state` — остаётся `FOC_STATE_STARTUP=0`. Только `foc_running` → false → RUN=0 в телеметрии.

## Источник узких bounds

**Board-профиль BOAR v2 (src/map_capture_profiles.c:418-423):**

```c
region->mu_min = MAP_CAPTURE_BOARD_MOD[sector][0] - 2048;
region->mu_max = MAP_CAPTURE_BOARD_MOD[sector][0] + 2048;
region->mv_min = MAP_CAPTURE_BOARD_MOD[sector][1] - 2048;
region->mv_max = MAP_CAPTURE_BOARD_MOD[sector][1] + 2048;
region->mw_min = MAP_CAPTURE_BOARD_MOD[sector][2] - 2048;
region->mw_max = MAP_CAPTURE_BOARD_MOD[sector][2] + 2048;
```

`2048` Q15 = ±6.25% шкалы = ±62.5 CCR при ARR=999 (разброс съёмки ±4 CCR × 15.6× запас).

Это **placeholder** для solver/certifier — регионы рассчитываются офлайн по разбросу съёмки (statistical bounds из кластеров), а не по геометрии секторов.

**Solver/certifier** в текущем пайплайне (`tools/map_artifact_pipeline_cli`) берут статистические bounds из сэмплов (min/max modulation по row), усекают `guard_q15` (из qualifications.region.guard_q15), и кладут в регион. Для BOAR 60V съёмки (48 точек × 32 импульса) разброс именно ±262 Q15.

## Это фундаментальное ограничение, не баг команд

Карта сертифицирована **только в 12 статических опорных точках** (кластеры ±4 CCR съёмки). Вращающийся FOC-вектор (и STARTUP V/f, и RUN за ротором) физически не может всё время находиться в «пятнах» — его траектория непрерывна по кругу модуляции.

Пока регионы узкие — FOC с этой картой **не заведётся ни в каком режиме**, не только в STARTUP.

## Варианты решения (нужен выбор — safety-уровень)

### (a) Широкие секторные регионы — РЕКОМЕНДУЕТСЯ

**Идея:** регионы карты = клинья секторов (6×60° × амплитудные зоны), полное покрытие круга модуляции.

**Реализация:**
- Solver/certifier заменяют statistical bounds на геометрические bounds по секторам.
- Для каждого сектора S и окна W: регион = геометрический клин 60° (например, mu > 0 > mv > mw для сектора 0) × амплитудная зона (окно 0: 6000..10000 Q15, окно 1: 10000..14000 Q15).
- Recon-строки остаются сертифицированными по опорной точке сектора (M оценивается в центре региона, но применяется во всём клине — линейная аппроксимация).

**Требует:**
- Ревизия offline-пайплайна (solver/certifier) — новый contract region = geometry, не statistics.
- Пересборка `oew_map_v2.bin` с новыми bounds.
- Новый стендовый цикл verification (mapload + FOC_START).

**Safety:**
- Recon-строки сертифицированы только в центре региона — интерполяция на край клина вносит error.
- Требуется анализ interpolation error на краях региона (error bounds должны быть < qualification limits).
- Возможно, нужны дополнительные certified points внутри региона (grid более 4 точек).

### (b) Управление только по опорным векторам — НЕ ПОДХОДИТ

**Идея:** FOC без непрерывного вращения — позиционирование по точкам карты (6×2 = 12 статических векторов).

**Проблема:** не подходит для пуска мотора — статические векторы не создают вращающегося поля, ротор не разгонится. Это уже другой режим (positioning / torque control, не FOC).

### (c) Смягчить FOC — НЕ РЕШАЕТ

**Идея:** в STARTUP не требовать регион (окно выборки default), карту применять только в RUN.

**Проблема:** в RUN вектор тоже вращается за ротором → та же проблема с узкими регионами. Не решает.

## Требуется решение

**Рекомендую (a) — широкие секторные регионы.** Это согласуется с замыслом «карта = таблица окно+реконструкция по сектору»: регион определяет сектор SVPWM (6 клиньев по 60°), а реконструкция сертифицирована внутри каждого.

**Следующие шаги:**
1. Safety-owner approves contract revision: region = geometry (sector wedge), не statistics.
2. Solver/certifier redesign: bounds из геометрии секторов, guard_q15 = запас на краях.
3. Error analysis: интерполяция recon-коэффициентов на краях региона (должна быть < solver/certifier limits).
4. Пересборка BOAR 60V campaign с новыми bounds.
5. Verification: mapload + FOC_START + разгон мотора.

**До этого решения:** FOC с картой BOAR не используется — остаётся V/f режим (который не требует map — он использует `vfc_select_context` с широким aperture VfcApertureContract).
