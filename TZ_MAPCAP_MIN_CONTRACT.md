# ТЗ (docs-only, сжатый): минимальный контракт mapcap для перехода к FOC

ПК-2, 20.09.2026 · docs-only · прошивка не изменялась
Заменяет как **активный план** документ `TZ_MAPCAP_EVIDENCE_CONTRACT.md` (тот остаётся справкой
по отложенному долгу: §5.2-полный, §5.3-метрология, per-счётчик, derived-проверка в прошивке).

## 0. Принцип

```text
Не закрываем каждую теоретическую дыру перед следующим шагом.
Закрываем только ту, которая реально блокирует следующий безопасный запуск FOC.
mapcap — не отдельный qualification project.
```

Разделение: **необходимое для запуска FOC** против **академически полной квалификации mapcap**.
Полная квалификация — долг, не блокер.

## 1. Что уже дано (и потому работы не требует)

```text
ADC acquisition                 PASS   (rev7: 9/9 блоков, jeos, UART, safety)
PWM service path                PASS   (rev4…rev7, PWM_ServiceCaptureStart)
I1/I2 response                  PASS   (жив, подписан, нечётен 17/18, повторяем)
sample ↔ CCR                    PROVEN (cap_snapshot читает ЖИВЫЕ CCR + snapshot_matches_request,
                                       расхождение = terminal сессии)
```

## 2. Что ровно одно блокирует сейчас

`@MC:REC` (`main.c:530`) не содержит `sector/window` — значит вопрос «зависит ли (i1,i2) от
sector/window» по существующему логу **непроверяем**. Поля есть в `AdcFrame` (`adc.h:55-56`) и
в `timestamp_cycles` (`:54`) — не хватает только их вывода. Это gap транспорта доказательства.

## 3. Минимальная правка (единственная)

```text
main.c, формат @MC:REC: добавить
    :sec=<frame.tim1_sector>:win=<frame.sample_window>:ts=<frame.timestamp_cycles>
Порядок существующих полей сохранить, ничего не удалять и не переименовывать.
Структуры не менять. Логику безопасности/admission не трогать.
Обновить тесты, которые проверяют состав/парсинг @MC:REC.
```

Больше в прошивке для этого этапа **ничего не требуется**: проверка соответствия CCR запросу уже
существует и работает; вывод метки делает лог пригодным, а не-тавтологичность обеспечивается
offline-пересчётом (§5b).

## 4. Минимальный набор сессий (один bench-визит)

```text
pass 1:  сектора 0..5, окно 0, точка 0        → 6 сессий × 8 импульсов = 48 записей
контроль: повтор одной сессии (например сектор 0, окно 0, точка 0) → +8 = 56 записей
НЕ в pass 1: окно 1, остальные точки сетки, все 12 рядов — только если понадобится (шаг 3 развилки)
```

Профили уже утверждены в прошивной allow-list (`map_capture_profiles.c:180-345`); id собирается
как `0x424F4152 + sector*2 + window`, точка — вариантом в вызове профиля. Новых профилей не вводим.

## 5. Timing: практический критерий для ЭТОГО этапа

> **ADC frame должен быть воспроизводимо связан с тем CCR-состоянием, которое записано в snapshot.**

Проверяется тремя независимыми способами, все доступны без осциллографа:

```text
(a) snapshot == request            (существующая проверка в сессии, PROVEN)
(b) offline-пересчёт (sector, window, point) ИЗ НАПЕЧАТАННЫХ CCR по таблице профиля
    (порядок модуляции / сдвиг кластера / сетка) обязан совпасть с напечатанными sec/win —
    это делает связь фальсифицируемой: метка перестаёт быть echo запроса
(c) повторяемость: CCR и seq/ts внутри сессии стабильны, между повторами совпадают
```

`trigger_offset_ticks=0` и полная метрология TRGO→апертура — **технический долг**, не блокер
(§8). Требовать измерения положения/ширины апертуры перед первым FOC-прогоном не будем.

## 6. Критерии приёмки прогона

```text
HARD (PASS только при всех):
 1. поля sec/win/ts присутствуют в КАЖДОЙ записи @MC:REC
 2. offline-пересчёт (sector,window,point) из CCR совпал с sec/win во ВСЕХ записях
 3. TIM8 CCR внутри сессии неизменны и соответствуют утверждённому профилю
 4. seq растёт строго монотонно, ts не убывает
 5. status/fault без нарушений; записей ровно столько, сколько запрошено
 6. после каждой сессии: CCER=0 · MOE=0 · @BRK:valid=0; uart_drp=uart_trunc=0
 7. покрытие: 6 секторов (окно 0, точка 0) + 1 повтор

DIAGNOSTIC (никогда не HARD):
  вариация (i1,i2) по секторам · повторяемость внутри и между сессиями · raw и масштабированные ·
  знаки · Ires (ZSV/HW-0, в конвенции не участвует)

INTERPRETATION:
  сравнение сигнатур секторов по §7 → DISTINGUISHABLE или NOT_DISTINGUISHABLE
```

## 7. Критерий различимости (регистрируется ЗАРАНЕЕ)

```text
DISTINGUISHABLE, если
  (i)  классы (i1,i2) для пар секторов попарно не пересекаются в пределах диагностического
       конверта (квантование 1 LSB = 12.79 мА + измеренная дисперсия повторов), и
  (ii) результат воспроизводится на контрольном повторе.
NOT_DISTINGUISHABLE — иначе. Выбор «наиболее похожего» сектора/фазы ЗАПРЕЩЁН.
```

Развилка (то, что решает следующий шаг):

```text
DISTINGUISHABLE      → сигнатуру использовать для установления конвенции → строить/принимать map → FOC
NOT_DISTINGUISHABLE  → назвать КОНКРЕТНО недостающий сигнал и исправить только его;
                       серию слепо не расширять
```

## 8. Что НЕ требуется сейчас (явные не-цели)

```text
· абсолютная фазовая точность ADC и полная метрология TRGO→апертура (долг)
· полная физическая квалификация OEW map
· универсальная sampling feasibility
· идеальная симметрия D+/D−  (R — диагностика, не критерий)
· все комбинации sector × window
· всё, что относится к Ls — отдельный независимый вопрос, с mapcap не смешивать
```

## 9. Запреты и инварианты

```text
energize — только по этому ТЗ и явному GO владельца
не трогать: foc.c · protect.c · adc_dispatch.c · pwm.c · adc.c · .ioc · Makefile · both_enable()
не менять: уровень/частоту/профильную таблицу · admission · safety-логику
Ires — ZSV/HW-0, в конвенции не участвует · prod/R — диагностика, не квалификация
«window=1 → физически снято в sampling window #1» — по-прежнему ЗАПРЕЩЕНО формулировать
```

## 10. Артефакты этапа

```text
1. правка печати (§3): main.c + тесты → make/test/cubemx/CI → образ → пакет для стенда
2. лог-инструмент ПК-2: разбор @MC:REC, offline-пересчёт CCR → (sector,window,point),
   кросс-проверка с sec/win, матрица по секторам, вердикт по §7 (никогда не падает)
3. один стендовый прогон (§4) → отчёт по трём уровням (§6)

Порядок: это ТЗ → ревью владельца → GO → правка + образ → прогон → разбор.
```
