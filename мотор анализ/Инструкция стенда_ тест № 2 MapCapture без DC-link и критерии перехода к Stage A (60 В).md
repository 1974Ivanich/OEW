# Инструкция стенда: тест № 2 MapCapture без DC-link и критерии перехода к Stage A (60 В)

**Версия:** 1.0  
**Назначение:** NUCLEO-G474RE + два STEVAL-IPM20B, OEW Motor  
**Режим теста № 2:** **no-HV** — DC-link физически отключён, PC4 не получает имитацию VBUS и остаётся на нулевом уровне.  
**Автор:** Manus AI

> **Цель теста № 2 — не получить записи карты и не разрешить управление двигателем.** Его задача — проверить положительный вход в ограниченный diagnostic MapCapture-путь (`arm` и `run`) и последующее предсказуемое fail-closed завершение при нулевом VBUS. Любая команда FOC/V/f/autotune, `mapcap build=…`, формирование JSONL или подача DC-link в этом тесте запрещены.

## 1. Область действия и ожидаемая логика

Synthetic-профиль `SYNT` рассчитан на 16 ограниченных service-PWM периодов и содержит минимальный VBUS 1000 мВ. При PC4 на нуле входной ADC-кадр либо признаётся насыщенным, либо, если raw-код чуть выше аппаратного нижнего порога, переводится в значение ниже 1000 мВ. В обоих случаях прошивка обязана остановить service PWM, сохранить normal control закрытым и зафиксировать ошибку MapCapture. [1] [2] [3]

| Параметр synthetic-профиля | Значение | Значение для теста № 2 |
|---|---:|---|
| Идентификатор профиля | `1398361684` (`0x53594E54`, `SYNT`) | Используется только для диагностического arm |
| Число импульсов | 16 | При PC4=0 **не должно** быть 16 принятых кадров |
| Тайм-аут | 20 периодов | Не должен быть достигнут при нормальной работе VBUS-гейта |
| Лимит I1/I2 | ±10 А | Не должен стать причиной завершения |
| Допустимый VBUS | 1000–70000 мВ | При PC4=0 должен вызвать fail-closed исход |
| Нормальная admission | `false` | Должна оставаться закрытой весь тест |

## 2. Результат, который считается PASS

Тест считается пройденным, только если диагностический образ допускает `mcarm=SYNT` и `mapcap run`, после чего нулевой VBUS завершает сеанс без записей и без сохраняющегося PWM.

| Контрольная точка | Обязательный результат PASS |
|---|---|
| Arm | `@MC:ARM:cap=…:rc=0` |
| Start | `@MC:RUN:rc=0` |
| Terminal state | `state=5` (`MAP_CAPTURE_FAULTED`), `frames=0`, `dropped=0`, `avail=0` |
| Terminal reason | `term=-11` **или** `term=-12` — см. раздел 7 |
| Записи | Нет строк `@MC:REC`, `@MC:DRAIN:records=0` |
| Силовая часть | После terminal state PWM отключён: MOE=0, таймеры остановлены/выходы не активны |
| Защита | Центральный fault защёлкнут; после проверки результата он очищается только явной командой `f` при SD1/SD2 high |
| Normal control | `control_admitted` не открывался; не запускались FOC/V/f/autotune |

> **Не-PASS:** `records>0`, `state=COMPLETE`, `term=0`, PWM остаётся включённым после terminal state, либо возникает причина отказа, отличная от `-11`/`-12`. Такое событие является блокером Stage A до разбора причины и повторной проверки.

## 3. Роли, оснащение и обязательные ограничения

Оператор стенда отвечает за физическую конфигурацию и решение о начале/остановке. Приёмщик подтверждает ревизию исходного кода, CI и переход к следующей стадии. В тесте используется UART-лог как доказательство, а не устное подтверждение результата.

| Требуется | Условие перед началом |
|---|---|
| DC-link | Физически отсоединён от обоих IPM; DMM подтверждает на обеих шинах менее 1 В |
| PC4 / VBUS | Никакого внешнего имитатора; PC4 остаётся на штатном нулевом уровне |
| Логическое питание | Aux 3,3 В обоих STEVAL подано от отдельного источника, а не от шины Nucleo |
| SD1/SD2 | Высокий уровень, проверен щупом/считыванием; никаких принудительных тестов SD в этой процедуре |
| Отладка | UART 115200 8N1, непрерывная запись полного лога; DMM; осциллограф или ЛА для фиксации bounded service burst и выключения PWM |
| Механика | Вал не должен вращаться; двигателю не даются команды управления |
| ПО | Рабочая копия соответствует согласованной ревизии; нет незапланированных изменений safety-модулей |

Если хотя бы один пункт не выполнен, тест не начинают. Нельзя заменять DC-link низковольтным источником, подавать сигнал на PC4 или использовать `mapcap build` для «проверки заодно».

## 4. Подготовка программного образа

Тест требует **временного диагностического** образа. Его нельзя считать production-, Stage-A- или board-qualified образом. После теста плата возвращается на generic default-deny сборку.

### Шаг 4.1. Зафиксировать исходные данные

1. Открыть новый файл UART-лога, например `campaign_raw/test2_nohv_YYYYMMDD_HHMM/uart.log`.
2. В начале лога записать: SHA прошиваемой ревизии, имя ветки, дату/время, номер платы, COM-порт, оператора и факт «DC-link disconnected; PC4=0».
3. Убедиться, что ранее принятые T1–T4 SD-приёмки всё ещё применимы к этой аппаратной конфигурации. Любое изменение SD-проводки, PWM, protect, ADC или `.ioc` требует повторной оценки/приёмки до дальнейших действий. [4]

### Шаг 4.2. Собрать диагностический образ

В корне репозитория выполнить:

```bash
make clean
make EXTRA_CFLAGS="-DOEW_MAP_CAPTURE=1 -DOEW_MAP_L3=1 -DPWM_OEW_BOARD_REVISION=7 -DOEW_MAP_SYNTHETIC_PROFILE=1 -DOEW_HOST_TEST=1"
make flash
```

Параметры `OEW_MAP_SYNTHETIC_PROFILE=1` и `OEW_HOST_TEST=1` включают **только** временный synthetic allow-list. Флаг `OEW_HOST_TEST` в этом конкретном образе — явный guard для профиля и не является разрешением normal FOC. Его не переносят в Stage A или generic production-сборку. [1]

| Проверка | PASS | Если FAIL |
|---|---|---|
| Сборка | `Build complete!`, нет ошибок компилятора/линкера | Не прошивать; сохранить вывод и устранить проблему в отдельном ТЗ |
| Прошивка | `Download verified successfully` и `MCU Reset` | Не переходить к UART; проверить ST-Link/питание/подключение |
| UART после reset | Порт отвечает, нет непрерывного fault-latch | Остановить, проверить SD и питание модулей |

## 5. Предпусковая проверка на плате

Команды ниже отправлять по одной, сохраняя полный ответ в UART-логе. Перед следующей командой дождаться завершения предыдущего ответа.

| Шаг | Команда / действие | Признак PASS | Действие при отклонении |
|---:|---|---|---|
| 1 | Проверить DMM: обе шины DC-link <1 В; проверить PC4 без внешнего воздействия | Значения зафиксированы в журнале | **STOP**: устранить физическую причину |
| 2 | Включить aux 3,3 В; проверить SD1/SD2 high | SD-линии high; нет fault | **STOP**: не очищать fault при SD low |
| 3 | `sysinfo` | Есть ответ от свежей прошивки | **STOP**: перепроверить прошивку/UART |
| 4 | `p?` и/или `pdump` | PWM исходно выключен; MOE=0 | **STOP**: снять aux, расследовать неожиданный PWM |
| 5 | `a` | I1/I2 около собственных нулевых смещений; VBUS raw ожидаемо около нижней границы; значение сохранить | **STOP**, если I1/I2 насыщены либо VBUS не соответствует состоянию PC4 |
| 6 | `c` | Успешная калибровка текущих каналов | **STOP**: `mcarm` не выполнять при невалидных offsets |
| 7 | `enc` | `err=0`; значение period сохранить как диагностическое | **STOP** при ошибке энкодера, поскольку базовая стендовая целостность не подтверждена |
| 8 | `mapcap status` | Сеанс не активен: `state=0`, `frames=0`, `avail=0` | **STOP**: перезагрузить и выяснить, почему есть активный сеанс |

Нулевой raw Ires допустим для этой топологии CT; это не причина браковать тест. Для I1/I2 и VBUS действуют отдельные anti-saturation условия. [3]

## 6. Выполнение теста № 2

### Шаг 6.1. Arm synthetic request

Отправить:

```text
mcarm=1398361684
```

**Ожидание:** `@MC:ARM:cap=<N>:rc=0`, где `<N>` — ненулевой capture id.

Сразу после этого отправить:

```text
mapcap status
```

**Ожидание:** `state=1` (`MAP_CAPTURE_ARMED`), `term=0`, `frames=0`, `avail=0`. Этот ответ доказывает, что диагностический allow-list действительно сформировал request, offsets валидны, SD/interlock здоровы, и normal control не активен.

> Если получен `@MC:ARM:BLOCKED:PROFILE`, synthetic-флаги не попали в образ либо прошита не та версия. Не продолжайте с `mapcap run`; пересоберите и перепроверьте флаги. Если получен `rc<0`, прекратите тест и разберите именно этот предпусковой гейт.

### Шаг 6.2. Запустить bounded service path

Проверить, что осциллограф/ЛА уже пишет. Затем отправить:

```text
mapcap run
```

**Первичный ответ:** `@MC:RUN:rc=0`.

Это означает только успешное начало ограниченного service-PWM пути. Ответ `rc=0` не является допуском к FOC, не открывает admission и не означает принятие ADC-кадра. Из-за PC4=0 сеанс должен перейти в terminal fault сразу после первого релевантного injected ADC frame.

Подождать не менее одной секунды, не посылая команд управления.

### Шаг 6.3. Зафиксировать terminal state

Последовательно отправить:

```text
mapcap status
mapcap drain
p?
pdump
```

Записать все ответы без редактирования. Ожидаются `state=5`, отсутствие записей и выключенный PWM. На ЛА/осциллографе допустим только короткий service burst до выявления недопустимого кадра; непрерывный PWM после terminal state запрещён.

### Шаг 6.4. Зафиксировать защёлку и безопасно завершить сеанс

1. Сохранить осциллограмму/трейс с именем, связанным с UART-логом.
2. Проверить, что SD1/SD2 по-прежнему high.
3. Только после фиксации доказательств отправить `f` для явной попытки очистить защёлку.
4. Повторить `p?`/`pdump`: PWM остаётся выключенным. Очистка fault никогда не должна сама включать МОЕ или запускать таймеры. [4]
5. Если `f` не очищает fault при SD high, **STOP**: сохранить лог; Stage A запрещена.

## 7. Допустимые terminal status при PC4=0

Порядок проверки в прошивке важен: сначала оценивается пригодность ADC-кадра, и только затем предел VBUS. Поэтому два результата допустимы, а критерий в обоих случаях одинаков: ноль записей и terminal shutdown.

| Состояние raw VBUS | Ожидаемый `term` | Объяснение | Вердикт |
|---|---:|---|---|
| `0` или `1` | `-11` (`MAP_CAPTURE_ADC_FAULT`) | Вход VBUS на нижней границе, ADC-кадр отклонён как saturated до проверки диапазона request | PASS |
| `≥2`, но расчётный VBUS <1000 мВ | `-12` (`MAP_CAPTURE_LIMIT_EXCEEDED`) | ADC-кадр пригоден, но не выполняет нижнюю границу VBUS synthetic request | PASS |
| `0` | `term=0`, `state=COMPLETE`, либо `records>0` | Нулевая шина ошибочно пропущена как годный измерительный режим | **FAIL / blocker** |
| Любой другой отрицательный статус | Например, interlock, offset, trigger, timeout, protection | Не подтверждает запланированный VBUS gate; нужна диагностика | **FAIL / blocker** |

Для `-12` порт фиксирует `PROTECT_FAULT_CAPTURE_LIMIT`; для `-11` применяется центральный capture-ADC fault. В обоих путях `terminal_stop()` останавливает service PWM, останавливает injected ADC, делает expected window невалидным и оставляет admission закрытой. [2] [5]

| PWM не отключается | Критическая safety-аномалия | Не посылать новых стартовых команд; безопасно снять aux/питание по локальной процедуре | непрерывный trace, UART, регистры |

## 9. Завершение теста и возврат платы в безопасное состояние

1. Убедиться, что оба DC-link остаются отсоединёнными и менее 1 В.
2. Сохранить UART-лог, вывод сборки, DMM-показания и PWM-trace локально. Артефакты стенда не коммитировать в репозиторий.
3. Пересобрать и прошить generic default-deny образ:

```bash
make clean
make
make flash
```

4. После reset проверить `p?`: PWM выключен; diagnostic synthetic команды не должны использоваться как рабочий режим.
5. Внести в журнал одну итоговую строку: SHA, фактический raw VBUS, `term`, `records`, MOE после terminal state, результат `f`, имена сохранённых файлов и вердикт PASS/FAIL.

## 10. Gate перехода к реальной Stage A с DC-link 60 В

> **Успешный тест № 2 — необходимое, но недостаточное условие Stage A.** Он доказывает только безопасный отказ при нулевом VBUS; не подтверждает реальный CCR-паттерн, physical sampling window, токовую карту, токовые пределы и не даёт права открыть `control_admitted`.

Переход к Stage A разрешается только после одновременного выполнения всех условий ниже.

| Гейт | Обязательное доказательство | Кто подтверждает | Статус для допуска |
|---|---|---|---|
| T2.1 — test № 2 | Полный UART-лог: arm/run PASS, `term=-11` или `-12`, `records=0`, PWM off; DMM и trace приложены | Оператор + приёмщик | Обязательно PASS |
| T2.2 — SD/interlock | Действующие доказательства T1–T4: SD1/SD2 hardware break, explicit clear, no self-rearm, reset default-deny | Приёмщик | Обязательно PASS; любое изменение hardware/PWM/protect требует повторной приёмки |
| T2.3 — исходный код | Согласованная ревизия, чистый `git diff --check`, зелёный CI с `make test` и commissioning build | Приёмщик | Обязательно PASS |
| T2.4 — стартовый Stage-A capture profile или утверждённая процедура его получения | Отдельно рассмотренный safety-пакет: либо временный board-specific профиль для минимального измерительного burst, либо независимая scope-процедура, которая формирует его константы до `mapcap run` | Приёмщик / safety-owner | Обязательно PASS; `SYNT` и `OEW_HOST_TEST` запрещены на 60 В |
| T2.5 — финальный board-qualified map profile | После Stage A: измеренные и scope-подтверждённые CCR/окна/лимиты, exact equality и полное покрытие, необходимое L3 | Приёмщик / safety-owner | Не является входным условием первого Stage-A burst; обязателен до `mapcap build`, `MAP_READY` и admission |
| T2.6 — физическая подготовка | Письменный план Stage A, назначенный оператор, метод аварийного снятия питания, исправные SD, изолированный/соответствующий измерительный тракт, запись UART и осциллографа | Оператор + ответственный за стенд | Обязательно PASS |
| T2.7 — источник 60 В | DC-link источник установлен на 60 В и **токоограничение задано значением, утверждённым ответственным за стенд для данного двигателя/IPM**; источник выключен до финального preflight | Ответственный за стенд | Обязательно PASS |
| T2.8 — final preflight | На final Stage-A образе: offsets valid, SD high, fault cleared, VBUS/ADC живы, baseline `p?` показывает PWM off | Оператор | Обязательно PASS |
| T2.9 — запреты admission | Нет ручного обхода `ADC_SetControlAdmission`; normal FOC/V/f не допускается до отдельной L3-приёмки | Приёмщик | Обязательно PASS |

### 10.1. Устранить разрыв «профиль нужен для Stage A — данные нужны для профиля»

Реальный final profile нельзя заменить synthetic-профилем. Но проектные материалы фиксируют два последовательных уровня данных: Stage A должна получить физические измерения, а окончательная таблица профиля/карты кодируется после этих данных. При этом текущий `mapcap run` сознательно fail-closed и не запускается без разрешённого request. [1] [2] [6]

Поэтому **тест № 2 сам по себе не даёт автоматического GO к 60 В**. До первой подачи 60 В приёмщик обязан письменно закрыть этот разрыв одним из двух безопасных путей.

| Допустимый путь | Что должно быть утверждено до 60 В | Что запрещено |
|---|---|---|
| **A. Временный Stage-A acquisition profile** | Узкий board-specific request для одного/нескольких минимальных capture bursts: известные ARR/trigger/dead-time, конкретные CCR, sector/window, VBUS и current limits, `pulse_count`/timeout; exact equality; осциллографический план подтверждения | Подмена его `SYNT`, диапазонные проверки, UART-параметры или открытие admission |
| **B. Отдельная scope-процедура предварительной характеризации** | Отдельное safety-ТЗ, которое даёт измеренные константы для последующего узкого request profile, не используя обход MapCapture | Применять `mapcap run` без request profile или менять safety-модули «на месте» |

После получения Stage-A evidence создаётся **final board-qualified profile** и L3-артефакты: полное требуемое покрытие, реконструкция, identity и exact equality. Только этот второй пакет может быть основанием для `mapcap build`, `MAP_READY` и последующего решения об admission. [6] [7]

Пока ни путь A, ни путь B не утверждён, решение — **NO-GO**, даже если тест № 2 завершился PASS.

### 10.2. Финальное решение GO / NO-GO

| Решение | Когда принимается |
|---|---|
| **GO к Stage A** | Все входные пункты T2.1–T2.4 и T2.6–T2.9 имеют документированное PASS, ответственным за стенд утверждены токовый лимит и аварийная процедура, а также принят путь A или B из раздела 10.1 |
| **NO-GO** | Не хватает хотя бы одного доказательства, тест № 2 имеет нецелевой terminal status, есть latched fault без объяснения, CI не зелёный, остаётся только synthetic-профиль, не утверждён путь A/B, либо не утверждены лимит тока и порядок отключения |

Даже после GO к Stage A разрешается только ограниченная capture-кампания с 60 В и токоограничением. Успешный Stage-A захват и появление raw records ещё не разрешают FOC: требуется L3-конвейер, проверка всех требуемых строк карты, приёмка измерительных доказательств и отдельное решение приёмщика об открытии `control_admitted`.
