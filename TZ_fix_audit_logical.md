# ТЗ: исправление логических ошибок OEW FOC / Auto-Tune (аудит L1–L12)

**Проект:** OEW Motor FOC — STM32G474RE (Nucleo-G474RE), 2× STEVAL-IPM20B
(SLLIMM STGIB20M60TSL), общий DC-link, асинхронный двигатель (OEW, 6 концов).
**Стек:** CMSIS-only (без HAL), C99, arm-none-eabi-gcc, Makefile, hosted+QEMU
тесты, Python GUI (`nucleo_debug_tool.py`, `vf_panel.py`).
**Источник:** внешний аудит «Аудит логических ошибок OEW FOC и Auto-Tune» (12 пунктов L1–L12).
**Вердикт интегратора:** 5 пунктов — осознанный fail-closed дизайн (НЕ исправлять, см. §2),
7 пунктов — реальные баги (исправить, §1). L9 верен по сути, но неточен в цифре (default pole_pairs FOC = 6, не 4).

---

## 1. Исправления (все в одном пакете, по порядку)

### F1 (аудит L5): гарантированный сброс `g_autotune_busy` во всех Auto-Tune entry points

- **Файл:** `src/autotune.c`
- **Текущее поведение:** `Autotune_DetectChannel()` ставит `g_autotune_busy = 1` (строка ~401) и не сбрасывает ни на одном пути выхода. `Autotune_ProbePhase()` ставит `busy = 1` (строка ~558) и сбрасывает только на успешном пути (строка ~623); error-пути (например, `AT_SafetyCheck() != 0`) выходят без сброса. После команды `ch` (`Autotune_IsActive()` == true) `map_capture_port.c` блокирует capture — commissioning-цикл застревает.
- **Требование:** единый cleanup (паттерн `goto cleanup`) во ВСЕХ функциях, которые ставят `g_autotune_busy = 1` (строки 401, 558 — проверить также 63/80, общий механизм `AT_TestBegin`/`AT_TestEnd`): `g_autotune_busy = 0` гарантированно на каждом пути выхода (успех И каждая ошибка).
- **Критерий приёмки:** после любой команды `ch`/`chu`/`chv`/`chw` (успех или ошибка) `Autotune_IsActive() == false`; команда `mapcap` не блокируется по `Autotune_IsActive`. Где возможно — hosted-тест на cleanup.

### F2 (аудит L7): `TRIG_Low()` при неудачном `VFC_Start()`

- **Файл:** `main.c`, команда `vf=` (строки ~677–684)
- **Текущее поведение:** `TRIG_High()` → `VFC_Start(a1)` → при `vfc_rc != VFC_START_OK`: печать + `vflog_period_ms = 0` + `break` — `TRIG_Low()` НЕ вызывается. Поскольку текущий `VFC_Start()` всегда возвращает ошибку, PB6 воспроизводимо зависает высоким после каждой попытки `vf=`.
- **Требование:** `TRIG_Low()` в error-ветке перед `break`. Дополнительно (для надёжности) — сброс триггера в `VFC_Stop()` и общем fault/stop cleanup, если это не меняет существующее поведение остановки.
- **Критерий приёмки:** после неудачного `vf=N` PB6 гарантированно низкий (проверка ЛА/осциллографом на стенде; статически — вызов присутствует на всех путях).

### F3 (аудит L8): `VFC_Start()` применяет `target_rpm`

- **Файл:** `src/vf_control.c` (строки 58–69)
- **Текущее поведение:** `(void)target_rpm;` — цель игнорируется, `VFC_SetTarget()` не вызывается. Гейт `VFC_START_CONTEXT_UNVERIFIED` — **НЕ ТРОГАТЬ** (fail-closed, см. §2).
- **Требование:** в начале `VFC_Start()`: клампить `target_rpm` в диапазон `±VFC_MAX_RPM` и применить через `VFC_SetTarget(target_rpm)` (или эквивалент: `vfc.target_rpm` и `vfc.ramp_target_rpm`) ДО существующих проверок; затем — существующая логика гейтов без изменений.
- **Критерий приёмки:** после `VFC_Start(1500)` (даже если возвращена ошибка) `VFC_GetTarget() == 1500`. Hosted-тест `vf_control_test` дополнен проверкой.

### F4 (аудит L9): единый источник истины для `pole_pairs`

- **Файлы:** `src/vf_control.c`, `src/foc.c`, `main.c`
- **Текущее поведение:** FOC хранит собственный `pole_pairs` (`foc.c:127`, default `FOC_DEFAULT_POLE_PAIRS = 6`), V/f читает `g_motor_params.pole_pairs` с fallback `1` (`vf_control.c:128-129`). `Autotune_Init()` обнуляет `g_motor_params` → после init V/f считает `f_e` для p=1, FOC — для p=6. Рассинхрон.
- **Требование:** один источник истины. Предлагаемое решение (допустимы эквиваленты):
  1. V/f использует `FOC_GetPolePairs()` вместо `g_motor_params.pole_pairs` (защита `if (pp < 1) pp = 1` остаётся);
  2. `FOC_SetPolePairs()` дополнительно зеркалит значение в `g_motor_params.pole_pairs`;
  3. после инициализации (в `main.c`, после `FOC_Init()`/`Autotune_Init()`) синхронизировать `g_motor_params.pole_pairs = FOC_GetPolePairs()`.
- **Критерий приёмки:** `f_e = FOC_GetPolePairs()·n/60 + slip` в V/f; после `Autotune_Init` значение не теряется (== `FOC_DEFAULT_POLE_PAIRS`); hosted-тест.

### F5 (аудит L10): атомарное применение `mp=` (Lσ по свежим роторным параметрам)

- **Файл:** `main.c` (строки ~607–629)
- **Текущее поведение:** `FOC_SetMotorParams(a1, a2, Vbus)` вызывается ДО записи `Rr/Lm/Tr/Ke/p/J` в `g_motor_params`. `FOC_SetMotorParams()` считает `Lσ` по текущим `g_motor_params.Lm_uH/Tr_rotor_us/Rr_mOhm` → первый `mp=` даёт `Lσ ≈ Ls` (роторные параметры ещё нулевые).
- **Требование:** сначала записать ВСЕ переданные параметры в `g_motor_params` (+ `measured_mask`), затем ОДИН вызов применения (`FOC_SetMotorParams(Rs, Ls, Vbus)` + `FOC_SetPolePairs(p)` + пересчёт), затем вывод `@MP:OK`. Результат первого `mp=` должен совпадать с повторным `mpapply`.
- **Критерий приёмки:** первый `mp=5000,50000,3000,20000,15000,0,4,0` даёт `Lsig`, рассчитанный по переданным `Rr/Lm/Tr`, а не `≈Ls`. Статическая проверка порядка вызовов + описание в отчёте.

### F6 (аудит L11): поле `drp` в CSV V/f

- **Файл:** `vf_panel.py` (строки 27–28)
- **Текущее поведение:** `CSV_FIELDS` заканчивается на `'fault'`; формат `@VFLOG` в `main.c:155-157` содержит ещё `drp=%lu` (счётчик отброшенных UART-пакетов). Поле теряется при записи `telemetry.csv`.
- **Требование:** добавить `'drp'` в конец `CSV_FIELDS`; убедиться, что число колонок совпадает с числом аргументов `@VFLOG`.
- **Критерий приёмки:** `telemetry.csv` содержит колонку `drp` с непустыми значениями в V/f-сессии.

### F7 (аудит L12): исключить гонку sigrok-захвата и старта V/f

- **Файл:** `vf_panel.py` (`_vf_start`, строки 103–120)
- **Текущее поведение:** поток `_capture_sigrok` стартует (строка 115), затем СРАЗУ отправляются `vfk=...` и `vf=...` (строки 119–120). Фронт PB6 (аппаратный триггер) может уйти раньше, чем анализатор готов к съёму.
- **Требование:** захват должен быть ПОДТВЕРЖДЁН как готовый ДО отправки `vf=`: `threading.Event` — поток `_capture_sigrok` сигналит о готовности (после запуска/открытия sigrok-cli), `_vf_start` ожидает событие с таймаутом перед `send("vf=")`. Без фиксированных `time.sleep`-магий. При таймауте — понятное сообщение пользователю (запуск без захвата или отмена — на усмотрение, но поведение задокументировать в коде).
- **Критерий приёмки:** фронт PB6 не может произойти раньше готовности захвата; повторные прогоны стабильны (субъективно: стартовый фронт попадает в захват).

## 2. ЧТО НЕ ЯВЛЯЕТСЯ ОШИБКОЙ И ЗАПРЕЩЕНО К ИЗМЕНЕНИЮ

Следующие пункты аудита — **осознанный fail-closed дизайн** текущей ветки
(generic safety-locked пакет до board-qualified commissioning). НЕ менять:

- **L1** — `both_enable()` в `autotune.c:1466` намеренно НЕ включает мосты (комментарий в коде: «прямого включения мостов больше НЕТ»). Запрещено возвращать прямую запись `CCER/BDTR/CEN/EN`.
- **L2** — `MapCaptureProfile_IsApproved()`/`MapCaptureProfile_BuildRequest()` (`map_capture_profiles.c`) намеренно возвращают `false` («Deliberately fail closed»).
- **L4** — безусловный `VFC_START_CONTEXT_UNVERIFIED` — fail-closed до валидного sample context. Снимать гейт НЕЛЬЗЯ (разрешено только внутреннее изменение F3).
- **L6** — `OEW_HS1_COMMISSIONING_RELEASE=0` в Makefile (firmware-сборка) — осознанный default-deny до стендовых тестов SD-защиты.
- **L3** (отсутствующий pipeline «mapcap → построение карты → `CurrentMap_LoadMeasured`») — НЕ ошибка текущего кода, а отсутствующая commissioning-фича; в этот пакет НЕ входит (отдельное ТЗ).

Дополнительные запреты:
- Не менять `src/pwm.c`, `src/pwm.h`, `src/protect.c` (safety-путь: BKIN, MOE, PRIMASK-commit), `.ioc`, распиновку.
- Не добавлять HAL, не менять стиль/формат существующего кода вне правок.
- Никакого попутного рефакторинга, переименований и «косметики» вне пунктов §1.

Для `src/autotune.c` и `src/vf_control.c` допустимы полные replacement-файлы, но с сохранением CRLF и без изменения несвязанных строк.
