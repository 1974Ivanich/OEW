# Инструкция по проведению исследований FOC-системы 3_Phase_Bolt

## 1. Подготовка стенда

### 1.1. Аппаратная часть
- STM32G474RE (NUCLEO-G474RE)
- Силовой мост: двойной инвертор (OEW-топология, TIM1 + TIM8)
- Двигатель: асинхронный, параметры в прошивке (Rs, Rr, Ls, Lr, Lm, p_pairs)
- Питание шины DC (рекомендуется 24 В для первых тестов)
- Токовые шунты: 6 каналов (2 × 3 фазы)
- UART: USB-COM, 921600 бод

### 1.2. Распиновка Nucleo-G474RE

> **Внимание:** Nucleo-G474RE использует LQFP64 корпус STM32G474RE.
> Пины обозначены по разъёмам платы Nucleo (CN7, CN8, CN9, CN10).
> Нумерация пинов на разъёмах может отличаться от Arduino-совместимых меток (A0..A5, D0..D15).

#### Силовые выходы ШИМ (6 пар, complementary)

| Разъём.Пин | Порт MCU | Сигнал | Назначение |
|---|---|---|---|
| CN10-17 | PA8 | TIM1_CH1 | Инвертор 1, фаза A, верхний ключ |
| CN10-20 | PB13 | TIM1_CH1N | Инвертор 1, фаза A, нижний ключ |
| CN10-14 | PC1 | TIM1_CH2 | Инвертор 1, фаза B, верхний ключ |
| CN8-3 | PB0 | TIM1_CH2N | Инвертор 1, фаза B, нижний ключ |
| CN10-11 | PA10 | TIM1_CH3 | Инвертор 1, фаза C, верхний ключ |
| CN10-22 | PB15 | TIM1_CH3N | Инвертор 1, фаза C, нижний ключ |
| CN10-4 | PC6 | TIM8_CH1 | Инвертор 2, фаза A, верхний ключ |
| CN8-14 | PB3 | TIM8_CH1N | Инвертор 2, фаза A, нижний ключ |
| CN10-6 | PC7 | TIM8_CH2 | Инвертор 2, фаза B, верхний ключ |
| CN8-16 | PC11 | TIM8_CH2N | Инвертор 2, фаза B, нижний ключ |
| CN10-9 | PC8 | TIM8_CH3 | Инвертор 2, фаза C, верхний ключ |
| CN8-15 | PB1 | TIM8_CH3N | Инвертор 2, фаза C, нижний ключ |

> Dead-time = 120 тактов таймера (≈1.41 мкс при 170 МГц), зашит в CubeMX.
> TIM1 — master (генерирует TRGO Update → триггер АЦП), TIM8 — slave (синхронизирован).

#### АЦП — токовые шунты (6 каналов)

| Разъём.Пин | Arduino метка | Порт MCU | ADC | Канал | Назначение |
|---|---|---|---|---|---|
| CN7-12 | A0 | PA0 | ADC1 | IN1 | Инвертор 1, фаза A (ia1) |
| CN7-14 | A1 | PB14 | ADC1 | IN5 | Инвертор 1, фаза B (ib1) |
| CN7-16 | A2 | PC0 | ADC1 | IN6 | Инвертор 1, фаза C (ic1, отладочный) |
| CN7-11 | A3 | PA1 | ADC2 | IN2 | Инвертор 2, фаза A (ia2) |
| CN7-15 | A4 | PA6 | ADC2 | IN3 | Инвертор 2, фаза B (ib2) |
| CN7-17 | A5 | PA7 | ADC2 | IN4 | Инвертор 2, фаза C (ic2, отладочный) |

> **Важно:** Фаза C в обоих инверторах вычисляется по Кирхгофу (ic = zero_sum − ia − ib),
> а не измеряется напрямую. ADC1 IN6 (PC0) и ADC2 IN4 (PA7) используются только
> для отладки (last_raw_c1, last_raw_c2 в стриме). Триггер АЦП — TIM1_TRGO (Update event).
> ADC работает в dual mode: ADC1 + ADC2 simultaneously injected, 12-bit, 12.5 cycles sampling.

#### UART (управление и телеметрия)

| Разъём.Пин | Порт MCU | Сигнал | Назначение |
|---|---|---|---|
| CN10-33 | PA2 | USART2_TX | TX → PC (телеметрия, команды) |
| CN10-34 | PA3 | USART2_RX | RX ← PC (команды) |

> На плате Nucleo USART2 подключён к ST-LINK VCOM (USB-CDC).
> Бодрейт: 921600. Можно использовать либо USB ST-LINK VCOM,
> либо внешний USB-UART адаптер на пинах PA2/PA3.

#### Отладка и служебные пины

| Разъём.Пин | Порт MCU | Сигнал | Назначение |
|---|---|---|---|
| CN10-12 | PA13 | SWDIO | ST-Link отладка (SWD) |
| CN10-14 | PA14 | SWCLK | ST-Link отладка (SWD) |
| CN7-23 | PC13 | EXTI13 | Кнопка USER (B1) |
| CN7-24 | PA5 | GPIO_Output | LED2 (зелёный, LD2) |

#### Питание

| Разъём.Пин | Назначение |
|---|---|
| CN7-8 | 3V3 — питание логики 3.3 В |
| CN7-20 | GND — земля логики |
| CN7-4 | VIN — вход питания 5V (от USB ST-LINK) |
| A0..A5 | Аналоговые входы — диапазон 0..3.3 В, не превышать! |

#### Кварцы

| Порт | Назначение |
|---|---|
| PF0 (OSC_IN) | HSE 8 МГц (от ST-LINK MCO) |
| PF1 (OSC_OUT) | HSE |
| PC14 (OSC32_IN) | LSE 32.768 кГц |
| PC15 (OSC32_OUT) | LSE |

> Системная частота: 170 МГц (PLL из HSE 8 МГц × 42.5).

#### Схема подключения силовой части (OEW — Open-End Winding)

```
                     Nucleo-G474RE
                     ┌──────────────┐
  DC+ ───────────────┤              │
                     │              │
  Инвертер 1:        │              │
  PA8  (TIM1_CH1)   ─┤─ Верх A1     ├── Фаза A обмотки ──┐
  PB13 (TIM1_CH1N)  ─┤─ Низ  A1     │                     │
  PC1  (TIM1_CH2)   ─┤─ Верх B1     ├── Фаза B обмотки ──┤
  PB0  (TIM1_CH2N)  ─┤─ Низ  B1     │                     │
  PA10 (TIM1_CH3)   ─┤─ Верх C1     ├── Фаза C обмотки ──┤
  PB15 (TIM1_CH3N)  ─┤─ Низ  C1     │                     │
                     │              │   OEW: обмотка      │
  Инвертер 2:        │              │   открыта с обоих   │
  PC6  (TIM8_CH1)   ─┤─ Верх A2     ├── Фаза A' ─────────┤
  PB3  (TIM8_CH1N)  ─┤─ Низ  A2     │                     │
  PC7  (TIM8_CH2)   ─┤─ Верх B2     ├── Фаза B' ─────────┤
  PC11 (TIM8_CH2N)  ─┤─ Низ  B2     │                     │
  PC8  (TIM8_CH3)   ─┤─ Верх C2     ├── Фаза C' ─────────┘
  PB1  (TIM8_CH3N)  ─┤─ Низ  C2     │
                     │              │
  DC- ───────────────┤              │
                     └──────────────┘

  Токовые шунты (измерение):
  PA0  (ADC1_IN1) ← Шунт фазы A, инвертер 1   (ia1)
  PB14 (ADC1_IN5) ← Шунт фазы B, инвертер 1   (ib1)
  PC0  (ADC1_IN6) ← Шунт фазы C, инвертер 1   (ic1, отладка)
  PA1  (ADC2_IN2) ← Шунт фазы A, инвертер 2   (ia2)
  PA6  (ADC2_IN3) ← Шунт фазы B, инвертер 2   (ib2)
  PA7  (ADC2_IN4) ← Шунт фазы C, инвертер 2   (ic2, отладка)

  UART:
  PA2 (USART2_TX) → PC
  PA3 (USART2_RX) ← PC
```

## 2. Прошивка и подключение

1. Собрать проект в STM32CubeIDE (Debug или Release конфигурация)
2. Прошить MCU (ST-Link)
3. Открыть GUI `python gui.py`, выбрать COM-порт, нажать **Connect**
4. Проверить диагностику: ISR ~10000 Гц, калибровка — должна пройти автоматически

При старте MCU выводит:
```
System Started. Pure FOC Mode.
FLASH LOG: resumed at N records (addr=0x0804XXXX)   ← если есть записи во flash
```

## 3. Система логирования — три уровня

### 3.1. UART JSON-стрим (50 Гц, real-time)
- **Что:** телеметрия в реальном времени (~20–50 кадров/сек)
- **Поля:** токи (6 каналов), Id/Iq, Vd/Vq, скорость, угол, slip, Te, psi,
  P/Q, e_alpha/e_beta, Kdt, DTC flags, sat_flags, ISR timing, flash log status
- **Назначение:** мониторинг при подключённом PC, запись в CSV
- **Управление:** `stream on` / `stream off` или кнопка в GUI
- **CSV:** кнопка "Start CSV Log" в GUI → `captures/run_YYYYMMDD_HHMMSS.csv`

### 3.2. Burst capture (5 кГц effective, 200 мс окно)
- **Что:** высокоскоростной захват 1024 отсчётов (каждый 2-й такт ISR)
- **Поля (40):** ts, ia1..ic2, izs, ang, id, iq, idT, iqT, vd, vq, vd_raw, vq_raw,
  wr, slip, psi, te, pi_id_i, pi_iq_i, pi_spd_i, sat_flags, e_alpha, e_beta,
  tgt_spd, theta_jit, diq_dt, dwr_dt, p_elec, q_elec, kdt, dtc_corr, d1a..d2c
- **Назначение:** анализ fault, колебаний, переходных процессов, формы тока
- **Триггеры:**
  - Ручной: команда `capture` или кнопка "Capture Burst" в GUI
  - Авто: fault (overcurrent, di/dt, RMS), FOC_LOST — захват сохраняется в SRAM,
    но не записывается в файл (только просмотр)
- **CSV:** `captures/burst_YYYYMMDD_HHMMSS.csv` (только ручной захват)
- **Окно:** ~200 мс (1024 сэмпла × 2 такта × 100 мкс = 204.8 мс)
  - Pre-trigger: ~100 мс
  - Post-trigger: ~100 мс

### 3.3. Flash Black Box (10 Гц, до 13 минут)
- **Что:** компактные 32-байтные snapshot-записи в flash bank 2 (256 КБ)
- **Поля (17):** ts, id, iq, vd, vq, wr, slip, te, psi, sat, foc_state, p, q,
  ea, eb, kdt, fault
- **Назначение:** запись всего сеанса без PC, переживает сброс питания
- **Управление:**
  - `flashlog on` / `flashlog off` — включение/выключение записи
  - `flashinfo` — статус (записей, страниц, адрес)
  - `dumpflash` — выгрузка всех записей в CSV по UART
  - `clearflash` — стирание bank 2 (полная очистка)
- **CSV:** `captures/flashlog_YYYYMMDD_HHMMSS.csv`
- **Возобновление:** при старте MCU автоматически находит последнюю пустую
  запись и продолжает с неё (resume после сброса питания)
- **Сигнализация переполнения:**
  - UART: `WARNING: FLASH LOG FULL` каждые 10 сек
  - JSON: поле `"flg":"recs/pages/en/full"`
  - GUI: красный текст `flash: FULL N recs`

## 4. Полный цикл исследования

### 4.1. Подготовка к тесту

```
clearflash          ← очистить flash от предыдущих тестов (если нужно)
flashinfo           ← проверить, что flash пуст
calib               ← сбросить калибровку АЦП (проводится автоматически при start)
```

### 4.1.5. Идентификация параметров двигателя (Test L/R)

> **Внимание:** Выполняется ОДИН раз перед первым запуском двигателя.
> Результаты сохраняются только в RAM — после перезагрузки МК нужно повторить.

#### Что измеряет Test L/R

| Параметр | Как | Формула |
|---|---|---|
| L (индуктивность фазы) | Отклик тока на шаг напряжения | L_phase = V_applied / (di/dt) |
| R (сопротивление фаза-фаза) | Установившийся ток в конце импульса | R = 2·V_applied / I_final |
| Rs, Rr | Деление R пополам | Rs = Rr = R / 2 |
| Ls, Lr | Эвристическая оценка (×15) | Ls = Lr = L × 15 |
| Lm | Вычитание рассеяния | Lm = Ls − L / 2 |
| PI KP, KI | Расчёт по L и R | KP = 500·L / Vdc, KI = 500·R / Vdc |
| I_max, I_rms | По току теста | I_max = I_final × 2.5, I_rms = I_final × 1.5 |

> **R соответствует показаниям мультиметра** между двумя фазами (phase-to-phase).
> **p_pairs** (число пар полюсов) тестом НЕ определяется — задаётся вручную
> через правку `g_motor.p_pairs` в коде.

#### Пошаговая процедура

**Шаг 1. Калибровка нуля АЦП**
```
calib               ← калибровка offset токовых датчиков (мотор обесточен)
```
- Мотор НЕ подключён к нагрузке, ШИМ на нейтрали
- ~0.2 с, 2000 выборок
- Проверить: в стриме `calibrated=1`

**Шаг 2. Зафиксировать ротор**
- Ротор двигателя должен быть МЁРТВО зафиксирован
- При Test L/R на обмотки подаётся ~20% Vdc — ротор дёрнется

**Шаг 3. Test L/R**
```
testL               ← подаёт тестовый импульс (50 выборок, 5 мс)
```
- МК выводит `$TESTL_BEGIN..$TESTL_END` с массивом токов
- GUI автоматически:
  1. Вычисляет L, R, Rs, Rr, Ls, Lr, Lm
  2. Отправляет в МК: `MP<rs,rr,ls,lr,lm>` — параметры FOC-наблюдателя
  3. Отправляет в МК: `KP`, `KI`, `I_max`, `I_rms`, `DT` — настройки PI-регулятора
  4. Показывает результат в окне статуса

**Шаг 4. Проверка результата**
- В GUI: `L=XX.X mH R=XX.X Ohm` — должны быть разумные значения
- Подробности в текстовом окне: Rs, Rr, Ls, Lr, Lm, KP, KI
- При необходимости — корректировка вручную: `MP0.5,0.3,0.01,0.01,0.009`

**Шаг 5. Проверка p_pairs**
- Если число пар полюсов отличается от 2 (дефолт), задать вручную:
  `MP<Rs>,<Rr>,<Ls>,<Lr>,<Lm>` — НО p_pairs через MP не меняется
- Для изменения p_pairs: правка `g_motor.p_pairs` в `main.c` и перешивка

#### Типовые значения для справки

| Параметр | Типовой диапазон | Единицы |
|---|---|---|
| R (суммарное) | 0.5 – 10 | Ом |
| L (рассеяния) | 0.1 – 5 | мГн |
| Ls = Lr | 1.5 – 75 | мГн |
| Lm | 1 – 70 | мГн |
| I_test | 0.5 – 5 | А |

### 4.2. Запуск двигателя

**Вариант A — Автоматический (рекомендуется для первого включения):**
```
start               ← полная последовательность: калибровка → разгон → ZSC автотюн → FOC
```
Последовательность:
1. Калибровка АЦП (автоматически)
2. Разгон до FOC_MIN_STARTUP_HZ (15 Гц)
3. ZSC автотюн (2 сек на релейном методе)
4. Восстановление целевой скорости и вход в FOC

**Вариант B — Ручной (для отладки):**
```
s20                 ← задать скорость 20 Гц
stream on           ← включить телеметрию
start               ← запуск (калибровка + разгон)
                    ← дождаться "FOC ENGAGED"
zscatune            ← ручной ZSC автотюн (после разгона)
```

### 4.3. Настройка параметров во время работы

| Команда | Описание | Пример |
|---|---|---|
| `s<val>` | Целевая скорость, Гц | `s50` |
| `p<val>` | Целевая мощность, о.е. | `p0.5` |
| `i<val>` | Целевой ток, А | `i2.0` |
| `KP<val>` | Пропорциональный коэффициент PI | `KP0.1` |
| `KI<val>` | Интегральный коэффициент PI | `KI25` |
| `MP<rs,rr,ls,lr,lm>` | Параметры двигателя | `MP0.5,0.3,0.01,0.01,0.009` |

### 4.4. DTC (адаптивная компенсация мёртвого времени)

```
dtc on              ← включить адаптацию Kdt
dtccomp on          ← включить компенсацию в ШИМ
dtcinfo             ← текущее состояние: Kdt, corr, enorm, flags, ticks
                    ← дождаться "DTC CONVERGED" (~3 сек после входа в FOC)
```

Если Kdt ползёт к 0 или к максимуму:
```
DS-1                ← инвертировать знак градиента
dtcreset            ← сбросить Kdt к значению по умолчанию
```

Ручная установка Kdt (для сравнения с адаптивной):
```
dtc off             ← заморозить адаптацию
DK150               ← установить Kdt = 150
dtccomp on          ← применить компенсацию
```

### 4.5. Эксперименты

#### Эксперимент 1: Разгон и установившийся режим
```
clearflash
stream on
s50                 ← целевая скорость
start               ← запуск
                    ← ждать установления (5–10 сек)
capture             ← захват burst для анализа переходного процесса
                    ← плавно менять скорость: s100, s150, s200...
stop                ← остановка
dumpflash           ← выгрузка всего сеанса из flash
```

#### Эксперимент 2: Field weakening
```
clearflash
stream on
s300                ← высокая скорость (FW должен включиться)
start
                    ← наблюдать sat_flags: бит SAT_FW (0x02)
                    ← наблюдать Id — должен стать отрицательным
capture             ← захват в режиме FW
s350                ← увеличить скорость
capture
stop
dumpflash
```

#### Эксперимент 3: SVPWM проверка
```
clearflash
stream on
s250                ← скорость, где модуляция близка к пределу
start
                    ← наблюдать Vd/Vq и sat_flags
                    ← SVPWM расширяет линейный диапазон до 1.0
                    ← FW должен включаться позже (по скорости)
capture
stop
dumpflash
```

#### Эксперимент 4: Нагрузочный шаг
```
clearflash
stream on
s100
start
                    ← ждать установления
i1.0                ← малый ток (холостой ход)
                    ← ждать 3 сек
i3.0                ← шаг тока (нагрузка)
capture             ← захват реакции на шаг тока
                    ← ждать 3 сек
i1.0                ← снятие нагрузки
capture
stop
dumpflash
```

#### Эксперимент 5: ZSC автотюн
```
stream on
s50
start
                    ← ждать FOC ENGAGED
zscatune            ← запуск релейного автотюна
                    ← ждать "ZSC AUTOTUNE DONE"
                    ← наблюдать Izs — circulating current должен уменьшиться
capture
```

#### Эксперимент 6: Auto-Tune контура тока (из GUI)
1. Установить скорость s50, запустить `start`
2. Нажать кнопку "Auto-Tune I-Loop" в GUI
3. Скрипт автоматически: шаг тока → захват burst → анализ → расчёт KP/KI
4. Результат: предложенные коэффициенты PI регулятора тока

#### Эксперимент 7: Test L/R (идентификация индуктивности)
```
testL               ← подаёт тестовый импульс, измеряет отклик
                    ← выводит $TESTL_BEGIN..$TESTL_END с данными
```

### 4.6. Остановка и выгрузка данных

```
stop                ← остановка ШИМ, Kdt сохраняется
stream off          ← выключить стрим
dumpflash           ← выгрузка flash black box (если был включён)
events              ← выгрузка журнала событий (fault, FOC transitions, DTC)
flashinfo           ← проверить статус flash
```

### 4.7. После аварии (fault)

При срабатывании защиты:
- ШИМ выключается (MOE = 0)
- Автоматический burst capture (в SRAM, не сохраняется в файл)
- Событие в журнале

```
events              ← посмотреть причину аварии
faultclr            ← очистить fault
                    ← проверить параметры перед повторным запуском
```

## 7. Типовые сценарии диагностики

### 7.1. «Двигатель не запускается»
1. `events` — проверить, на каком этапе остановка
2. Проверить калибровку: `calib` → `start`
3. Проверить токовые каналы: стрим `stream on`, смотреть ia1..ic2
4. Проверить параметры двигателя: `MP...` — корректны ли Rs, Lm?

### 7.2. «FOC теряет синхронизацию»
1. `events` — найти EVT_FOC_LOST
2. `capture` — захват в момент потери
3. Анализ burst: wr (скорость), theta_jit (джиттер угла), e_alpha/e_beta
4. Проверить нагрузку — не превышает ли она доступный момент
5. Попробовать `s15` (минимальная скорость) и плавно повышать

### 7.3. «Ток не синусоидальный»
1. `capture` — захват burst
2. Анализ ia1, ib1, ic1 — форма фазных токов
3. FFT id/iq — наличие 6-й гармоники
4. `dtcinfo` — проверка DTC: если corr_lpf большая → DTC не сходится
5. `DS-1` — попробовать инверсию знака DTC
6. `zscatune` — повторить ZSC автотюн

### 7.5. «Двигатель не выходит на высокую скорость»
1. `stream on` — наблюдать sat_flags
2. Если SAT_FW (0x02) активен — FW работает, но не хватает напряжения
3. Если SAT_DUTY (0x08) — упёрлись в предел ШИМ
4. Проверить Vdc — достаточно ли напряжение шины
5. SVPWM должен расширить диапазон — проверить, что v_max_limit = 0.95

### 7.6. «Авария по току»
1. `events` — тип аварии (IABS, IRMS, DIDT)
2. `capture` — авто-захват уже сделан, но не сохранён в файл
3. Уменьшить уставки: `i1.0`, `s20`
4. Проверить `IM`, `IR`, `DT` — не слишком ли малы пределы?
5. `faultclr` → повторный запуск с меньшей нагрузкой

## 8. Безопасность

- ⚠️ **Всегда** начинайте с пониженного питания (12–24 В)
- ⚠️ **Первый запуск** — без нагрузки, малая скорость (`s15`)
- ⚠️ Уставки тока `i1.0` → `i2.0` → `i3.0` — повышать постепенно
- ⚠️ При аварии — `events` для анализа, `faultclr` для сброса
- ⚠️ Не оставлять без присмотра при высоких скоростях/токах
- ⚠️ Flash black box переживает сброс питания — данные не потеряются
