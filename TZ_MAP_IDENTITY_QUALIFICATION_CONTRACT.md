# ТЗ: контракт identity, sampling evidence и семантики geometry-региона

**Версия:** 2 (расширена после установления факта «geometry-конвейер отвергает все 12 рядов»).
**Статус:** техническое задание. **Не** разрешение на запуск стенда и **не** разрешение на
hardware swap-test. Safety-модули (`foc/pwm/protect/vf/adc/adc_dispatch`, `.ioc`) не затрагиваются.
**База:** `origin/main` (SHA фиксируется при старте работ).
**Основание:** `docs/BOAR_DATASET_AUDIT_VERIFICATION.md` §4–§8,
`docs/FIRMWARE_TRANSITION_SAMPLING_SPEC.md` §2.1–2.2, §4, §5,
`docs/TZ_MAP_REGION_GEOMETRY_REFACTOR.md` (замороженный контракт).
**Принцип:** контракт нельзя подгонять под существующие данные — данные пересобираются под контракт.
ТЗ начинается **не** с порогов, а с фиксации семантики региона и sampling evidence.

---

## 0. Исходное состояние (измерено инструментами, не оценивается)

| факт | измерение | где |
|---|---|---|
| geometry-конвейер отвергает датасет | `use_geometry=1` → **12/12 `MAP_CERT_VALID_OUTSIDE` (7)**, CLI `EXIT 1`, артефакт не создан | отчёт §6 |
| legacy-конвейер принимает | `use_geometry=0` → `EXIT 0`, артефакт 497 Б | отчёт §6 |
| причина | регион требует среднюю фазу ≤ −1, центр вектора кампании даёт **ровно 0** → 24/32 cells вне региона | спец. §2.2 |
| предикаты секторов не partition | покрытие **269.9° (75 %)**, dead zones **(30°…90°)** и **(180°…210°)** = 90° | спец. §2.1 |
| identity датасета несовместима | `acs=0x13572468`, `ccs=0x24681357` (synthetic) vs live `0x26B9B97B`/`0x13552B12`; те же значения ушли в артефакт | отчёт §5–§6 |
| `pwm_frequency_hz` | в identity/артефакте **294**, фактический carrier **5000 Гц**; в sampling-контракт не входит | спец. §5 |
| trigger offset | `0`, семантика «не измерено»; неопределённость момента выборки **±100 мкс (полупериод)** | спец. §4 |
| доказательность полей вырождена | `margin`=110, `settled`=1, `scope`=1, `ict`=0 в 384/384; `refu≡idc1`, `refv≡idc2`, `refw≡−(refu+refv)` | отчёт §4 |
| линейность «ADC-конверсии» | OLS `ref = a + b·idc1 + c·idc2`: остаток **0.000000 мА** на 12/12 рядов и 3 каналах — но `refu≡idc1`, `refv≡idc2` → **ADC linearity / gain / offset: NOT TESTED** | отчёт §4.1 |

**Ключевое разделение вердиктов (запрещено смешивать):**

```text
LEGACY ACCEPTANCE      (EXIT 0, MAP_CERT_OK)      ≠ доказательство пригодности для geometry-map
GEOMETRY ACCEPTANCE    (MAP_CERT_VALID_OUTSIDE)   = отказ по принадлежности региону
```

Legacy-проход проверяет структуру, диапазоны, identity и согласованность записей; он **не**
проверяет принадлежность sample своему geometry-региону и потому не может подтверждать
geometry-qualified карту.

## P1. Identity и metadata (независимо от решения A/B)

| # | Требование |
|---|---|
| R1.1 | Единый источник carrier frequency. Формула для center-aligned: `carrier = get_tim_ck_int() / (2·(PSC+1)·(ARR+1))`. Устранить двойное деление на (PSC+1) (`src/map_capture_port.c:109-121`); путаницу создаёт `PWM_GetSysInfo()` (`src/pwm.c:612-616`), возвращающий уже поделённый `tclk` — переименовать/задокументировать или вернуть необработанную частоту. |
| R1.2 | **Запрет дублирования значения** `5000` в константах профиля: `MAP_CAPTURE_BOARD_PWM_HZ` (`src/map_capture_profiles.c:191`) обязан быть derived/проверяемым, а не «ручной копией в lockstep». Тест обязан ловить расхождение константы и живого расчёта. |
| R1.3 | Identity формируется **только** из живого firmware (`mapcap identity`); ручной ввод `acs/ccs/pwm` в кампанию запрещён (ingest обязан fail-closed). |
| R1.4 | Явная версия identity-схемы (поле/константа schema revision) — чтобы смена семантики полей не выглядела как «тот же identity». |
| R1.5 | Инвалидация старых артефактов — **явная**: зафиксировать в отчёте, что все артефакты с `pwm=294` и/или placeholder-подписями отвергаются, с указанием новой revision в provenance. |
| R1.6 | `trigger_offset_ticks` до измерения остаётся 0; подстановка «правдоподобного» значения запрещена (см. P2). |
| R1.7 | Не добавлять новых зависимостей от `pwm_frequency_hz` в runtime sampling: проверено, что сейчас поле влияет только на identity/consistency admission (спец. §5). |

**Точная формулировка для отчёта:** `pwm_frequency_hz` **не** является параметром runtime
sampling behavior и **не** участвует в расчёте blanking, margin или выбора окна; он участвует
в identity/consistency admission, поэтому неверное значение ведёт к
`metadata → identity mismatch → artifact rejection`. Исправление metadata **не** повышает
физическую пригодность карты.

**Acceptance P1:** unit-тест «PSC=16, ARR=999, tck=170 МГц → 5000»; тест «константа профиля ==
живой расчёт»; отрицательные тесты на mismatch (acs/ccs/pwm/arr/toff) → REJECT; сборка `make`,
hosted-тесты, CI зелёный; отчёт с числами.

## P2. Sampling evidence (declared ≠ measured; независимо от A/B)

Сейчас `frame.sample_window` — **копия** объявленного значения (`src/adc.c:335-341` →
`:123, 392, 547`), а UEV в center-aligned возникает и на overflow, и на underflow, и код их не
различает. Для вращающегося FOC-вектора это ±100 мкс.

| # | Требование |
|---|---|
| R2.1 | Разделить поля и запретить их смешение: `declared_window` (что firmware считает окном) · `measured_trigger_event` (overflow/underflow) · `measured_counter_direction` · `trigger_offset_ticks` (от вершины) · `sample_timestamp`. |
| R2.2 | `declared_window` **запрещено** использовать как timing evidence: документировать это в коде и в ТЗ-цепочке; в отчётах указывать «declared, not measured». |
| R2.3 | Различать overflow/underflow: захват `TIM1->CR1.DIR` (или `CNT`) в момент JEOS/ISR, поле в кадре. Это дешёвая и проверяемая мера. |
| R2.4 | Измерить `toff` (тики от конкретной вершины) и его разброс; до измерения поле = 0 и трактуется как «не измерено». |
| R2.5 | Документировать фактическую цепочку `TIM1 MMS=2 (UEV) → TRGO → ADC JEXTSEL=0, rising → injected (ADC1 rank1 | ADC2 ranks1-3) → JEOS ADC2 → ISR/снимок` с числами (5 кГц, 46.09 мкс, RCR=1, CMS=3). |
| R2.6 | Сверка `JEXTSEL=0` с RM0440 — как requirement, а не как комментарий в коде. |

**Acceptance P2:** тест, что кадр несёт `measured_trigger_event`/`DIR` и что при их отсутствии
фрейм помечается `TIMING_UNPROVEN`; отчёт с числами измерений (после стендовой процедуры).

## P3. Семантика geometry-региона + решение A/B (**требуется решение владельца**)

Сейчас в одном понятии «регион» смешаны три разных смысла:

```text
(1) физически допустимая область измерения (sampling physics: blanking/settling/margin/toff)
(2) класс PWM-вектора (sector/window как семантическая классификация)
(3) окно допуска вокруг номинального центра (tolerance box кампании)
```

Смешение и даёт наблюдаемое: прямоугольник (2)+(3) отвергает центр вектора из (1).

| # | Требование |
|---|---|
| R3.1 | Явно выбрать и записать, какой смысл (или какая их композиция) у региона; для каждого из трёх смыслов — свой артефакт/поле/predicate, а не одна структура. |
| R3.2 | Порядок «сначала семантика, потом пороги»: пороги выводятся из семантики и из измерений, не наоборот. |
| R3.3 | **Вариант A** (рекомендуется): полное покрытие окружности с явным tie-break, при этом: 1) нет неописанных областей; 2) у каждой граничной точки ровно один владелец; 3) задан приоритет при пересечении; 4) задано поведение точки ровно на границе; 5) задана политика численных погрешностей (эпсилон); 6) связь региона с номинальным вектором, измеренным током, допустимым sampling window, settling/blanking, `toff`, margin — описана явно; 7) зафиксировано, что считается доказательством физической пригодности, а что лишь результатом математической классификации. |
| R3.4 | **Tie-break не имеет права превращать физически непригодную точку в пригодную**: он разрешает неоднозначность принадлежности, но не отменяет ограничений sampling physics. |
| R3.5 | **Вариант B** неполноценен для непрерывного FOC-цикла: dead zones должны обрабатываться **runtime-политикой** (вектор в dead zone → отказ/удержание/иной режим), а не только записью в provenance. Если выбран B — требуется явный `UNQUALIFIED / NO_CAPTURE`, политика в артефакте и тест selector'а. |
| R3.6 | Практическое число для проектирования: при `mod_q15 ∈ [7500, 9000]` регион sector 0 допускает θ ∈ (22.4°, 30°) — «регион» фактически амплитудная коробка шириной ~7.6°; это либо принимается и записывается, либо меняется вместе с семантикой. |

**Acceptance P3:** решение зафиксировано документом; тесты: (a) центр каждого сектора
принадлежит своему региону; (b) dead-zone вектор ведёт себя по принятой политике (A: покрыт;
B: отвергнут); (c) equivalence host-certifier ↔ firmware-selector на одном наборе векторов;
(d) граничные точки (tie, 0, ±30°, ±180°) имеют предсказуемого владельца.

## P4. Новая qualification campaign (после P1–P3)

| # | Требование |
|---|---|
| R4.1 | identity — из живого порта; `pwm` рассчитан корректно; актуальные `acs/ccs`; расхождение → BLOCKED. |
| R4.2 | Grid: центры каждого (сектор, окно) попадают в сертифицируемый регион по P3 (fail-closed до запуска). |
| R4.3 | Амплитуды: W0/W1 кластеры внутри своих окон по `mod_q15` (пороги не переопределяются; при TZ-порогах W1 требует `mod ≥ 10000`, текущие 9240 не подходят). |
| R4.4 | `margin` per-sample — измеренный запас либо явный признак `margin_source=CONTRACT_CONSTANT` с запретом использовать как доказательство. |
| R4.5 | `ref*`: запрещено выдавать синтез за измерение — признаки `reference_source=SCOPE|KCL_SYNTHETIC`; KCL-остаток по KCL-синтезу не является независимым подтверждением. |
| R4.6 | Протокол захвата: устранить структурные пропуски `seq` (83 в старой кампании) либо документировать их источник и обеспечить cycle closure. |
| R4.7 | Timing evidence независим от declared-полей (см. P2). |

**Acceptance P4:** geometry-CLI → **EXIT 0** и **12/12 `MAP_CERT_OK`**; артефакт на борту →
`mapload PASS:COMMISSION`; identity совпадает с live; coverage соответствует утверждённой модели;
отчёт с числами и SHA.

## P5. Физическая валидация (после P4)

| # | Требование |
|---|---|
| R5.1 | **Запрет на тавтологию как доказательство:** OLS residual, KCL residual либо совпадение `ref*` с `idc*` **не могут** считаться доказательством ADC linearity, gain, offset, phase mapping или физической точности тока, если reference-поля получены из тех же измеренных каналов или алгебраически определены через них. Формулировка «ADC conversion PASS» запрещена; используется: «преобразование raw → engineering согласовано с заявленной формулой, точность и линейность ADC независимо не подтверждены». |
| R5.2 | Независимый источник обязателен хотя бы одного типа: (1) внешний токовый эталон (датчик/шунт/осциллограф с независимым трактом); (2) контролируемый электрический режим с независимым расчётом ожидаемого тока; (3) независимая аппаратная перестановка (controlled swap: ADC input 1↔2, фаза U↔V, полярность датчика); (4) независимая модель `I_expected = f(Vbus, PWM, Rsense, gain, нагрузка)`, **не** построенная из проверяемых `idc1/idc2`. |
| R5.3 | Обязательный артефакт `independent_reference` на каждый проверяемый канал: `source_type` · `source_signal` · `calibration` · `uncertainty` · `timestamp_alignment` · `mapping_to_adc_channel`. |
| R5.4 | Для каждого проверяемого канала должно быть явно отвечено: откуда взят эталон · каким прибором измерен · какова его погрешность · как синхронизирован по времени с ADC · как сопоставлен с конкретным ADC input · **не использовался ли проверяемый сигнал при построении эталона**. |
| R5.5 | Обязательная последовательность: независимая фазовая/полярностная проверка → controlled ADC/phase swap → непрерывный полный цикл → фактическая временная привязка ADC (P2). |
| R5.6 | `PHYSICAL MAPPING PASS` записывается только при выполнении R5.2–R5.5 (спец. §7). |

**Acceptance P5:** отчёт с артефактом `independent_reference` (все поля заполнены, включая
`uncertainty` и ответ на R5.4), числами по каждому каналу и явным указанием, что независимость
подтверждена; без этого блока любые «residual»/«PASS» в отчёте не принимаются.

## P7. Запреты и non-goals

Запрещено: менять пороги W0/W1 под существующий датасет (TZ §3) · выпускать firmware-loadable
artifact с `use_geometry=1` до решения P3 · запускать swap-test на артефакте, отвергаемом по
identity · использовать `declared_window` как timing evidence · **считать OLS/KCL residual или
совпадение `ref*` с `idc*` доказательством линейности, усиления, оффсета, фазового маппинга или
физической точности тока** · использовать формулировку «ADC conversion PASS» (в этом датасете
остаток тождественно 0, `ref` дублирует измерение).

Non-goals: физическое измерение `toff` внутри P1/P3 (выделено в P2/P5) · любое включение
FOC/энергетики · изменения safety-модулей.
