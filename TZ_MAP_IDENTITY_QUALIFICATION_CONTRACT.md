# ТЗ: контракт identity и qualification (перед новой кампанией карты)

**Статус:** техническое задание, **не** разрешение на запуск стенда и **не** разрешение на
hardware swap-test. Safety-модули (`foc/pwm/protect/vf/adc/adc_dispatch`, `.ioc`)
не затрагиваются.
**База:** `origin/main` (SHA фиксируется при старте работ).
**Основание:** `docs/BOAR_DATASET_AUDIT_VERIFICATION.md` §5–§8,
`docs/FIRMWARE_TRANSITION_SAMPLING_SPEC.md` §2.1–2.2, §4, §5,
`docs/TZ_MAP_REGION_GEOMETRY_REFACTOR.md` (замороженный контракт, §3/§4/§5).
**Принцип:** контракт нельзя подгонять под существующие данные; данные пересобираются под
контракт.

## P1. Identity / metadata contract

| # | Требование |
|---|---|
| R1.1 | Исправить двойное деление на (PSC+1) в `cap_pwm_frequency_hz` (`src/map_capture_port.c:109-121`). Каноническая формула: `carrier = get_tim_ck_int() / (2·(PSC+1)·(ARR+1))`. `PWM_GetSysInfo()` вернуть/использовать без повторного деления (`src/pwm.c:612-616` — источник путаницы). |
| R1.2 | `MAP_CAPTURE_BOARD_PWM_HZ` = **5000** (`src/map_capture_profiles.c:191`), синхронно с R1.1; комментарий «в lockstep» удалить/переписать. |
| R1.3 | Инвалидация старых артефактов должна быть **явной**, не молчаливой: в отчёте зафиксировать, что все ранее выпущенные artifact'ы с `pwm=294` теперь отвергаются по identity, и указать новый revision в provenance. |
| R1.4 | `trigger_offset_ticks` остаётся 0 до измерения. Запрещено подставлять «правдоподобное» значение. Документировать семантику «0 = не измерено» в `src/map_capture_port.c:218,288` и в спеке. |
| R1.5 | Датасет кампании обязан генерироваться из **живого** identity (CLI `mapcap identity` уже есть); ручной ввод `acs/ccs/pwm` в кампанию запрещён (fail-closed в ingest-инструменте). |
| R1.6 | `pwm_frequency_hz` не участвует в выборе sampling-контракта (проверено grep'ом, спец. §5) — при исправлении **не** добавлять новых зависимостей от этого поля. |

**Acceptance P1:** unit-тест «при PSC=16, ARR=999, tck=170 МГц → 5000»; grep-подтверждение
отсутствия второго деления; сборка `make` + hosted-тесты; CI зелёный; отчёт с числами.

## P2. Qualification contract: что физически означает W0/W1

| # | Требование |
|---|---|
| R2.1 | Зафиксировать семантику окна: `mod_q15 = max(|mu|,|mv|,|mw|)`, предикаты полуоткрытые (TZ §3), пороги — в qualification и в provenance revision. |
| R2.2 | Границы W0/W1 обязаны быть **выведены и обоснованы** измеренными величинами: положение триггера (`toff`), blanking, длительность acquisition (46.09 мкс), settling шунтов, margin. Обоснование — в документе с числами, а не «подходит к данным». |
| R2.3 | Если пороги TZ (W1.min = 10000) сохраняются, новая кампания обязана дать W1-кластер с `mod ≥ 10000`; текущие 9240 — не проходят. Кампания пересобирается, пороги — нет. |
| R2.4 | Поле `margin` в per-sample записи обязано нести **измеренный** запас до границы (в тиках). Ситуация «`margin` == контрактная константа у 384/384 sample» означает, что поле не измеряется: требуется либо реальное измерение, либо явный признак `margin_source=CONTRACT_CONSTANT` и запрет использовать такие записи как доказательность. |
| R2.5 | `refu/refv/refw`: запрещено выдавать синтез за измерение. Если `refw` получен по KCL (`−(refu+refv)`) — обязателен признак `reference_source=KCL_SYNTHETIC`; KCL-остаток по таким данным не может считаться независимым подтверждением. Аналогично `refu≡idc1`, `refv≡idc2` при `source=SCOPE`: признак обязателен. |

**Acceptance P2:** обновлённый документ контракта + тесты, которые отвергают (или помечают)
per-sample `margin` = константа и KCL-синтезированный `refw`.

## P3. Sector partition — требуется решение владельца (A или B)

Дано (спец. §2.1–2.2): предикаты покрывают 269.9°, dead zones (30°…90°) и (180°…210°);
прямоугольник geometry-режима требует среднюю фазу ≤ −1, а центры векторов кампании дают 0.

* **Вариант A (рекомендуется):** предикаты образуют полное покрытие с явным tie-break
  (TZ §4), центры векторов выбираются во внутренней области со строгим упорядочиванием фаз,
  certifier и selector используют одну shared geometry-библиотеку, прямоугольники заменяются
  семантическим предикатом.
* **Вариант B (допустим как временный):** dead zones признаются намеренными, но тогда
  qualification обязан возвращать явный `UNQUALIFIED / NO_CAPTURE` для этих интервалов,
  artifact обязан нести dead-zone policy в provenance, а selector — отклонять вектор,
  попавший в dead zone (не «промахиваться молча»).

**Число для проектирования:** при `mod_q15 ∈ [7500, 9000]` регион sector 0 допускает
θ ∈ (22.4°, 30°) — то есть каждый «регион» фактически является амплитудной коробкой шириной
~7.6° по углу. Это должно быть либо принято (и записано), либо изменено вместе с семантикой.

**Acceptance P3:** решение зафиксировано в документе; тесты: (a) центр вектора каждого
сектора принадлежит своему региону; (b) для варианта B — dead-zone вектор отвергается
selector'ом; (c) host certifier и firmware selector дают одинаковый вердикт на одном наборе
векторов (equivalence-тест).

## P4. Новая кампания (после P1–P3)

| # | Требование |
|---|---|
| R4.1 | identity кампании — из живого порта, `pwm=5000`, актуальные `acs/ccs`; расхождение → BLOCKED. |
| R4.2 | Grid: центры каждого (сектор, окно) должны попадать в сертифицируемый регион по P3, а не «рядом» (проверка fail-closed до запуска). |
| R4.3 | Амплитуды: W0 и W1 кластеры попадают в свои окна по `mod_q15` (R2.1) без переопределения порогов. |

(identity совпадает); отчёт с числами и SHA.

## P5. Порядок, запреты, non-goals

Порядок: **P1+P2** (код/контракт) → **P3** (решение) → **P4** (кампания) → только затем
экспериментальная идентификация фаз (непрерывный захват → timing → независимый эталон фаз →
baseline → controlled swap; спец. §7).

Запрещено:
* менять пороги W0/W1 под существующий датасет (TZ §3 — только новая revision + recertification);
* выпускать firmware-loadable artifact с `use_geometry=1` до решения P3 (TZ §5);
* запускать swap-test на артефакте, который текущая прошивка отвергает по identity;
* считать KCL/остатки по синтезированному `refw` доказательством физической привязки фаз;
* трактовать `margin` = константа контракта как измеренный запас.

Non-goals: физическое измерение `toff` (отдельная процедура), любое включение FOC/энергетики,
изменения safety-модулей.
