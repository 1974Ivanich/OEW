# DeepSeek API (deepseek-chat) — ответ на ТЗ atan2_q31

## Код (получен через API, прямой запрос)

Метод: нормализация к [0,1] + полином 4-й степени (Q30) + квадрантная коррекция.

```c
int32_t atan2_q31(int32_t y, int32_t x) {
    int64_t ax = x < 0 ? -(int64_t)x : x;
    int64_t ay = y < 0 ? -(int64_t)y : y;
    int64_t num, den;
    if (ax >= ay) { num = ay << 30; den = ax; }
    else          { num = ax << 30; den = ay; }
    if (den == 0) return (x >= 0) ? 0 : 0x80000000;
    int64_t t = num / den;  // Q30
    int64_t t2 = (t * t) >> 30;
    int64_t t4 = (t2 * t2) >> 30;
    int64_t t6 = (t4 * t2) >> 30;
    int64_t poly = 1073741824LL - 354748416LL*t2 + 193468416LL*t4 - 91422720LL*t6;
    int64_t result = (t * poly) >> 30;
    result = (result * 1686629713LL) >> 30;
    if (ax >= ay) {
        if (x >= 0) return (y >= 0) ? result : -result;
        else        return (y >= 0) ? (0x40000000 - result) : (0xC0000000 + result);
    } else {
        if (y >= 0) return (x >= 0) ? (0x40000000 - result) : (0x40000000 + result);
        else        return (x >= 0) ? (0xC0000000 + result) : (0xC0000000 - result);
    }
}
```

## Численная проверка (имитация int32/int64, все углы)

| Метрика | Результат |
|---------|-----------|
| Макс. ошибка | **272.8°** (при 161°) |
| Ошибка > 2° | ~80% точек |
| Точные точки | только ±11°, ±101° (случайно) |

## 🔴 Баги

1. **Квадранты Q2/Q3: `0x40000000` вместо `0x7FFFFFFF`**
   - `0x40000000` = π/2, но для x<0 угол должен быть **π − atan** (0x7FFFFFFF − result)
   - `0xC0000000 + result` = −π/2 + atan — тоже неверно (нужно −π + atan)
   - Ветка `|y|>|x|`: `0x40000000 − result` возвращает угол из [0, π/2], но нужен [π/2, π]

2. **Полином масштабирован неверно**: `result = t*poly >> 30` даёт atan(t) в Q30, затем `*1686629713 >> 30` (1686629713 = π/4·2³⁰) — но atan(t) в Q30 уже, а не безразмерное; перемножение двух Q30 даёт Q60 >> 30 = Q30, а нужно привести к Q31. Смесь Q30/Q31 без выравнивания.

3. **Нет проверки переполнения**: `ay << 30` при ay=32768 → 2⁴⁵ — ок для int64, но полином: `354748416 * t2` при t2~2³⁰ → 3.8e17 < 9.2e18 — на грани, но в int64. При t=2³⁰ (угол 45°): t2=2³⁰, t4=2³⁰, t6=2³⁰ → poly = 1.07e9 − 3.8e17 + 2.1e17 − 9.8e16 = −2.7e17 — отрицательный полином → мусор.

## Оценка

- ✅ Идея: полиномиальная аппроксимация atan + редукция к [0,1] — рабочая схема
- ✅ Использование int64 — правильно
- 🔴 Ошибки масштабирования Q30/Q31 в полиноме (полином «схлопывается» при больших t)
- 🔴 Квадранты Q2/Q3: π/2 вместо π (фундаментальная ошибка коррекции)
- 🔴 Ошибка до 273° — код полностью нерабочий
