# TZ_MAP_PHASE_REFERENCE_CONTRACT — контракт независимой фазовой референции `y`

**Статус:** docs-only. Ничего в прошивке, профиле, ingest-инструменте и порогах не меняется до фиксации
этого документа. Реализация — отдельным ТЗ с явным GO владельца.

**Зачем:** S-гейт solver'а проверен и пройден (`ROW_NON_DEGENERATE`, `det_rel = 314 075 ppm` при пороге
10 000 ppm) — то есть сингулярность строки больше не блокер. Следующий блокер по спеке аккумулятора
(`docs/MAP_ACCUMULATOR_SPEC.md` §1, §6.1) — отсутствие независимого эталона фазных токов `y`:
без него строка не может стать `ROW_READY`, карта — `MAP_READY`, а residual / hold-out / KCL / polarity
гейты не проверяемы. Оценка `M` только по `idc1/idc2` запрещена спекой как самоподтверждение модели.

## 1. Что такое `y` и что им НЕ является

```text
y = (i_phase_a, i_phase_b) — два РАЗНЫХ фазных тока, измеренных НЕЗАВИСИМЫМ датчиком в фазном проводе,
    одновременно (или с измеренным и ограниченным сдвигом) с шунтовым sample.
```

Запрещено контрактом (любое из этого делает квалификацию тавтологической):

```text
· получать ia/ib арифметически из idc1/idc2 (KCL, обратная реконструкция, «M·x» из предыдущей карты);
· получать ia/ib из модели FOC / V/f / предполагаемого вектора тока;
· подставлять номинальные/расчётные значения вместо измерения;
· маскировать отсутствие y нулями, псевдообратной матрицей или «reference provider», который сам
  вычисляет фазы из шунтов. Absent reference ⇒ строка REJECT, а не «допустим с оговоркой».
```

Допустимо: разные датчики на разных входах одного АЦП, если это физически раздельные измерительные
тракты и сдвиг выборки между ними измерен (см. §4). Общий ADC/триггер/таймбаза — не нарушение.

## 2. Где физически измеряется

Существующая стендовая схема (см. `tools/map_scope_ingest.md`): два ACS712-20A включены последовательно
в фазные провода между инвертором и мотором, CH1 осциллографа = фаза U, CH2 = фаза V.

```text
· REQUIREMENT: датчики находятся В ФАЗНОЙ ЦЕПИ, а не в DC-link; точка установки указывается в отчёте
  (до/после какого разъёма) и не меняется внутри кампании;
· вносимый импеданс должен быть заявлен (и проверен, что не меняет ток в интересующей полосе);
· калибровка обязательна и fail-closed: перед каждой кампанией — замер нулевых уровней `v0_U`/`v0_V`
  при обесточенном моторе (шаг 0b протокола), фактический Vcc, чувствительность; mV-режим без `--calib`
  отклоняется (уже реализовано в ingest);
· полоса датчика не должна сглаживать ШИМ-пульсации (в ingest зафиксирован запрет CF=47 нФ);
· третья фаза может выводиться по KCL, но тогда KCL НЕ является доказательством синхронности (§5).
```

## 3. Как sample связывается с фазовой записью

Authoritative-поля (другие не используются):

```text
· `capture.frame.sequence` (в логе — `seq`) — единственный ordering marker;
· независимая реконструкция (sector, window, point) из CCR (реализована и проверена: 96/96 × 2 метода);
· эталонная запись должна нести тот же `sample_id`, что и `capture.frame.sequence`.
```

```text
· REQUIREMENT: `reference.sample_id == capture.frame.sequence` для 100 % использованных samples
  (требование `MAP_ACCUMULATOR_SPEC.md` §3);
· ТЕКУЩИЙ РАЗРЫВ, который контракт закрывает: `tools/map_scope_ingest.py` связывает reference по НОМЕРУ
  СТРОКИ CSV (`pulse` ↔ порядок записей). Спека прямо предупреждает: «Если reference измерен
  осциллографом, соответствие должно быть установлено offline по trigger marker; простое совпадение
  номера строки недостаточно». Пока привязка только порядковая — она НЕ является доказательством;
· REQUIREMENT: привязка подтверждается триггерным признаком, а не порядком: для каждой записи должно
  быть предъявлено, ПО КАКОМУ признаку этот scope-фрагмент отнесён к этому `seq`
  (маркер триггера / характерный признак события / иной воспроизводимый признак, выбранный и
  обоснованный ДО прогона);
· НЕ ТРЕБУЕТСЯ доказывать абсолютную фазовую точность ADC — требуется воспроизводимая однозначная
  привязка каждой использованной пары (shunt sample, reference sample).
```

## 4. Что считается синхронностью

```text
· сдвиг Δt между шунтовым sample (апертура инжектированной конверсии) и эталонной записью должен быть
  ИЗМЕРЕН, а не выведен из firmware-меток: способ измерения объявляется заранее (например, по фронту
  ШИМ/GPIO на канале осциллографа с одновременной регистрацией момента выборки АЦП), вместе с оценкой
  погрешности;
· окно допустимого Δt объявляется ЧИСЛОМ до прогона; записи вне окна отклоняются, а не «уточняются»;
· маркерное поле `trigger id = 0x4F455731` фиксирует идентичность триггерной конфигурации, но само
  по себе синхронность не доказывает;
· EXT TRIG стендового осциллографа как данность НЕ предполагается: механизм привязки (какой канал,
  какой признак) объявляется явно; если механизм недоступен — контракт не выполнен;
· REQUIREMENT (обязательный контроль): негативный тест — при умышленном сдвиге привязки на ±1 sample
  конвейер ОБЯЗАН отклонить строку (residual/hold-out/KCL). Если такой сдвиг не отклоняется, привязка
  считается недоказанной. Тест выполняется на тех же данных и предъявляется в отчёте.
```

## 5. Про `timing evidence` и про KCL

```text
· `scope_qualified`, `margin_ticks`, `blanking_ticks` должны иметь ОПРЕДЕЛЁННУЮ семантику и измеренный
  источник. Порог `margin_ticks >= 110` берётся из профиля (MAP_CAPTURE_BOARD_MARGIN) и не меняется
  этим контрактом; требуется лишь предъявить, чем именно он подтверждён для данного типа сессии;
· при двух датчиках третья фаза выводится по KCL ⇒ KCL-гейт ФОРМАЛЕН и НЕ является доказательством
  синхронности. Запрещено ссылаться на KCL как на подтверждение привязки;
· если третья фаза измеряется физически (третий датчик), KCL становится содержательным тестом и
  порог |u+v+w| задаётся заранее.
```

## 6. Запреты (сводно)

```text
· y из idc1/idc2 или из модели — см. §1;
· `@MC:STATUS ... sector=0 window=0` как доказательство сектора/окна: по коду (main.c:625) это снимок
  ТЕРМИНАЛЬНОГО кадра (map_capture.c:373-374), в этих сессиях не заполняется. Авторитетны `seq` и
  независимая реконструкция из CCR. Рекомендация отдельным пакетом: заполнять либо убрать поля;
· опора на `ts`: в текущих прогонах `ts = 0` во всех записях (период=0; src/adc.c:91-94 — поле
  опционально). Если привязке нужен аппаратный таймстамп, это ОТДЕЛЬНОЕ firmware-ТЗ с явным GO
  (новый timing-механизм не вводится: место — существующее `AdcFrame.timestamp_cycles`);
· переносить синхронность «по предположению», «по номиналу датчика», «по прошлой кампании»;
· менять апертуру/MMS/CCR4 под предлогом улучшения reference: §5.3 к этому контракту не относится.
```

## 7. Доказательства приёмки reference-слоя (E1…E6)

```text
E1. Источник y объявлен физически: тип датчика, точка установки, калибровка (v0/Vcc/sens), дата и
    условие калибровки. Без калибровки — REJECT (уже fail-closed в ingest).
E2. Привязка: 100 % использованных samples имеют `sample_id == frame.sequence`, и для каждого
    предъявлен признак привязки (§3). Порядковая привязка одна — недостаточна.
E3. Синхронность: измеренный Δt + погрешность + объявленное окно; все использованные samples в окне.
E4. Негативный контроль: умышленный сдвиг ±1 sample ⇒ строка отклоняется (E4 обязателен; без него
    доказательство не принимается).
E5. Non-tautology: заявленный `source` + негативный контроль с отключённым датчиком (y уходит в упор/
    ноль ⇒ строка REJECT). Идеально точный residual сам по себе считается признаком тавтологии и
    требует разбора, а не приёмки.
E6. Воспроизводимость: повтор сессии reference даёт те же гейты (в пределах объявленного допуска);
    смена p1-блока и повторный расчёт не меняют вердикт строки.
```

## 8. Границы контракта

```text
· контракт НЕ квалифицирует OEW map и НЕ устанавливает фазовую конвенцию;
· контракт НЕ трогает апертуру/SMPR/MMS/CCR4 (S-гейт уже пройден, §5.3 не требуется);
· контракт НЕ занимается Ls (вне этого контура);
· `foc.c`, `pwm.c`, `protect.c`, `adc_dispatch`, `.ioc`, `Makefile` — не трогаются этим ТЗ;
· любые изменения firmware/ingest — отдельное ТЗ с явным GO; после правки ingest доказательства E2–E5
  предъявляются заново на реальных данных (PASS на синтетике доказательством не является).
```

## 9. Ожидаемый следующий артефакт

```text
Одно из двух, по решению владельца:
(а) ТЗ на ingest-правку (привязка по триггерному признаку вместо порядка строк + негативные контроли) —
    без правки прошивки, если признаки доступны в уже сохраняемых данных;
(б) ТЗ на reference-тракт (какие каналы, какой триггерный признак, как измеряется Δt и margin/blanking) —
    если требуется изменение измерительной части.
В обоих случаях перед прогоном фиксируются: окно Δt, допуск, признак привязки, критерии E4/E5.
```
