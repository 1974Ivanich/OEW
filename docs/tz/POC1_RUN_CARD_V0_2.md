# POC-1 Run Card v0.2 — BM1109 OEW-6T

**Назначение:** превратить POC-1 из контракта
(`TZ_FEM_BACKEND_CONTRACT_V0_1.md`, разделы «Объём POC», «Пять физических
проверок», «Приёмка») в заранее зафиксированный список расчётных состояний с
критериями PASS/FAIL, чтобы первый реальный FEM-прогон не стал серией
импровизированных экспериментов.

**Статус документа:** план. Ни один кейс этим документом не генерируется и не
запускается. `solver/getdp/cases/*.json` создаются при первом прогоне из таблицы
§5, а не заранее: файл кейса без прогона — непроверяемый артефакт.

**Изменения v0.2 (по итогам ревью v0.1):**

1. `T_cog = 20°` убран как установленный факт: 9 катушек — не 9 пазов, число
   пазов берётся только из G0.4.
2. `p = 3` остаётся **только** falsification gate; совпадение двух точек
   периодичность не доказывает.
3. Производная момента получила явный угловой stencil (точки и шаг `h`).
4. Проверки разделены на группы S (статические) и A (угловые): при
   `theta_e0 = UNKNOWN` группа S исполняется, группа A — нет.
5. Порог нелинейной суперпозиции `1e-4` переведён в проверку конфигурации
   решателя и привязан к `BH_VALIDATED`, а не к физике двигателя.

## 1. Границы и предусловия

Run card не меняет контракт и не добавляет проверок: он раскладывает уже
принятые POC-1…POC-5 на конкретные состояния, углы и пороги.

Предусловия (без них статус всего документа — `BLOCKED`):

| Предусловие | Источник | Без него |
|---|---|---|
| G0 PASS | `TZ_FEM_BACKEND_CONTRACT_V0_1_G0_M.md` §7 | ни одного BM1109-кейса |
| `I_ref` (номинальный фазный ток) | `geometry_parameters.json` | нельзя задать амплитуду; «типовой ток» запрещён |
| `N_s` — число **пазов** | только G0.4 (чертёж/обмер) | период cogging не вычисляется; 9 катушек пазами не считаются |
| `N_p` — число полюсов | G0.1/G0.2 + магнитная периодичность | углы группы A не привязываются к полюсам |
| `p` подтверждён периодичностью | G0-M §6 | `p = 3` — гипотеза; углы группы A помечаются как гипотетические |
| `theta_e0` и его статус | G0-M §6 | группа S разрешена, группа A — нет (§4) |
| Режим материала | G0.7 | по умолчанию `linear` + явная запись в `manifest.json` |

`solver/getdp/model/*.geo` появляется только после G0 PASS. Smoke-геометрия
(`solver/getdp_smoke/`) в этот прогон не входит и к BM1109 не относится.

## 3. Проверка реализации или проверка физики

Разделение обязательно: иначе расхождение с ожиданием спишут на «физику
двигателя», а ошибку знака или отсутствие нелинейности — на «особенность
стали».

| Проверка | Что доказывает PASS | Что PASS **не** доказывает |
|---|---|---|
| POC-1.1 сходимость, `psi = 0` | решатель и постановка задачи работают | ничего о cogging и насыщении |
| POC-1.1 `Te(θ)` не тождественный нуль | в модели есть позиционная зависимость | её величину и период у реального образца |
| POC-1.2 знак `psi`, антисимметрия `Te` | соглашение `i_U: U1 -> U2` реализовано верно | правильность `theta_e0` относительно ротора |
| POC-1.3 взаимность 3×3 | матрица `L` симметрична в линейном режиме | что `i_0 != 0` физически значим |
| POC-1.3 `psi(i+t·1) != psi(i)` | звезда не навязана моделью | отсутствие звезды у реальной машины |
| POC-1.4 PASS на линейном | экстрактор и суперпозиция согласованы | поведение на насыщении |
| POC-1.4 отклонение на нелинейном | B-H таблица действительно применена | пригодность B-H для этой машины (`BH_VALIDATED`) |
| POC-1.5 `eps_psi` | энергия и поток согласованы между собой | соответствие измеренному потоку |
| POC-1.5 `Te` из `W'` vs Maxwell | две независимые формулировки согласны | соответствие измеренному моменту |
| A6 повтор и замыкание | детерминизм модели; гипотеза `p = 3` не опровергнута | что `p = 3` подтверждено |

Итог: **POC-1 проверяет реализацию FEM-контракта и внутреннюю согласованность
модели.** Проверкой физики BM1109 он становится только вместе с данными обмера
(§9) — и то лишь в части, которую эти данные покрывают.

## 4. Группы S и A: что блокирует `theta_e0 = UNKNOWN`

Правило G0-M §6: при `theta_e0 = UNKNOWN` допустимы размерные и статические
проверки, угловые зависимости ROM — нет. Run card следует этому правилу и не
останавливает серию целиком.

| Группа | Что входит | Условие запуска |
|---|---|---|
| **S** — статические и геометрические | нулевое поле, `psi = 0`, знаки `psi(±I)` и антисимметрия `Te`, взаимность 3×3, evidence отсутствия звезды, линейная суперпозиция, `eps_psi`, `W'(0) = 0`, повтор | G0 PASS + `I_ref` |
| **A** — угловые | `psi(i, θ)` как функция угла, `Te(θ)` и период cogging, `∂W'/∂θ`, замыкание цикла при кандидате на период | G0 PASS + `theta_e0` подтверждён + `p` имеет основание |

Следствия:

- при `theta_e0 = UNKNOWN` исполняются кейсы 5, 6, 9–14, 17 и статическая часть
  кейса 1 (9 кейсов + `psi = 0`); кейсы 2–4, 7, 8, 15, 16 не запускаются и
  получают статус `NOT RUN`, а не `FAIL`;
- гейты A1, A2, A5 при этом фиксируются как `PARTIAL (S)`, A6 — как `PARTIAL`
  (повтор есть, замыкание цикла нет);
- угловая привязка не «досчитывается» подстановкой `theta_e0 = 0`: `UNKNOWN`
  остаётся `UNKNOWN`, а группа A ждёт G0-M §6.

## 5. Входные параметры

Все величины берутся из `geometry_parameters.json` и `manifest.json`, а не
назначаются в run card:

| Символ | Значение | Примечание |
|---|---|---|
| `I` | `1.0 * I_ref` | единственная амплитуда серии |
| `Δi` | `0.05 * I_ref` | шаг для `psi`-производных, как в DOE_1 |
| `θ_m` набор A | `k * 120°/p`, `k = 0..3` | при `p = 3`: `0, 40, 80, 120°` |
| `θ_m` предварительный набор B | `0, 5, 10, 15°` | **не** привязан к подтверждённому периоду; см. ниже |
| `θ_e` | `p * θ_m + theta_e0` | оба угла писать в `results.csv`/отчёт |

### О периоде cogging

`T_cog = 360°/LCM(N_s, N_p)` — формула для **пазов**, а не катушек. В исходных
данных BM1109 подтверждены 9 катушек; число пазов `N_s` неизвестно до G0.4.
Поэтому:

- `T_cog` в этом документе **не вычисляется** и нигде не используется как факт;
- углы `0, 5, 10, 15°` — предварительные состояния, равномерно покрывающие
  первые 15° механического угла; они годятся для проверки того, что позиционная
  зависимость вообще есть, и не более;
- после G0.4 (`N_s`) и подтверждения магнитной периодичности период
  пересчитывается, и набор B переопределяется до запуска группы A;
- если окажется, что `N_s != 9`, набор B из 4 точек пересматривается в
  `manifest.json` до серии, а не после.

## 7. Критерии по группам

Обозначения: `psi_scale = max|psi_k|` по серии (не по одному кейсу);
`Te_scale = |Te|` в кейсе 5; все допуски относительные и фиксируются в
`manifest.json` до первого запуска.

### POC-1.1 — нулевой ток

| Проверка | Критерий PASS | Класс | Группа |
|---|---|---|---|
| Сходимость | `converged = 1` во всех запущенных кейсах | реализация | S |
| Нулевой поток | `|psi_k| <= 1e-9 * psi_scale`, все три фазы | реализация | S |
| Отсутствие вырождения | `max|B|` конечно и `< B_limit` из манифеста, нет `NaN` | реализация | S |
| Позиционный момент | `Te(θ)` не тождественный нуль при `i = 0` | физика модели | A |
| Величина cogging | `max|Te(θ)| <= 0.02 * Te_scale`; иначе — находка `COGGING_SIGNIFICANT`, не PASS | физика | A |
| Период cogging | **не проверяется**: `T_cog` не установлен (§5) | — | — |

Порог `Te_cog_max` в абсолютных единицах заранее **не** назначается: он либо
берётся из паспорта/чертежа, либо заменяется относительным правилом выше.

### POC-1.2 — одна пара выводов, `±I`

| Проверка | Критерий PASS | Класс | Группа |
|---|---|---|---|
| Антисимметрия потока | `|psi_U(+I) + psi_U(-I)| <= 1e-6 * max|psi_U|` (кейсы 5, 6) | реализация | S |
| Знак потока | `psi_U(+I) > 0`, `psi_U(-I) < 0` при соглашении `U1 -> U2` | реализация | S |
| Антисимметрия момента | `sign(Te(+I)) = -sign(Te(-I))` с тем же допуском (кейсы 5, 6) | реализация | S |
| Знак `Te` по углу | сравнение `Te(+I)` и `Te(-I)` на `θ = 40°` (кейсы 7, 8) | реализация | A |
| Связь фаз | `psi_V`, `psi_W` записаны; значимая связь — физика, не гейт | физика | S |

Антисимметрия по моменту проверяется на статическом угле: она не требует
`theta_e0`, потому что сравнивает два состояния при одном и том же положении
ротора.

### POC-1.3 — три независимых состояния, отсутствие звезды

| Проверка | Критерий PASS | Класс | Группа |
|---|---|---|---|
| Матрица `L` 3×3 | строится из кейсов 5, 9, 10: `L_ab = psi_a(i_b)/I` | реализация | S |
| Взаимность | `|L_ab - L_ba| <= 1e-6 * max|L_ab|` | реализация | S |
| Звезда не навязана | `|psi(i+t*1) - psi(i)| / psi_scale > 1e-3` (кейсы 12 против 11) | реализация (A7) | S |
| Эффект `i_0 != 0` | число `Δpsi/psi_scale` записывается; `> 1e-3` — находка `I0_EFFECT`, требует решения до ROM | физика | S |

Критерий по звезде — это evidence, что постановка не содержит связи
`U2/V2/W2`; он ничего не говорит о том, есть ли звезда у реального образца.

### POC-1.4 — суперпозиция

| Проверка | Критерий PASS | Класс | Группа |
|---|---|---|---|
| Линейный материал | `|psi(I,I,0) - psi(I,0,0) - psi(0,I,0)| <= 1e-6 * psi_scale` (кейсы 13, 5, 9) | реализация | S |
| Нелинейный материал | отклонение заметно больше линейного допуска: `>= 1e-4 * psi_scale` | **конфигурация решателя** | S |
| Нелинейность не «пустая» | если на кейсе 14 отклонение `<= 1e-6 * psi_scale`, это FAIL конфигурации (B-H не применена) | конфигурация | S |

Порог `1e-4` — не физический критерий и не универсальная константа: величина
отклонения зависит от B-H, уровня возбуждения и геометрии. Без
`BH_VALIDATED` этот тест доказывает только то, что нелинейная таблица
действительно применяется и решатель её учитывает. Проверкой нелинейной физики
двигателя он становится только после `BH_VALIDATED`; до этого статус —
`CONFIG_ONLY`.

### POC-1.5 — энергия и момент

Расчёт `Te` из энергии — **явный угловой stencil**, а не «разность по трём
точкам»:

```text
h   = 40° механического угла = 0.69813170 rad  (фиксируется до серии)
θ0  = 0°
Te(θ0) ≈ ( -3*W'(θ0) + 4*W'(θ0+h) - W'(θ0+2h) ) / (2*h)
```

Требования к stencil:

- все три расчёта — с **одинаковыми** `i_U, i_V, i_W = (I, 0, 0)`;
- точки stencil: `θ_m = 0°, 40°, 80°` — кейсы 5, 7, 15;
- угол в формуле — в радианах; `W'` — в джоулях на осевую длину пакета либо
  в джоулях, но одинаково во всех трёх точках (единица фиксируется в манифесте);
- та же сетка, те же настройки решателя, тот же материал во всех трёх точках;
- `h` не подбирается после прогона; чувствительность `Te` к шагу `h` — не гейт
  POC-1, а отдельная проверка ROM-датасета.

| Проверка | Критерий PASS | Класс | Группа |
|---|---|---|---|
| Две ветви `psi` | `eps_psi = |psi_W' - psi_A| / max|psi| <= 1e-3` | реализация | S |
| `Te` из `W'` | вычислен по stencil выше без изменения шага | реализация | A |
| `Te` vs Maxwell | расхождение `<= 2 %` от `Te_scale`, либо `<= abs_floor` из манифеста | реализация | A |
| Роль Maxwell | только независимая проверка; заменять энергическую производную нельзя | — | — |
| Энергия | `W'(0) = 0`, `W'(i != 0) > 0`, `W'` конечна во всех кейсах | реализация | S |
| Монотонность по току | `W'` не убывает при росте `|i|` вдоль оси одного состояния | физика модели | S |

### A6 — повторяемость и замыкание

| Проверка | Критерий PASS | Класс | Группа |
|---|---|---|---|
| Повтор кейса | `psi`, `Te` совпадают с кейсом 5 в пределах `1e-9` отн. (кейс 17) | реализация | S |
| Замыкание цикла | `|psi(θ=0) - psi(θ=120°)| <= 1e-6 * psi_scale` (кейсы 5, 16) | проверка гипотезы | A |

**Что даёт замыкание цикла.** Это falsification gate, а не подтверждение
`p = 3`: совпадение двух значений необходимо, но недостаточно. Даже при точном
совпадении периодичность за полный механический оборот не доказана — нужны
измеренная магнитная периодичность, несколько характерных положений за оборот,
согласованность по всем трём фазам и независимое подтверждение по ЭДС при
вращении. Расхождение же при `p = 3` прямо опровергает гипотезу, и тогда `p`
не подгоняется, а фиксируется как находка.

## 8. Условия остановки серии

Серия останавливается и не «догоняется» другими кейсами, если:

1. любой запущенный кейс не сошёлся (`converged = 0`) — сначала постановка и
   сетка, потом остальные кейсы;
2. A6 (повтор) расходится больше `1e-9` — модель или экстрактор
   недетерминированы;
3. `eps_psi > 1e-3` — ветви `W'` и `A` противоречат друг другу;
4. суперпозиция на линейном материале не проходит — ошибка реализации, а не
   физика;
5. отсутствует `I_ref` — амплитуда не определена;
6. для группы A: `theta_e0 = UNKNOWN` или `p` не имеет основания — группа A
   **не запускается** (это не остановка серии, см. §4).

Ни одно из условий не закрывается усреднением или подбором допуска после
прогона.

## 9. Что записывается в `manifest.json` до серии

- `I_ref`, `Δi`, список `case_id` с группой S/A и его SHA-256;
- `p`, основание (`гипотеза` / `подтверждено периодичностью`), `theta_e0` и его
  статус; `N_s` с источником (G0.4) и `N_p`;
- выбранный набор B и правило его пересчёта, если `N_s != 9`;
- режим материала: `linear mu_r = ...` или `BH_AVAILABLE` + ссылка на кривую;
  отдельно — `BH_VALIDATED` да/нет;
- сетка: `h_airgap_mm`, `h_iron_mm`, версия модели;
- stencil момента: точки `0, 40, 80°`, `h = 0.69813170 rad`, единица `W'`;
- все допуски из §7 (`1e-9`, `1e-6`, `1e-3`, `2 %`, `0.02`, `1e-4`);
- правило cogging: относительное (п. 1.1) или абсолютный порог с источником.

Допуск, назначенный после прогона, в отчёт не принимается.

## 10. Что run card не покрывает

- **Магнитные материалы.** POC-1 с `linear mu_r` проверяет реализацию, а не
  сталь. `MATERIAL_IDENTIFIED`, `BH_AVAILABLE`, `BH_VALIDATED` — отдельные
  статусы; POC-1 не повышает ни один из них, а тест нелинейной суперпозиции до
  `BH_VALIDATED` остаётся проверкой конфигурации.
- **Период cogging.** Нужны `N_s` из G0.4 и подтверждённая магнитная
  периодичность; до этого периода нет.
- **Подтверждение `p = 3`.** Может быть только опровергнуто (§7, A6).
- **Соответствие измеренной ЭДС.** `e_k = ω_m * ∂psi_k/∂θ_m` требует данных
  обмера (ЭДС при медленном вращении) и проверяется отдельно, вне POC-1.
- **DOE-1.** 792/10357 кейсов не запускаются: POC-1 даёт 17.
- **ROM-гейты.** Симметрия и положительная определённость `L_inc`,
  `psi = ∇_i W'` на полной сетке, устойчивость численных производных по шагу —
  это проверки ROM-датасета, а не POC-1. Здесь строится только `L` 3×3.
