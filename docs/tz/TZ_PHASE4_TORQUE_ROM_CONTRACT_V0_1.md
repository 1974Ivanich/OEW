# TZ_PHASE4_TORQUE_ROM_CONTRACT_V0_1 — torque data path и сквозная интеграция DOE-1/2/3

**Статус: ЗАМОРОЖЕН** решениями владельца от 2026-11-25 (APPROVED: механический момент, полный per-row стенсил 792 состояния, экспериментальное обоснование h). Создан после закрытия Phase-3 (commit `6553b86`).
До согласования владельцем код DOE не правится. Ничто в этом документе не меняет
замороженные контракты `POC2_NONLINEAR_CONTRACT_V0_1.md` и
`TZ_DOE3_CONTROL_CONTRACT_V0_1.md` задним числом; где требуется уточнение
замороженного текста — оформлено как отдельная поправка (§9), а не скрытая замена.

## 1. Scope

Phase-4 закрывает единственный оставшийся нормативный пробел DOE-3: момент.
Решение владельца: вариант A — угловые стенсилы co-energy на узлах сетки —
как контрактная конструкция; реальная FEM-кампания выполняется только после
появления FEM-backend и отдельного разрешения.

Phase-4 включает:
1. torque data path: per-row `Te_coenergy` в ROM DOE-1;
2. сквозную интеграцию `DOE-1 → DOE-2/P2-N2 → summary.json → DOE-3`
   на синтетике с честными уровнями валидации;
3. отдельную численную задачу сравнения стенсилов `dm_di`/`l_from_flux`
   (§8) — без изменения основного результата.

Phase-4 не включает: реальную Maxwell-кампанию, изменение сетки 33×12,
новые физические гейты DOE-3, изменение стенсилов линеаризации в основном коде.

## 2. Определение момента — разрешение неоднозначности §5 контракта DOE-3

Замороженный §5 `TZ_DOE3_CONTROL_CONTRACT_V0_1.md` пишет
`T_e = ∂W'/∂θ_e|_i`. Буквальное чтение по электрическому углу даёт момент,
отличающийся в `p` раз от механического. Физически используемый в приводе
момент — механический:

```
T_mech = ∂W'/∂θ_mech | i_UVW = const
```

Стенсил DOE-1 уже построен физически правильно: фиксированы фазные токи UVW,
ротор поворачивается на ±h по **механическому** углу
(`theta_m_deg`, см. `torque_checks` в bm1109_doe1.py). Поэтому Phase-4
фиксирует нормативно:

```
Te_coenergy = (W'(θ_m + h) − W'(θ_m − h)) / (2 h),   h в механических радианах
```

фазные токи UVW при повороте неизменны; dq0-компоненты стенсил-точек
пересчитываются из тех же UVW под новым углом — это не «изменение тока»,
а следствие вращения системы координат.

**Поправка к DOE-3 §5 — УТВЕРЖДЕНА владельцем 2026-11-25** и внесена в
`TZ_DOE3_CONTROL_CONTRACT_V0_1.md` отдельной пометкой, без переписывания
остальных положений: норматив — механическая производная
`T_mech = ∂W'/∂θ_m|i_UVW` (Н·м), при производной по электрическому углу
`T_mech = p·∂W'/∂θ_e`, где `p` — число пар полюсов; `Te_coenergy` всегда
в Н·м; при угловом дифференцировании фиксированы фазные токи UVW, их
dq0-координаты пересчитываются под новый угол — фиксировать одновременно
UVW и dq0 нельзя; cross-product — диагностика, не источник.

**Знак момента (утверждено):** единый знак `Te_coenergy`, согласованный
с положительным направлением `θ_m`, положительным направлением тока и
принятой ориентацией момента; тесты проверяют не только величину, но и знак.

## 3. Torque data path: конструкция

1. Для каждой строки базовой сетки (узел × угол, 33×12 = 396 строк) — два
   дополнительных состояния `θ_m ± h` при фиксированных UVW-токах строки.
   Стоимость: +792 FEM-состояния на полную ROM. На синтетике стоимость нулевая;
   для реальной кампании — предмет отдельного разрешения.
2. `h = TORQUE_H_DEG` в механических градусах. Текущее значение 5° не
   заморожено как норматив: §6 требует численного обоснования до заморозки.
3. DOE-1 экспортирует в ROM колонку `Te_coenergy` (Н·м, механические)
   для каждой строки сетки. Строки без полного стенсила — колонка пустая
   (missing), а не ноль.
4. Нулевой ток не исключение: `Te_coenergy` при `i = 0` — это cogging-момент
   PM-машины; он не обязан быть нулём и не зануляется (DOE-3 §5).
5. DOE-3 потребляет колонку как есть (уже реализовано в `torque_source`):
   без колонки момент — локальный `NOT_EVALUATED`, вариант C Phase-3.
6. Существующие 3 валидационные группы `TORQUE_STATES` не удаляются.
   Разделение трёх проверок (утверждено):

   | Проверка | Назначение |
   |---|---|
   | Per-row `Te_coenergy` | нормативный источник момента в ROM |
   | `TORQUE_STATES` | валидация способа расчёта момента |
   | cross-product | диагностическая проверка согласованности |

   Успешная проверка `TORQUE_STATES` **не заменяет** отсутствующие per-row
   данные. Неполный угловой стенсил — отсутствующее значение `Te_coenergy`,
   а не нулевой момент. Источник нормативного момента один — co-energy
   derivative; `Te_fem` — validation reference, не вход ROM.
7. Стенсил — полный, все 396 строк (33×12), +792 FEM-состояния
   (APPROVED). Зональная логика не вводится. Реальные FEM-состояния
   не запускаются без отдельного разрешения на кампанию.

## 4. Влияние на соседние поля ROM

Стенсил-точки `θ ± h` **не входят** в базовую сетку ψ/L: их dq0-координаты
не совпадают с узлами решётки. Они используются только для W'-разности.
Это уже устроенное в DOE-1 разделение `kind = "torque"`; контракт
запрещает смешивать стенсил-состояния с сеточными при построении
`psi_delta_scale`, N1/N2/N3 и линеаризации.

## 5. Сквозная интеграция и уровни валидации

Цепочка `DOE-1 → DOE-2/P2-N2 → ROM + summary.json → DOE-3` на синтетике
должна быть прогнана end-to-end одной командой/скриптом, и отчёт обязан
разделять уровни:

| Уровень | Смысл |
|---|---|
| `PASS` (synthetic) | интерфейсная и численная проверка на синтетической ROM |
| `NOT_YET_VALIDATED` | интеграция на реальном FEM-ROM — ожидает backend |
| `NOT_EVALUATED` | контрактный вход отсутствует/недоступен |

Отсутствие реального ROM — не FAIL любого из DOE. Интеграционный прогон
проверяет: `Te_coenergy` доходит до точек DOE-3; наследование P2-N2 работает
с настоящим `summary.json` DOE-1, а не фикстурой; статусная иерархия
`FAIL_3 / NOT_EVALUATED / PASS_3` воспроизводится на сквозных данных.

## 6. Обоснование шага h — процедура утверждена

Историческое h = 5° нормативного статуса не имеет. Для контрольной
cogging-составляющей `W'_cog = A6·cos(6p·θ_m + φ)` аналитический момент
`T_exact = −6p·A6·sin(6p·θ_m + φ)`, а центральная разность даёт
гармоническое ослабление

```
T_FD/T_exact = sin(6p·h) / (6p·h),   h в механических радианах
```

Обязательная процедура эксперимента:
1. Несколько значений h, включая 5° механических.
2. Сравнение `Te_coenergy` с аналитической производной по всему угловому
   диапазону.
3. Отдельно относительная ошибка и абсолютная ошибка около нулей
   аналитического момента.
4. Чувствительность к численному шуму W'.
5. Выбранный шаг обязан одновременно давать разрешение cogging и
   приемлемую ошибку усечения.
6. Выбранный h, критерий приёмки и результаты фиксируются новой редакцией
   контракта.

**Критерий приёмки фиксируется ДО эксперимента и не выбирается постфактум
под понравившееся h.** Если ни один шаг критерий не проходит, 5° не
объявляется приемлемым по умолчанию.

5. Post-implementation audit по этому контракту.

## 8. Отдельная задача: сравнение стенсилов линеаризации

Не смешивается с torque data path. Исследование, не изменение кода:

1. `dm_di`/`l_from_flux` центральная разность при `h = 1.0·I_r` (текущее)
   и `h = 0.5·I_r` — во всех узлах и углах, где оба стенсила существуют;
2. расхождение результатов как функция нелинейности (a4/b4 синтетики);
3. чувствительность к шуму: добавление контролируемого численного шума
   к ψ/M узлов, сравнение усиления шума обоими стенсилами
   (короткий стенсил усиливает шум вдвое сильнее на тот же абсолютный шум);
4. результат — рекомендация с критерием приемлемого расхождения;
   основной код меняется только после заморозки критерия владельцем.

## 11. Редакция V0.2 — критерии и блокеры h-эксперимента (утверждены владельцем 2026-11-25)

### 11.1 Критерии приёмки h — зафиксированы ДО эксперимента

- **C1, truncation:** `|sin(6p·h)/6p·h − 1| ≤ 0.01`, p = 3, h — механический
  шаг в радианах. Отсюда `h_max ≈ 0.78°` мех; 1° и более C1 не проходят.
  C1 — верхняя граница h, не автоматический выбор.
- **C2, нули момента:** абсолютная ошибка в окрестностях нулей аналитического
  момента ≤ 1%·T_peak. Относительная ошибка вблизи нулей не применяется.
- **C3, noise:** при инжекции шума уровня `ε_W` полная абсолютная ошибка
  момента по всем проверяемым точкам ≤ 1%·T_peak — полная ошибка относительно
  аналитического момента, а не добавочная разность шумный/бесшумный.
- `T_peak` — аналитическая амплитуда момента тестовой гармоники.
- **Эталон шума (нормативный уровень инжекции, не утверждение о реальной
  ошибке co-energy):** `ε_W = ε_psi · psi_delta_scale · I_r`, где
  `ε_psi = 1e-3` — frozen относительный бюджет, `psi_delta_scale` — frozen
  масштаб P2-N1 без PM-постоянной составляющей, `I_r` — опорный ток manifest.
  Размерность Вб·А = Дж.
- Инжекция: шум задаётся на каждом значении W' torque-стенсила,
  детерминированный генератор с зафиксированными seed; проверяется худшая
  ошибка по всем точкам и фазам гармоники, а не только средняя. Дополнительно
  предельный угол `η+ = +ε_W, η− = −ε_W` — максимум ошибки центральной
  разности `ε_W/h`. Для независимого ограниченного шума
  `|ΔT_noise| ≤ ε_W/h`: C3 задаёт нижнюю границу h, C1 — верхнюю.
- **Если допустимого интервала [h_min(C3), h_max(C1)] нет — шаг не подбирается
  постфактум и критерии не ослабляются: фиксируется вывод, что заданной
  точности W' недостаточно для torque ROM, и вопрос выносится владельцу.**

### 11.2 Электрический/механический шаг — обязательная конвенция

Исторический `TORQUE_H_DEG = 5.0` в DOE-1 используется как **электрический**
угол: при p = 3 это h_m = 1.667°, потеря 6-й гармоники ~5%, а не 36%.
Нормативная конвенция Phase-4:

```
torque_h_mech_deg         — нормативный параметр (механические градусы)
delta_theta_e_deg = p · torque_h_mech_deg   — электрический сдвиг FEM-состояния
знаменатель производной: 2·h_m в механических радианах
```

Старый `TORQUE_H_DEG` не переиспользуется молча как механический параметр.
При `h_m = 0.78°` электрический сдвиг не более ~2.34°.

### 11.3 Блокеры до запуска h-эксперимента

1. **Истинный cogging при i = 0.** Текущая синтетика: `W'(0,θ) ≡ 0` — все
   члены energy() пропорциональны току. Требуется механическая угловая
   составляющая co-energy `W'_cog(θ_m) = A6·cos(6p·θ_m + φ)`,
   `T_cog = −6p·A6·sin(6p·θ_m + φ)`, ненулевая при i = 0. Член вида
   `iq²·cos(6θ_e)` эту проверку не заменяет.
2. **Согласованность `Synthetic.torque()` с `energy()`.** В `torque()`
   отсутствует вклад explicit-angle члена `psi_cog·cos(2θ)·id` (и любых
   будущих explicit-членов). До устранения расхождения `torque()` не годится
   как ground truth; ground truth h-эксперимента — аналитическая производная
   co-energy, а не `Te` модели.
3. **Missing-value convention:** отсутствующее числовое поле записывается
   пустым; `NaN` и `±Inf` — невалидные данные. Все downstream-проверки
   DOE-2/DOE-3 используют конечность, а не только `None`.
4. **Статусы:** `PASS (synthetic)` и `NOT_YET_VALIDATED` — статусы
   интеграционного отчёта, а не новые статусы физических gate DOE-3;
   `NOT_EVALUATED` остаётся статусом gate при отсутствии обязательного входа.
5. **P2-N2 inheritance:** DOE-3 намеренно наследует только verdict (статус)
   из `summary.json` DOE-1, а не бюджет/допуск; это записано прямо, и
   интеграционный тест не называется проверкой наследования бюджета.
6. **Writer/isfinite на main:** до интеграционного прогона — writer-fix и
   проверки конечности в DOE-1, включая фильтры P2-N1/N2/N3 на пропуск Inf
   и round-trip артефактов (отсутствие не превращается в ноль/число).
7. **Плотная угловая сетка:** 12 точек ROM — предел Найквиста для 6-й
   гармоники; h-эксперимент оценивает аналитическую функцию на плотной
   угловой сетке, не ограничиваясь 12 точками базового ROM.
8. **Бесплатная torque-сверка:** независимая проверка согласованности
   `Te_coenergy` с производной co-energy при фиксированных UVW; формула
   цепного правила UVW↔dq0 выводится и фиксируется явно в реализации,
   дополнительных FEM-состояний не требует.
