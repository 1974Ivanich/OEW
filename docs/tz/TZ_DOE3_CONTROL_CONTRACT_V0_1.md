# ТЗ: DOE-3 control contract v0.1 — BM1109 OEW-6T

**Назначение:** единственное нормативное место физической базы DOE-3
(`tools/bm1109_ctrl.py`): plant-модель, момент, напряжение, нулевая
последовательность, источники величин, семантика статусов и гейты.
Заморожено до Phase-3 implementation; код до заморозки не изменяется.

**Ревизии:** v0.1 (2026-11-25) — исходная редакция по аудиту DOE-3 (блоки
A0–A6) и решениям владельца.

**Источник:** аудит A0–A6 от 2026-11-25; контракты
`POC2_NONLINEAR_CONTRACT_V0_1.md` (P2-N1/N2/N3), DOE-2 voltage contract,
DOE-1 ROM contract.

**Границы:**

- этот документ фиксирует физическую базу, а не переделку синтеза PI:
  структура контура (pole placement, запас по фазе, дискретная модель)
  остаётся предметом отдельного решения;
- последовательность работ: аудит → этот контракт → заморозка →
  implementation commit → тесты → аудит результатов. Implementation до
  заморозки запрещён;
- порядок работ зафиксирован владельцем: `.md` — единственный шаг текущей
  фазы.

## 1. Scope

DOE-3 — синтез цифрового токового контура (PI) и линеаризация nonlinear ROM
вокруг рабочих точек сетки. Voltage **не вне scope**: синтез `K_p = L·ωc`
использует индуктивность как часть физической plant-модели, поэтому voltage
equation наследуется из DOE-2 полностью. DOE-3 не является
mechanical-only projection.

## 2. Нулевая последовательность (A0)

Нормативно:

```text
I_Σ       = i_U + i_V + i_W        — полноценная переменная состояния
I_0,orth  = I_Σ / sqrt(3)
I_0,phase = I_Σ / 3
```

- `I_0 ≠ 0` — допустимое состояние модели, а не исключаемое. `MODEL_EXCLUDED`
  для `I0 ≠ 0` удаляется из нормативной модели; утверждение докстринга «у
  BM1109 OEW-6T нет внешнего пути замыкания суммы фазных токов» физически
  неверно для двух мостов на общей шине и из модели удаляется;
- скрытое предположение `i_U + i_V + i_W = 0` запрещено в любой точке
  расчёта, включая мощность и редукции;
- если временно используется редуцированная модель, её математические
  условия применимости доказываются явно и записываются в контракт до
  реализации; бездоказательная редукция не допускается.

## 3. Plant-модель (A4, A5)

Единственное нормативное уравнение объекта — полное 3×3:

```text
u_dq0 = R_dq0 i_dq0 + L_inc^total · di_dq0/dt
        + ω_e (∂ψ_total/∂θ_e|_i + J ψ_total),   J ψ = (-ψ_q, ψ_d, 0)
```

- никакой скрытой 2×2 редукции: coupling `Ld0`, `Lq0`, `L00` — часть модели;
- DOE-3 не имеет собственного альтернативного voltage equation; функция
  напряжения наследуется из DOE-2 (`voltage()` или эквивалентный вызов);
- `R_dq0` — преобразование фазного сопротивления из UVW по общему dq0
  контракту.

## 4. Flux reference (A2)

- обязательное `psi_reference = ABSOLUTE` на входе; отсутствие подтверждения
  → `NOT_EVALUATED`, не молчаливая интерпретация;
- `ψ(0, θ) = ψ_PM(θ)` сохраняется как PM/cogging-related zero-current flux
  и нигде принудительно не обнуляется;
- относительный flux на входе — contract failure, а не расчётное состояние.

## 5. Момент (A1)

Единственный нормативный источник момента:

```text
T_mech = ∂W'/∂θ_m | i_UVW     (co-energy derivative, Н·м, механические единицы)
```

**Поправка от 2026-11-25 (утверждена владельцем, заморожена в
`TZ_PHASE4_TORQUE_ROM_CONTRACT_V0_1.md` §9.1):** первоначальная запись
`T_e = ∂W'/∂θ_e|i` читалась двусмысленно. Норматив — производная по
**механическому** углу при фиксированных фазных токах UVW; при производной
по электрическому углу `T_mech = p·∂W'/∂θ_e`, где `p` — число пар полюсов.
`Te_coenergy` всегда хранится в Н·м. При угловом дифференцировании
dq0-координаты пересчитываются под новый угол — фиксировать одновременно
UVW и dq0 нельзя. Знак момента единый, согласованный с положительным
направлением `θ_m` и тока.

- `p(ψ_d i_q − ψ_q i_d)` — только derived identity, допустимая при доказанной
  для конкретной ROM эквивалентности; доказательство фиксируется в
  артефакте, иначе формула не применяется;
- `T_e(0, θ) ≠ 0` для PM/cogging-capable ROM не является ошибкой и не может
  исчезать из-за выбора формулы: cross-product форма даёт тождественный
  ноль при `i = 0` и потому неполна без доказательства;
- момент берётся из DOE-1 (угловой стенсил co-energy), а не вычисляется
  второй независимой формулой внутри DOE-3.

## 6. End leakage (A3)

```text
ψ_total = ψ_FEM + L_σ,end^dq0 · i
∂ψ_total/∂θ_e = ∂ψ_FEM/∂θ_e + (∂L_σ,end^dq0/∂θ_e) · i
```

- член `∂θ L_σ,end` не теряется: если он нулевой, это доказывается
  (симметрия UVW-матрицы по фазам), а не предполагается;
- отсутствие данных `L_σ,end` → `NOT_EVALUATED`, не неявный ноль;
- `L_inc^total` в plant-модели включает leakage: синтез `K_p = L·ωc`
  работает с полной индуктивностью, иначе регулятор рассчитан на другую
  машину.

## 7. Source of truth (A5)

| Величина | Единственный источник |
|---|---|
| `ψ` | DOE-1 absolute flux |
| `L_inc` | DOE-1 differential Jacobian |
| `W'` | DOE-1 co-energy |
| `T_e` | DOE-1 co-energy derivative (∂W'/∂θ) |
| `L_σ,end` | Phase-1/2 leakage contract |
| `R_dq0` | UVW phase resistance transform |
| voltage | DOE-2 voltage contract |
| `I0` | общий dq0 contract (§2) |

Второй, упрощённый набор формул внутри `bm1109_ctrl.py` запрещён: любая
величина либо импортируется/вычисляется по контракту источника, либо DOE-3
получает `NOT_EVALUATED`.

## 8. PI synthesis

Per-axis синтез

```text
K_p = L · ω_c,   K_i = R · ω_c
```

— **diagonal approximation**. Наличие cross-coupling в полном `L_dq0` —
часть plant-модели; `coupling_index` — диагностическая величина и не
означает, что coupling учтён в регуляторе. Условия применимости diagonal
approximation (допустимый уровень coupling и критерий его оценки) либо
фиксируются отдельным контрактным критерием с замороженным порогом, либо
результат помечается `DIAGNOSTIC`/не валидируется. Молчаливая diagonal
approximation запрещена.

## 9. Гейты и семантика статусов (A6)

Иерархия:

```text
отсутствующий обязательный контрактный вход → NOT_EVALUATED
реально нарушенный physics/contract gate   → FAIL
```

`MODEL_EXCLUDED` для легитимных состояний модели (в том числе `I0 ≠ 0`)
запрещён.

Замороженные правила перестройки существующих гейтов:

| Гейт | Решение |
|---|---|
| `delay_budget` | удалить: тавтология по построению |
| `zero_sequence_scope` | перестроить из тавтологии в реальную проверку представления I0 (согласованность `I_Σ`, `I_0,orth`, `I_0,phase` в данных ROM) либо удалить |
| `l2_symmetric` | не имеет собственного произвольного `1e-9`: наследует P2-N2 budget на полной 3×3 матрице, либо отдельный frozen contract; проверка в 3×3, не в усечённом 2×2 |
| `l2_positive_definite` | не скрытый gate: отдельный нормативный критерий DOE-3 с budget, либо diagnostic; до решения — diagnostic |
| `torque_flux_identity` | переопределяется на источник §5: сверка с co-energy derivative DOE-1, а не с отсутствующей колонкой `Te_flux` |
| `l_inc_secant_diagnostic` | остаётся INFO-диагностикой — прецедент правильного оформления |

Тавтологические гейты (условие истинно по построению) запрещены во всех
новых гейтах.

## 10. Собственные значения

Комплексные собственные значения линеаризации не могут терять imaginary
part: колебательная неустойчивость иначе невидима. В артефакте — модуль,
вещественная и мнимая части каждого корня; критерий устойчивости формулируется
по вещественной части с учётом пары.

## 11. Что контракт не фиксирует

- структуру и настройку контура скорости (speed loop) — отдельное решение;
- MTPA/FW стратегию;
- численные значения параметров машины (`r_phase`, `f_pwm`, `ω_c`…) — входные
  данные прогона, не контракт;
- аппаратную валидацию: `hardware_validation` остаётся `NOT_EVALUATED` до
  стенда, и никакой PASS синтетики его не заменяет.
