# ТЗ: достоверность выборки тока в цикле FOC (ПК-3)

Статус: **черновик на согласование владельцу**. Код не правится до отдельного «добро на правку».
Дата: 2026-10-31. Автор: агент (ПК-3). Приёмщик: владелец проекта.

## 1. Основание — измеренные факты

Все числа получены на стенде ПК-3 (Nucleo-G474RE + 2× STEVAL-IPM20B, DC-link 30 В,
`mp=15120,19410,15000,20000,55000,0,3,0`, карта `crc32=0xF68D948B`, `@MAP:IDENTITY`
совпала по всем 11 полям).

1. В кадрах `@FOC` состояния RUN **17 % кадров несут `Id=Iq=0`** при `ADC_STATUS=1`:
   7 из 42 в `run_diag_20261015.log`, воспроизводится в `run_diag3_…` и `run_id15_…`.
2. В тех же прогонах `slip_dt` = 0 во **всех** кадрах RUN (проверено сырым значением
   поля, без деления на `PHASE_PER_HZ`), при этом ручная формула для наших чисел даёт
   ≈1490 единиц (и упирается в `MAX_DT`). То есть формула не считает ноль — ноль
   возвращает страж `FocSlipPolicy_ComputeDelta`:
   `abs_i32(prev_dq_d) < FOC_SLIP_POLICY_MIN_ID_INTERNAL (10)`.
3. `prev_dq_d/dq.q` — та же переменная, из которой кадр берёт `Id/Iq`
   (`FOC_GetIdMeasured_mA() = prev_dq_d * 100`, `src/foc.c:405`), и она публикуется
   **безусловно** из `Park_Transform(ab.alpha, ab.beta, theta)` (`src/foc.c:1031-1034`).
   Значит `dq = 0` тогда и только тогда, когда `ab = 0`, то есть когда **выборки тока
   в этом цикле нет**.
4. Следствия, наблюдаемые на стенде и объясняемые одной причиной: разгон с места до
   60–75 об/мин при уставке 100; раскачка `Id` ±1 А при уставке 2 А; срыв на 7–11 с
   с `RUN FAIL: encoder lost` (политика штатно снимает ШИМ).
5. Исключено отдельными измерениями: карта (identity), энкодер (`err=0`, `bad=1`,
   сигнал 896 мкс), шунты (`I1 268…319 мА`, `I2 51…204 мА`, `Ires 233…410 мА` — ровно),
   калибровка/масштаб тока (`al` дал оба канала положительными).

## 2. Дефект

Цикл управления FOC **не отличает свежую выборку тока от отсутствующей**. На циклах
без выборки:
- Кларк/Парк считаются от нуля → `dq = 0` → страж slip отказывает → угол поля теряет
  скольжение → момент проваливается;
- токовый PI получает нулевую обратную связь → накручивает напряжение → на следующем
  валидном кадре получает переток → раскачка тока.

Это не ошибка параметров ротора (`Tr`/`Rr`/`Lm`), не ошибка карты и не ошибка
энкодера. ТЗ на измерение `Tr` **не требуется** и в область этой работы не входит.

## 3. Объём работ

### 3.1. Признак свежести кадра в цикле FOC
- Ввести явный признак «выборка тока валидна в этом цикле» (по полю кадра АЦП /
  счётчику последовательности; не по величине тока).
- При отсутствии выборки: **не публиковать нулевой `dq`** — держать последний валидный
  вектор (или пропускать шаг управления без наращивания напряжения; выбор фиксируется
  в реализации и обосновывается).
- `prev_dq_*` для расчёта slip должны нести последний **валидный** вектор.

**Критерии приёмки:**
- инъекция кадра без выборки не обнуляет `dq`/`slip_dt` и не вызывает роста
  интегратора PI (проверяется тестом, п. 3.2);
- на стенде в кадрах RUN `Id=Iq=0` исчезает как класс; `slip_dt ≠ 0` в кадрах RUN;
- доля потерянных кадров измерена и выведена в телеметрию счётчиком.

### 3.2. Тест, удерживающий поведение
- Юнит/таргетный тест: подать кадр с признаком «нет выборки» и проверить, что
  контроллер не обнуляет вектор и не наращивает напряжение; отдельный тест — что
  страж slip не срабатывает ложно.
- Полный гейт `make test` зелёный (настоящий exit code, без `| tail`).

### 3.3. Причина потери 17 % выборок
- Счётчик пропусков в телеметрии + разбор: гонка с АЦП/TRGO, приоритет ISR,
  логика `sample_window`/сектора.
- **Критерий:** причина названа измерением; остаточная доля пропусков < 1 % на
  установившемся режиме, либо письменно обосновано, почему это норма.

## 4. Ограничения и правила
- `foc.c`/`adc.c`/`pwm*` — safety-модули: правка только по отдельному «добро на правку»,
  с тестами и гейтом; push в `main` — только при зелёном гейте.
- Диагностические сборки (ручной `Tr` в `FocSlipPolicy_TrUsable`, сырой `slip_dt` в поле
  `slip_hz`) в `main` не переносятся. Перед правкой рабочее дерево вернуть к `origin/main`.
- Все прогоны — при DC-link 30 В, аппаратный break при 60 В не трогаем.
- Прошивка/подача напряжения/слияние — только с отдельного разрешения владельца.
- Результаты приёмки — измеренные величины, а не PASS/FAIL по ожиданию.

## 5. Что НЕ входит
- Измерение `Tr`/`Rr`/`Lm`, возврат силового автотюна.
- Пересборка карты токов, калибровка энкодера.
- Настройка усилений PI «на слух» — до устранения причины п. 2.
