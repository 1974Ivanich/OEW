**Ревизия 2026-11-25:** POC-2 приведён к PM-корректной формулировке (см.

требование невыполнимо по построению, а не из-за дефекта модели.

**Ревизия 2026-11-25 (b):** `psi` закреплён как абсолютное потокосцепление

**Ревизия 2026-11-25 (c):** заморожены параметры фазы 2: `eps_psi` с

## Контракт OEW-6T

### Выводы и знаки

Шесть электрических physical groups в `.geo`:

```text
W_U1  W_U2     W_V1  W_V2     W_W1  W_W2
```

Соглашение о знаке фиксировано и не обсуждается в коде экстрактора:

```text
i_U : U1 -> U2
i_V : V1 -> V2
i_W : W1 -> W2
```

Положительный ток входит в первый вывод пары. Обмотка задаётся как stranded
coil с числом витков `N`, плотность тока в group `J = N*i/S` (`S` — площадь
group).

### Запрет нормализации в звезду

Запрещено: вводить star point, заземлять обмотку в общей точке, соединять
`U2/V2/W2` узлом схемы, подменять шесть выводов моделью `U,V,W,N`.

Токи `i_U, i_V, i_W` — независимые входы (у каждой фазы свой мост). Поэтому
требование `i_U + i_V + i_W = 0` в POC **не навязывается**, а измеряется
(POC-3): прежнее `i_0 = 0` — model constraint ROM-модели, а не свойство
топологии с шестью выводами. Если POC покажет, что `i_0 != 0` даёт
существенные `psi`/`Te`, это фиксируется как находка, а не подгоняется под
прежнее допущение.

### Угол

Вход — механический угол `theta_m` (град). Электрический:
`theta_e = p * theta_m`, `p = 3` — **гипотеза**, не измерение; в результатах
указывается оба угла.

## Форматы (контракт с существующим пайплайном)


Выход, `results.csv` — **ровно** те колонки, которые читает `process`
(`tools/bm1109_doe1.py`, `_flux`/`_torque_checks`):

```text

```

для аудита): `case_id,converged,iterations,residual,mesh_version,solver,
solver_version`.

Единицы SI: `psi` — Wb (потокосцепление пары выводов), `W_prime` — J,
`Te` — N*m. В CSV углы в градусах, внутри solver — радианы. Кодировка UTF-8,
разделитель `,`, десятичная точка.

## Определения (не переопределяются в коде)

- `W'(i, theta)` = `∫_Ω (∫_0^B H·dB') dV`; для линейного материала
  `= 1/2 ∫ B·H dV`.
- `psi_k = ∂W'/∂i_k` — центральная разность по сетке кейсов (шаг `Δi` как в
  DOE_1: `0.05`/`0.025 * I_r`), на границе — односторонняя 2-го порядка.
- `Te = ∂W'/∂theta_m` при фиксированных токах. **Не** `dpsi/dtheta`.
- Две независимые ветви для `psi`: из `W'` (энергия) и из `A`
  (потокосцепление по виткам). Расхождение — `eps_psi`.
- Взаимность: `∂psi_U/∂i_V = ∂psi_V/∂i_U` (линейный материал — точно).
- `psi` — **абсолютное** потокосцепление замкнутых катушек, без произвольной
  аддитивной постоянной. У модели с PM `psi(0, theta) = psi_pm(theta) != 0` —
  опорный PM-поток (`PM_REFERENCE`). Аддитивная постоянная в экспорте — ошибка
  постобработки, а не свойство модели.
- `psi_pm(theta) = psi(0, theta)`. Величина `psi_even = 0.5*(psi(+I) + psi(-I))`
  — чётная по току часть; с `psi_pm` она совпадает только для линейного материала.
- `W'(0, theta_ref) = 0` — выбранная нормировка в одной опорной точке, не
  физическое утверждение: при PM `W'(0, theta)` меняется с углом
  (`∂W'(0, theta)/∂theta_m = Te_cog`).
- Тип модели `model_type = NO_PM | PM` фиксируется в `manifest.json` до серии.

### Smoke-тест инфраструктуры != BM1109 POC

- **Smoke-тест** на нейтральной тестовой геометрии проверяет только
  инфраструктуру: Gmsh -> `.msh` -> GetDP -> `results.csv` -> `process`.
  Артефакты — `build/tools/smoke/`. Они **не** попадают в FEM dataset BM1109
  (`build/doe1/`), в ROM, в summary DOE и в любые выводы о машине.
- **BM1109 POC-1** требует G0 PASS и реальных размеров и материалов.
- Параметрическая модель без подтверждённых размеров маркируется
  `BM1109_GEOMETRY_HYPOTHESIS` и не используется для FEM-кейсов.

Первый прогон smoke (2026-11-25, `solver/getdp_smoke/`): S0–S5 PASS,
энергия `0.176336 J/m`, поток через торец `1.38856e-04 Wb/m`,
`max|B| = 0.0708 T`, повторный прогон совпал (S4). Артефакты —
`build/tools/smoke/` (`manifest.json`, `diagnostics.csv`, логи, `.msh`, `.res`).

Наблюдение smoke, которое **нельзя обобщать**: в проверенной комбинации
(GetDP 3.5.0 + `Form1P`/`BF_PerpendicularEdge` + `Integral`-постобработка +
этот `.pro`) поле `{d a}` на 1D-регионе даёт `0`, тогда как `∫ 1 dl`
возвращает точную длину `0.01 m`. Это ограничение именно проверенной
комбинации, а не всех 1D-регионов и не всех формулировок GetDP; при смене
формулировки проверка повторяется.

Поток в smoke считается как `A_z(P2) − A_z(P1)` [Wb/m]. Это поток на единицу
осевой длины, **не** потокосцепление катушки `psi`: для `psi` нужны реальная
геометрия витков, их ориентация и число витков, и переход `A -> psi_UVW`
в BM1109 POC — отдельная проверка (см. приложение G0-M, §8).

## Пять физических проверок

### POC-1 — zero current

`(i_U, i_V, i_W) = (0, 0, 0)`, 3–4 угла. Solver сходится; поле конечно;
`|Te|` не превышает ожидаемый cogging/позиционный момент (порог фиксируется в
`manifest.json` **до** серии, не после); паразитного тока нет.

| Модель | Нулевое состояние |
|---|---|
| `NO_PM` | `|psi_k(0)| <= 1e-9 * psi_scale`; `|Te(0, theta)| <= abs_floor` |
| `PM` | `psi_k(0, theta) = ∂W'/∂i_k(0, theta)` с допуском `eps_psi`; значение пишется как `psi_pm(theta)`, ноль **не** требуется |

### POC-2 — одна пара выводов

`(I, 0, 0)` и `(-I, 0, 0)` на двух углах. Это тест sign convention, но форма
проверки зависит от наличия PM-составляющей:

```text
psi(+I) + psi(-I) = 2 * psi_pm(th)              (не ноль при PM)
Te(+I)  + Te(-I)  = I^2 * dL/dth + 2 * dC/dth   (в общем случае не ноль)
psi(+I)  - psi(-I) = 2 * L * I                  (PM сокращается)
```

| Модель | Проверка |
|---|---|
| линейная без PM | `|psi(+I) + psi(-I)| <= 1e-6 * max|psi|` — исходный критерий |
| линейная с PM | приращение от нулевого тока: `psi_inc = psi(+I) - psi(0) > 0` и `|psi(+I) - psi(-I) - 2*psi_inc| <= 1e-6 * psi_scale` |
| нелинейная с PM | согласованность с co-energy (`psi = grad_i W'`) и симметрия `L_inc`; универсальная антисимметрия по току **не** проверяется |

`psi_even = 0.5*(psi(+I) + psi(-I))` записывается как diagnostics, ноль не
требуется; `psi_pm` берётся как `psi(0, theta)` (раздел «Определения»). По моменту: `Te_odd = 0.5*(Te(+I) - Te(-I))` (PM-момент) и
`Te_even = 0.5*(Te(+I) + Te(-I))` (cogging + реактивный);
`Te(+I) = -Te(-I)` критерием не является.

### POC-3 — три независимых состояния и проверка отсутствия звезды

`(I,0,0)`, `(0,I,0)`, `(0,0,I)` на одном угле. Строится матрица
`psi_a(i_b)` 3x3, проверяется взаимность. Отдельно измеряется разница
`psi(i_0 != 0)` против `psi(i_0 = 0)` — число записывается в отчёт, а не
объявляется нулём.

### POC-4 — суперпозиция

Линейный материал: `psi(I,I,0) = psi(I,0,0) + psi(0,I,0)` с допуском
`1e-6` относительно. На нелинейном материале проверка обязана **не** проходить
(это подтверждает, что нелинейность действительно включена).

### POC-5 — энергия и момент

Для `(i, theta_m)`: `W'`, `psi_k = ∂W'/∂i_k`, `Te = ∂W'/∂theta_m`.
Гейты: `eps_psi = max_k |psi_W',k - psi_A,k| / max(psi_scale, psi_floor) <= 1e-3`
(`psi_floor` — из `manifest.json`, до серии), `Te` из `∂W'/∂theta` против Maxwell
stress <= 2 % (или абсолютный floor для малых моментов).

## Выход на DOE-2 и DOE-2C

**Опорный уровень `psi`.** Результат FEM, передаваемый в DOE-2, обязан нести
`psi_reference = ABSOLUTE`. DOE-2 использует `psi` в ЭДС `omega_e * J * psi`
напрямую; вход без этого поля или с другим значением DOE-2 отклоняет.

**Лобовые части.** 2D FEM даёт потокосцепление на длину пакета и не учитывает
рассеяние лобовых частей. Оно задаётся отдельным параметром — матрицей
`L_sigma_end^UVW` (3×3, симметричная, не зависит от угла ротора), не скаляром:

```text
L_sigma_end^dq0 = T * L_sigma_end^UVW * T^T
psi_total       = psi_FEM(i, theta) + L_sigma_end^dq0 * i
L_total,inc     = L_FEM,inc + L_sigma_end^dq0
u = R i + L_total,inc di/dt + omega_e * (∂psi_total/∂theta_e|_i + J psi_total)
```

`L_sigma_end` в `psi_pm` не входит (`psi_pm = psi_FEM(0, theta)`), но входит
и в `L di/dt`, и в `J psi_total`: без него занижены и индуктивное падение, и
перекрёстная ЭДС `omega_e * J * L_sigma_end^dq0 * i`. Предпосылка:
`L_sigma_end^UVW = const` (от угла ротора не зависит). Циркулянтность этой
матрицы (`L_s` на диагонали, `M_s` вне её) — достаточное условие того, что
`L_sigma_end^dq0 = diag(L_s - M_s, L_s - M_s, L_s + 2*M_s)` от `theta_e` не
зависит. При неравных фазах даже постоянная в UVW матрица в общем случае даёт
`∂L_sigma_end^dq0/∂theta_e != 0`, и угловой член остаётся полным:
`omega_e * (∂psi_FEM/∂theta_e + ∂L_sigma_end^dq0/∂theta_e * i)`.
Значение `L_sigma_end` и метод его получения записываются в манифест; при
отсутствии — `NOT_EVALUATED` для напряжения DOE-2, не ноль по умолчанию.

**Режим состояния DOE-2C** (`state_mode`, обязателен, не выводится из наличия
`c_dc`/`step_s`):

| `state_mode` | Смысл | Требования |
|---|---|---|
| `INDEPENDENT` | каждая строка — отдельная рабочая точка: `x_k = x_init` | состояние ёмкости между строками не переносится; порядок строк не влияет на результат |
| `SEQUENTIAL` | строки — траектория: `x_{k+1} = F(x_k, u_k)` | монотонное время `t_k`; заданное начальное состояние `V_cap(t_0)`; порядок строк сохраняется, сортировка без явного указания запрещена; каждая строка начинается с конечного состояния предыдущей |

Сходимость по шагу для `SEQUENTIAL` проверяется на всей связанной траектории.
`dt` — внутренний шаг интегрирования; длительности строк не меняются. Параметры
заморожены (ревизия c), подбирать их по результату запрещено:

| Параметр | Значение |
|---|---|
| набор шагов | `dt = 20, 10, 5, 2.5 мкс`; одинаковые `V_cap(t_0)` и `state_mode = SEQUENTIAL` |
| интервал | вся траектория `[t_0, t_N]` |
| ошибка пары | `eps_x(dt) = max_k |x_dt(t_k) - x_dt/2(t_k)| / max(|x_dt/2(t_k)|, x_scale)` |
| наблюдаемые и `x_scale` | `V_dc` → `V_src,nom`; `E_cap` → `0.5 * C_DC * V_src,nom^2`; `P_src` → `V_src,nom * I_src,max` |
| точность | `eps_x(5 мкс ↔ 2.5 мкс) <= 1e-3` для каждой наблюдаемой |
| порядок | `q = log2(eps_x(dt) / eps_x(dt/2))` для каждого из двух соседних отношений (`20↔10 / 10↔5` и `10↔5 / 5↔2.5`); каждое `q >= 0.8` |

Если `eps_x` уже на уровне округления (`<= 1e-12`), `q` не вычисляется и
пишется `NOT_EVALUATED (converged to roundoff)`, а не FAIL. Проверка одного шага
против 8 подшагов той же замороженной экспоненты — согласованность реализации
(`frozen_load_exact_solution_consistency`), а не сходимость.

## Смежные ограничения (не меняются сейчас)

- **S2 остаётся на 24 углах.** Это минимальная разрешающая конфигурация
  synthetic oracle (`N/2 - 1 >= 6`), а не выбор сетки для FEM. Вопрос
  `24 vs 28 vs 36` — отдельное решение по дизайну FEM DOE.
- **angular resolution != physical harmonic content.** `harmonics_resolved = 6`
  означает, что сетка различает 6-ю гармонику, а не что она физически
  присутствует с существенной амплитудой.
- **C_ROM != physics_coverage.** Полнота ROM-узлов не даёт `PASS` по
  кросс-производным (закреплено тестом).
- `abs_max`/`rms` кросс-производных остаются diagnostics, не gate.
