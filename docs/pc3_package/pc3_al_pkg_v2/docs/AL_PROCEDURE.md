# Процедура align-check на стенде (ред. 2 — команды сверены с кодом 4507983)

Отличия от ред. 1 (и правки по приёмке ред. 2):

1. удалено правило «`i=` не использовать / ответ unknown → уставка через `s=`»,
   опиравшееся на неверное дерево: `4507983` содержит `i=<Id>,<Iq>` как штатную
   команду (раздел 6, docs/COMMANDS.md);
2. **инвертирована ветка наблюдения** (раздел 3): во время удержания штатно
   JADSTART = 1 и живая @FOC; JADSTART = 0 в удержании — аномалия, а не
   альтернативный способ измерения. Причина: `PWM_AlignApertureStart()`
   взводит injected (`ADC_InjectedStart()`), а при взведённом JADSTART
   `ADC_StartConversion()` сразу отказывает (`src/adc.c`), поэтому `a` внутри
   удержания даёт молча устаревший кадр;
3. срединный `dumpa` понижен до опционального кросс-чека; обязательным
   остаётся пост-мортем (раздел 5).

## 0. Подготовка

Установить внешний лимит источника. Зафиксировать вариант сборки
(production / OEW_SD_MONITOR_ONLY) и фактический Vbus.

## 1. Preflight

```
c
dump
dump8
sysinfo
a?
a
dumpa
```

Записи — по docs/SAFETY.md, раздел Preflight. Замечание по offset'ам:
`c` печатает `@ADC:CAL:offset_i1=..:offset_i2=..:offset_ires=..` напрямую
(src/cli.c:71), поэтому offset I2 не нужно выводить из нулевого raw — он
наблюдаем явно. Прежняя формулировка («a? печатает только offset_i1, поэтому
нулевой raw используется как offset I1 и I2») верна только для `a?`
(src/cli.c:58-60) и как оценка остаётся допустимой, если `c` отказывает
(`@ADC:CAL:FAIL:rc=..`, например Ires unqualified). `c` требует выключенного
инвертора.

## 2. Align

```
al            -> дословный ответ (@AL:... или admission-отказ)
dumpa         -> регистровый снимок ВО ВРЕМЯ удержания (безопасен:
                 читает только регистры, конверсий не запускает);
                 опциональный кросс-чек, ожидаемо JADSTART = 1 (раздел 3)
```

Актуальные поля ответа: `@AL:OK:code=0:u=..:uu=..:v=..:vv=..:w=..:ww=..:
i1_ma=..:i2_ma=..:align=0` (u/uu — CCR1..CCR3 TIM1, v/vv — TIM8), отказы —
`@AL:FAIL:start (PWM off, no fault, SD high, ADC idle)` / `@AL:FAIL:vector`;
завершение — `al off` → `@AL:OFF` (src/cli.c:140-190).

## 3. Режим наблюдения во время удержания

Штатно `PWM_AlignApertureStart()` взводит injected (`ADC_InjectedStart()`),
поэтому во время удержания ожидаемо **JADSTART = 1** (`dumpa`, поле CR, бит 3),
и основной канал наблюдения — живая телеметрия `@FOC` (10 строк/с, значения
уже в мА: `AdcFrame` публикуется в `ADC_InjectedIrq` → `adc_commit_injected_frame`
→ `adc_publish`, `src/adc.c:392-416`, независимо от `FOC_IsRunning()`;
гейт `src/adc_dispatch.c:24-28` закрывает только PROTECT и `FOC_RunFrame`).
По `@FOC` берутся критерии 1–3 (знак, устойчивость, отсутствие runaway).

- `a` внутри удержания запрещён. При взведённом JADSTART `ADC_StartConversion()`
  сразу возвращает −1 (`src/adc.c`), кадр не обновляется, а raw-геттеры читают
  последний опубликованный кадр (`src/adc.c:688-691`) — `a` печатает молча
  устаревший результат. Это не «безвредное чтение».
- `dumpa` в середине удержания — опциональный кросс-чек регистров (JDR1/JDR2
  против значений из `@FOC`). Обязательным остаётся пост-мортем (раздел 5).
- **JADSTART = 0 во время удержания — аномалия**, а не альтернативная ветка:
  injected либо не взведён (старт апертуры не прошёл, а `al` всё же ответил),
  либо снят (fault/Stop) → `@FOC` stale, критерии недействительны. Действие:
  `al off`, питание вниз при необходимости, разбор по пост-мортему
  (`dump`, `dump8`, `sysinfo`, `a`, `dumpa`) и по полям `@FOC`
  FAULT/FAULT_R/FAIL/RUN/em_stop.
- Формула `мА ≈ Δraw · 12.79` (63 мВ/А тракт; 3300 мВ / 4096 отсч / 63 мВ/А
  = 12.788 мА/отсч) остаётся применимой вне удержания — префлайт и пост-мортем,
  где JADSTART = 0, — но НЕ является способом наблюдения внутри удержания.
- Ограничитель во время удержания: PROTECT вне FOC структурно слепа, а у `al`,
  в отличие от `ch`, нет собственного токового порога. Живые ограничители —
  внешний лимит источника и аппаратный break (если физически разведён).

## 4. Критерии (по порядку значимости)

1. sign(I1) = −sign(I2) — относительная полярность измерительных цепей;
2. ток стабилен между двумя наблюдениями;
3. нет роста тока во время удержания (runaway);
4. дополнительно, при удержании ≥ ~100 мс (установившийся режим):
   |I1| / |I2| ≈ 2; для коротких удержаний — не критерий;
5. raw в пределах 50..4045 (отсечки насыщения/около нуля).

Ires в принятии решения НЕ используется.

Нарушение 1 при выполненном отношении — локальная причина (канал,
offset, усиление): локализовать, ничего не инвертировать.
Отношение верно, знаки верны, абсолютный знак противоположен ожиданию —
глобальная конвенция (правится в одном месте), не перепутанная проводка.

## 5. Завершение

```
al off
dump
dump8
sysinfo
a
dumpa
```

Требуется: MOE = 0 на обоих таймерах, CCER = 0, ток вернулся к
префлайтовому нулю, OVR без дельты, FAULT = 0, JADSTART в baseline-состоянии.

## 6. Результат → следующий шаг

все критерии 1–5 + пост-мортем OK:
    параметры двигателя (маршрут A или B, docs/SAFETY.md) → pp=3 →
    `i=<Id_mA>,<Iq_mA>` → минимальный короткий FOC;
критерий 1 нарушен:
    локализация канала;
критерий 2 или 3 нарушен:
    STOP, анализ по полям @FOC;
FAULT ≠ 0 или hardware break:
    STOP, пост-мортем dump/dumpa;
al не даёт тока вообще:
    STOP, dump/dump8/sysinfo.

Ни при каком результате не переходить к `1` без заполненных параметров
двигателя и подтверждённого pp=3 (Autotune_Init обнуляет pole_pairs
при загрузке; устанавливают только pp=N или седьмое поле mp=).

Юниты: токи — **мА**. `i=<Id>,<Iq>` — обе величины обязательны, `Iq=0` —
режим без прямой q-уставки; ответ `@I:OK:Id=…:Iq=…` (src/cli.c:427 →
main.c:519 cli_foc_current → FOC_SetIdRef/FOC_SetIqRef). Команда только
пишет уставку и силовую часть не включает, поэтому безопасна до `1`;
значения клампятся в ±10000 мА (FOC_I_MAX_MA).

`s=N` — независимая уставка скорости (±50000 об/мин), НЕ замена `i=`;
развилки «пробный ввод i= → unknown → использовать s=» не существует.

`mp=` выполнять при запитанной шине на рабочем для первого FOC напряжении
(Vbus участвует в расчёте PI); в `@MP:OK` проверить ненулевые Kp/Ki и AP=1.
Коды отказа `1`: 0=OK, −1=clock/fault, −2=map_unverified, −3=calib,
−4=arm, −5=pwm_enable, −6=params_out_of_range; −2 и −3 — входные
fail-closed условия (нет действующей карты токов / калибровки), а не авария:
их устраняют до попытки первого FOC, FAULT при этом не защёлкивается.
