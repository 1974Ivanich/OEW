# CORRECTIONS_v2 — дефекты ред. 1 и их правки

Аудит проведён **до** запуска скана (пакет в ред. 1 не прогонялся на стенде).
Ссылки — на замороженный образ `ab1274d` (тот, что заявлен в §1 протокола);
проверка — через `git show ab1274d:<файл>`, а не по памяти.
Итог: SHA-256 архива совпадал с заявленным, внутренние проверки ред. 1 проходили,
но редакция была **небезопасна к запуску**: шкала метрики уезжала в 8.5 раза,
автостоп по `FAULT` был мёртв, амплитуды не отправлялись.

| № | дефект ред. 1 | следствие | правка ред. 2 |
|---|---|---|---|
| B1 | `COMMANDS.md` требует `--sysclk <TCLK из sysinfo>`, а `calc_expected.py` ещё раз делит на `PSC+1` | шкала завышена в 17 раз (294 Гц вместо 5000) | `--clk` = `CLK` из `sysinfo`; `--tclk` — только сверка `CLK/(PSC+1)`; охранник `--pwm-expected` |
| B2 | `f_JEOS = 2*f_pwm` без учёта `TIM1->RCR` | `N_expected(2 с) = 1176` вместо 10000 | `f_JEOS = f_UEV/(RCR+1)`, `RCR` из исходника (`src/pwm.c:273`) |
| B3 | драйвер брал `RUN/STATE/FAULT/CCR1` из `sysinfo` | полей там нет → автостоп по `FAULT` не работал | живые поля берутся из `@FOC`; стоп по `FAULT`/`FAULT_R` |
| B4 | стоп по подстрокам `EM_STOP`/`SD active` | таких строк в прошивке нет → проверки мертвы | стоп по `em_stop1==0`/`em_stop2==0` (поле = уровень линии SD) |
| B5 | `--amp` нигде не отправлялся (`i=` не выдавалось) | 4 «амплитудные» ячейки идентичны | `i=<Id_ma>,<Iq_ma>` после `1` и до окна; ответ `@I:OK` + `Id_ref/Iq_ref` в окне |
| B6 | документация: `i=<mA>,<deg>`, второй аргумент — угол | неверная семантика (второй аргумент — `Iq` в мА) | документировано как `i=<Id_ma>,<Iq_ma>`; угол превращается в `Id/Iq` в драйвере |
| B7 | «каждый `f` вызывает `ADC_CalibrateOffsets`» | неверно: калибровка только при успешном снятии латча (`rc==0`) | формулировка исправлена; `f` драйвером не отправляется вообще |
| B8 | «`-8`/`rc=-8` = не energize-сборка» | `-8` не существует; реальная подпись — `rc=-5` | стоп с текстом `@FOC:START:FAIL:rc=-5` (`FOC_START_PWM_ENABLE_FAILED`) |
| B9 | шаг 0 требует `rev` и `cv` (`@ADC:CV:…`) | в `ab1274d` этих команд нет | проверка образа через `p?` (`SYS/PSC/ARR/CR1`) |
| B10 | сайдкар `.sha256` для ZIP отсутствовал | получатель не мог проверить целостность архива | `scripts/build_foc_scan_48cell_pkg.py` пишет `<zip>.sha256` |

## B1. Шкала: `TCLK` вместо `CLK` (ошибка ×17)

`src/pwm.c:612` — `PWM_GetSysInfo()`: `tclk = get_tim_ck_int()/(TIM1->PSC+1)`.
`src/cli.c` — `@SYS:CLK=%lu:PSC=%lu:TCLK=%lu:…`, где `CLK` = `SystemCoreClock`
(`main.c`, `cli_pwm_sysinfo()`: `out[0]=SystemCoreClock`).

То есть `TCLK` — частота **счётчика**, а не тактовая таймера. Ред. 1 подставляла `TCLK`
в поле `--sysclk`, а `calc_expected.py` делила на `PSC+1` второй раз:

```text
ред. 1:  10_000_000/(16+1)=588 235 Гц  ->  f_pwm = 294.1 Гц,  f_JEOS = 588.2 Гц,  N(2 с) = 1176
ред. 2: 170_000_000/(16+1)=10 000 000 Гц -> f_pwm = 5000.0 Гц, f_JEOS = 5000.0 Гц,  N(2 с) = 10000
```

Правка: вход шкалы — `CLK`; `--tclk` используется только как сверка и при расхождении даёт
`MISMATCH` + код возврата 1; дополнительно `--pwm-expected 5000` сверяет декод с
`FOC_PWM_FREQ` (`src/pwm.c:13`) — ошибка такого класса больше не проходит «молча».

## B2. `RCR` выпал из формулы

`src/pwm.c:273` — `TIM1->RCR = 1u` (и `:293` для TIM8). При `RCR=1` и CMS=11
(центр-выровненный: 2 update-события за период) TRGO идёт с частотой
`2*f_pwm/(1+1) = f_pwm = 5000 Гц`, а не `2*f_pwm`. Ред. 1 считала `N_expected(2 с) = 1176`,
реальное ожидание — `10 000`; живая ячейка дала бы отношение `≈ 8.5`, правило кросс-чека
ред. 1 («отношение 2 или 0.5») не срабатывало → **ложный L2 PASS**.

`dump` RCR не печатает (`PWM_DumpRegs`, `src/pwm.c:629`) — поэтому в ред. 2 RCR фиксируется
как якорь на исходник образа (с явным указанием этого в `IDENTITY_AND_BASELINE.md`).

## B3. Живые поля брались не из той строки

Формат `@SYS` (`src/cli.c`): `CLK/PSC/TCLK/PLLCFGR/OVR/JEOS/TO/JQOVF/uart_drp/uart_trunc` —
полей `RUN`, `STATE`, `FAULT`, `CCR1` там нет. Они в `@FOC` (`src/telemetry_format.h`,
`FOC_TELEMETRY_FMT`): `…:Id: Iq: Id_ref: Iq_ref: VBUS: STATE: SPD: TH: sector: window:
CCR1: CCR2: CCR3: ADC_STATUS: FAULT: FAULT_R: FAIL: RUN: em_stop1: em_stop2`.
Ред. 1 парсила их из `sysinfo` → `None` → автостоп по `FAULT` не срабатывал никогда.
Правка: `@SYS` — для `JEOS/OVR/CLK/PSC/TCLK`, `@FOC` — для состояния; парсится **последняя**
строка `@FOC` внутри окна (без смешивания «до»/«после»).

## B4. Мёртвые стоп-проверки

Литералов `EM_STOP` и `SD active` в прошивке нет. Правильный источник — поля `em_stop1/2`
в `@FOC`, которые заполняются как `PWM_EmStop1IsHigh() ? 1u : 0u` (`main.c`): `1` = линия
высокая = здоровая, `0` = авария. Правка: стоп при `em_stop1==0 || em_stop2==0`; осознанное
исключение `--no-sd-stop` — только с записью в возврате.

## B5/B6. Амплитуды не отправлялись, семантика `i=` перепутана

Обработчик (`src/cli.c`): `sscanf(line, "i=%d,%d", &a1, &a2)` → `foc_set_current(a1,a2)` →
`FOC_SetIdRef(a1); FOC_SetIqRef(a2)` (кламп ±`FOC_I_MAX_MA` = 10 000 мА) → ответ
`@I:OK:Id=%ld:Iq=%ld`. Второй аргумент — **`Iq` в мА**, а не угол (ред. 1 писала `<deg>`).
Драйвер ред. 1 не отправлял `i=` вообще, поэтому 4 «амплитудные» ячейки были идентичны.

Правка: `Id = A·cos(θ)`, `Iq = A·sin(θ)`; отправка **после** `1` (первый `FOC_Start()`
вызывает `FOC_Init()` с `id_ref_ma = FOC_DEFAULT_ID_REF_MA` = 2000 мА, а сброса уставок
в `FOC_Start` нет — порядок «после `1`» исключает тихую подмену) и **до** окна;
ответ `@I:OK` и поля `Id_ref/Iq_ref` из окна пишутся в `cells.csv`.

## B7. `f` и калибровка нулей

Обработчик `f` (`src/cli.c`): при работающем FOC/Vf — отказ (`err: stop FOC/Vf first`);
иначе `rc = fault_request_clear()`, и калибровка выполняется **только если латч реально снят**:

```c
int rc = ops->fault_request_clear();
if (rc == 0) { ops->adc_calibrate(); ops->send_dbg("fault cleared\r\n> "); }
else { … rc=1: "no latched fault was active" … }
```

Поэтому утверждение ред. 1 «каждый `f` вызывает `ADC_CalibrateOffsets`» неверно:
`f` при чистом состоянии ничего не калибрует. Само FOC-стартование калибрует нули, но
только если они невалидны (`src/foc.c`: `if(!ADC_OffsetsAreValid() && ADC_CalibrateOffsets() != 0)
return FOC_START_CALIBRATION_FAILED;` — код `-3`). Правка: формулировка уточнена,
`f_list.txt` сохранён как отчётный файл, но драйвер ред. 2 не отправляет `f` **никогда**.

## B8. Подпись «не energize-сборка»

Коды `FOC_Start()` (`src/foc.h`): `0` OK, `-1` clock/fault, `-2` map_unverified, `-3` calib,
`-4` adc arm, `-5` pwm enable, `-6` params out of range. Ответ на `1` при отказе —
`@FOC:START:FAIL:rc=%d (0=OK -1=clock/fault … -5=pwm_enable …)`. Кода `-8` в FOC-старте
не существует (это коды V/f-старта команды `vf=`). Правка: стоп-текст драйвера
и `START_HERE` называют именно `rc=-5` (`FOC_START_PWM_ENABLE_FAILED`), а про `-7`/`-8`
сказано, где они живут.

## B9. Несуществующие команды в шаге 0

В `ab1274d` нет ни `rev`, ни `cv` (проверено поиском по `main.c` и `src/`), и нет строки
`@ADC:CV:`. ADC-телеметрия образа: `@ADC:I1=…:I2=…:Ires=…:VBUS=…`, `@ADC:STATUS:…`,
`@ADC:CAL:…`. Правка: проверка образа без перепрошивки — по `p?`
(`@PWM:FULL:SYS=…:T1:PSC=…:ARR=…:CR1=…`), ожидание для `ab1274d`:
`SYS=170000000`, `T1:PSC=16`, `T1:ARR=999`, `CR1` с CMS=11.

## B10. Отсутствие сайдкара

Ред. 1 передавалась одним ZIP; SHA-256 сверялся по переписке. Правка:
`scripts/build_foc_scan_48cell_pkg.py` пишет `<zip>.sha256` (формат `sha256sum`:
`<hex> *<имя>`) и умеет `--verify` (состав + хеши внутри `SHA256SUMS` + сайдкар).
ZIP детерминирован, поэтому один и тот же вход даёт один и тот же SHA-256.

## Что ещё добавлено в ред. 2 (свойство, а не косметика)

* `TOOLS/check_package.py` проверяет не «файлы на месте», а **свойства**: состав + покрытие
  `SHA256SUMS` без пропусков/лишних строк, отсутствие CRLF/BOM (иначе хеши зависят от
  `core.autocrlf`), контрольные числа шкалы (5000/5000/10000), отказ на подстановке `TCLK`,
  и инварианты драйвера (`--dry-run`: `f` среди команд = 0, `i=` строго после `1`);
* `docs/pc3_package/foc_scan_48cell_v2/.gitattributes` фиксирует `eol=lf` для `*.md`, `*.py`
  и `SHA256SUMS` — байты пакета не зависят от машины получателя;
* весь консольный вывод инструментов — ASCII (комплекты ПК-3 ранее отклонялись за
  `UnicodeEncodeError` на консоли cp1251/ascii);
* `TOOLS/scan_48cell.py` возвращает код 1 при автостопе, 2 при ошибке входа, пишет
  `cells.csv`, `session_raw.log`, `summary.txt` (уровни L0/L1/L2/unscaled, медиана отношения
  `ΔJEOS/N_expected`, подсказка по декоду, список отправленных `f`).

## Чего в ред. 2 по-прежнему нет (осознанно)

* проверки `FAIL=0` как стоп-условия: `FAIL` = `FOC_GetStartupFailReason()`, в начале разгона
  ненулевое значение ожидаемо → пишется как warning (это L4-критерий, читается глазами);
* чтения `RCR` с платы: `dump` его не печатает, а добавлять прошивку до конца скана запрещено
  (§7) — поэтому RCR фиксируется якорем на исходник образа;
* доказательства, что образ на плате — именно `d2bc0439…`: это доступно только на стенде
  (шаг 0), в пакете нет способа проверить это софтом.
