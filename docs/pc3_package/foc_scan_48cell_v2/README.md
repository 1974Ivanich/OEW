# Пакет FOC 48-ячеечного скана (ПК-3), ред. 2

Пакет для 48-ячеечного скана: 12 углов × 4 амплитуды, метрика — прирост счётчика `JEOS`
(`ΔJEOS`) за 2-секундное окно молчания. Прошивка не меняется и не перепрошивается:
счётчик уже есть в замороженном образе на плате (`ab1274d`, заявленный образ `d2bc0439…`).

Ред. 2 заменяет ред. 1 (передавалась одним ZIP без сайдкара): исправлены 19 дефектов,
из-за которых ред. 1 **нельзя было запускать** на стенде, — шкала метрики уезжала в 8.5 раза
(ложный L2), автостоп по `FAULT` был мёртв, амплитуды вообще не отправлялись, проверка
образа (шаг 0) искала строку `@PWM:FULL:`, которую печатает `pdump`, а не `p?`, а чтение
энкодера предлагалось полем `eangle=` из V/f-логирования вместо команды `enc`.
Последние два дефекта (B13, B14) — про **машинную проверяемость** шага 0: у него не было
софтверного вердикта (док заявлял, будто образ на плате нельзя проверить софтом), а токенов
`T1:ARR`/`T1:CR1`, на которые ссылались доки, в выводе образа нет: префикс группы `T1:`/`T8:`
стоит только у первого поля (`T1:PSC=16`, `T8:PSC=16`), дальше идут голые `ARR=`/`CR1=`.
Теперь вердикт шага 0 снимает `TOOLS/check_step0.py`. Следующий дефект (B15) найден **на стенде**
при первом запуске: инструменты читали порт блокирующе (`timeout=0.2` + `read(4096)`), а на VCP
STLink (`STLink Virtual COM Port`) такой `read()` не возвращается вообще — шаг 0 и скан висели
насмерть; теперь чтение неблокирующее (`timeout=0` + `in_waiting`).
Ещё два дефекта (B16, B17) найдены **на стенде** при живом запуске скана 2026-10-04: ред. 2
обещала только ответ `rc=-5` на `1` и не описывала ни гейт параметров двигателя (`rc=-6`
`params_out_of_range` — дефолт прошивки fail-closed: нужны `mp=<Rs_mOhm>,<Ls_uH>` +
`mpapply`), ни гейт карты секторов (`rc=-2` `map_unverified`), ни порядок снятия аппаратного
break (`FAULT_R=18`: сначала `c`, потом `f`). Сессия встала на первой же клетке с нулём из 48
ячеек; теперь коды ответа на `1`, состояние карты/параметров и порядок снятия латча описаны,
а самопроверка пакета требует их в доках (правило 10).
Третий стендовый дефект (B18, поправка к B17) — про вывод «команды `mapload` в образе нет»:
он был сделан по ответу `unknown` на слово без аргумента, а парсер ждёт `mapload ` + 994
hex-символа. Правильно поставленный читающий зонд (`mapload 00` → `@MAP:LOAD:FAIL:DECODE`,
`mapcap status` → `@MC:STATUS:…`) показывает, что весь L3-путь в образе **есть**
(`mcarm=`/`mapcap run`/`mapcap drain`/`mapcap build=<profile_id>`), а внешние артефакты от
08.09 не подходят по identity (`pwm=294` — дефект D3, двойной учёт `PSC`). Самопроверка
требует арность, запрещает вывод «команды нет» из `unknown` и требует профили BOAR
(правило 11).
Девятнадцатый дефект (B19) — про ссылки на файлы **вне архива**: доки указывали на
`docs/ACCEPTANCE_LESSONS.md` §25.10 (первоисточник порядка точки карты), `src/…`,
`scripts/…`, папку `мотор анализ\…`, но нигде не говорили, что этих файлов в ZIP нет, —
получатель с одним архивом искал бы их внутри пакета. Теперь есть раздел
«Внешние ссылки (не в ZIP)» с полным перечнем, а правило 12 следит, чтобы перечень совпадал
с фактическим употреблением (в обе стороны).
Полный разбор с ссылками на исходник: [CORRECTIONS_v2.md](CORRECTIONS_v2.md).

## Внешние ссылки (не в ZIP)

Часть ссылок в доках и инструментах пакета указывает на файлы **вне архива**: это пути
рабочего репозитория разработчика, каталог, который создаёт на стенде сам инструмент, и
папка владельца с внешними артефактами карты. Искать их в ZIP не нужно — их там нет.
Правило 12 самопроверки следит, чтобы перечень ниже совпадал с фактическим употреблением
в обе стороны (появилась новая внешняя ссылка — она обязана попасть в таблицу).

| внешний путь | что это | есть ли в ZIP |
|---|---|---|
| `docs/` | материалы репозитория: `docs/ACCEPTANCE_LESSONS.md` §25.10 (первоисточник порядка точки карты) и `docs/evidence/` (сырые логи прогонов) | нет |
| `src/` | исходники прошивки — источник истины для арности команд и профилей (`src/pwm.c`, `src/map_capture_profiles.c`, `src/cli.c`) | нет |
| `scripts/` | сборочный скрипт отправителя: `scripts/build_foc_scan_48cell_pkg.py` | нет |
| `tests/` | регрессия пакета: `tests/test_foc_scan_48cell_pkg.py` | нет |
| `build/` | папка отправителя, куда кладутся ZIP и сайдкар: `build/FOC_SCAN_48CELL_PC3_V2_<дата>.zip` | нет |
| `step0/` | каталог вердикта шага 0, его создаёт сам `TOOLS/check_step0.py` рядом с распакованным пакетом (`step0/result.json`, `step0/step0_report.txt`) | нет (создаётся при работе) |
| `main.c` | файл точки входа прошивки: реестр команд, разбор аргументов | нет |
| `README_BOAR_CAPTURE_PC3.md` | runbook точки захвата карты на стенде (его §3 — тот же порядок, что в `COMMANDS.md`) | нет |
| `мотор анализ\map_upload_pkg_20260908\*.bin` | папка владельца на ПК стенда с внешними артефактами карты от 08.09 (identity `pwm=294`, дефект D3 — не подходят) | нет |

Пакет самодостаточен для шагов 0–2 и самого скана: все команды, ожидания, поля возврата и
адреса выводов расписаны в `COMMANDS.md` и `START_HERE_PC3.md`. Внешние пути — это провенанс
(«откуда взято») и ссылки на первоисточник порядка комиссионинга, а не недостающие файлы.

## Требования

* Python 3.8+ (проверено на `py -3`); для реального прогона — `pyserial` (`pip install pyserial`);
* плата с замороженным образом; перед клетками обязателен baseline-декод (иначе `--n-expected`
  взять неоткуда и драйвер отказывается работать).

## Проверка пакета (обязательно перед стендом)

```bash
py -3 TOOLS/check_package.py
```

Проверяется: состав, покрытие `SHA256SUMS` (без пропусков и лишних строк), отсутствие CRLF/BOM,
контрольные числа шкалы (`f_pwm=5000`, `f_JEOS=5000`, `N_expected(2 с)=10000`), отказ на
подстановке `TCLK` вместо `CLK` (класс ошибки ред. 1), инварианты драйвера
(`--dry-run`: `f` среди команд = 0 и `i=` строго после `1`), атрибуция шага 0
(`@PWM:FULL` — от `pdump`, `p?` не отвечает за `SYS`/`PSC`/`ARR`) и словарь команд
(`eangle` — только как поле `@VFLOG`, энкодер читается командой `enc`). Ожидание — `TOTAL: PASS`.

Правила 8–9 (дефекты B13/B14) проверяют **машинную проверяемость** шага 0:

* `section step 0 machine verdict` — `TOOLS/check_step0.py --selftest` (1 положительный +
  6 негативных случаев) проходит, вход без телеметрии даёт `ERROR` (не `PASS`), и все документы
  шага 0 называют инструмент (иначе вердикт снова «на глаз»);
* `section step 0 field names` — в строке `@PWM:FULL` (её печатает `pdump`) префикс группы стоит
  только у первого поля (`T1:PSC=16`, `T8:PSC=16`): токенов `T1:ARR`/`T1:CR1` в выводе образа нет,
  и доки их не выдумывают, а фиксируют реальную форму `ARR=999`.

Правило 10 (дефекты B16/B17, найденные живым прогоном) проверяет **гейты старта**:
доки обязаны называть `rc=-6` (`params_out_of_range`), `rc=-2` (`map_unverified`), карту
(`map_id`/`map_crc32`) и строгий порядок снятия аппаратного break (`c`, затем `f`) —
иначе оператор снова получит «непонятный ответ» вместо готового диагноза.

Правило 11 (дефект B18) проверяет **путь к карте**: арность `mapload` (ровно 994 hex),
читающий зонд существования команды, профили BOAR-id (`0x424F4152 + …`) и требование
завершённого захвата. Правило 12 (дефект B19) проверяет **внешние ссылки**: доки обязаны
объявлять пути вида `docs/…`/`src/…`/`build/…` как «не в ZIP» (раздел «Внешние ссылки» выше),
причём перечень должен совпадать с фактическим употреблением в обе стороны — иначе получатель
ищет внутри архива файлы, которых там нет.

## Сборка ZIP (для отправителя)

```bash
py -3 scripts/build_foc_scan_48cell_pkg.py                 # manifest + check + ZIP + .sha256
py -3 scripts/build_foc_scan_48cell_pkg.py --verify build/FOC_SCAN_48CELL_PC3_V2_<дата>.zip
```

Сборка fail-closed: если `check_package.py` не PASS, ZIP не создаётся. ZIP детерминирован
(фиксированное время записей, сортировка, forward slashes) — один и тот же вход даёт один и
тот же SHA-256; рядом кладётся `<zip>.sha256` (`sha256sum`-формат), его нужно отправлять вместе
с ZIP.

**Две сборки одной даты не смешивать.** Если пакет правился после того, как архив с этой датой
уже был кому-то передан, имя дополняется (`--name …_r2.zip`, затем `_r3.zip`): одинаковое имя
при разных байтах — ловушка для получателя. Отменённые архивы ред. 2 (одна дата, три разные
байтовые сборки — брать только последний):

| архив | sha256 | что было | статус |
|---|---|---|---|
| `FOC_SCAN_48CELL_PC3_V2_20261004.zip` | `aff4985f…` | до исправления B18 | отменён |
| `FOC_SCAN_48CELL_PC3_V2_20261004_r2.zip` | `5d77b93d…` | исправление B18 | отменён (уступает `_r3`) |
| `FOC_SCAN_48CELL_PC3_V2_20261004_r3.zip` | сайдкар `<zip>.sha256` | исправление B19 (объявление внешних ссылок) | актуальный |

Если `check_package.py` печатает `CRLF FOUND` (рабочее дерево лежит на машине с
`core.autocrlf=true`), сначала лечится байты явным режимом:

```bash
py -3 scripts/build_foc_scan_48cell_pkg.py --normalize --manifest
```

`__pycache__/` и `*.pyc` в пакет не попадают (исключены и в упаковщике, и в `.gitignore`).

## Запуск сессии

Кратко (полностью — `START_HERE_PC3.md`):

```bash
py -3 TOOLS/calc_expected.py --clk 170000000 --psc 16 --arr 999 --cms 3 --rcr 1 --tclk 10000000 --window 2.0
py -3 TOOLS/scan_48cell.py --port COM4 --amp 2000,3000,4000,5000 --angles-el 0 --window 2.0 --n-expected 10000 --out .\run1 --dry-run
py -3 TOOLS/scan_48cell.py --port COM4 --amp 2000,3000,4000,5000 --angles-el 0 --window 2.0 --n-expected 10000 --out .\run1
```

Результат прогона — `cells.csv`, `session_raw.log`, `summary.txt`, `f_list.txt`.
Автостоп при: нет `FOC started` (`rc=-2` — нет карты, `rc=-5` — не energize-сборка,
`rc=-6` — параметры `Rs/Ls` вне окна), нет `@I:OK`, `FAULT`/`FAULT_R != 0`,
`em_stop=0` (линия SD в аварии).
