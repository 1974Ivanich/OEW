# ТЗ: калибровка тракта шунт→ADC инверторов через осциллограф (команда `ci`)

Ветка: `ai2/current-shunt-cal-v1` (от `ai2/vbus-offset-cal-v1` `2444aa4`, принятого ПК-1).

Источник требования — контракт заказчика от 29.09.2026: осциллограф (TAO3104A) даёт
**эталонный аналоговый ток через каждый шунт**, прошивка одновременно логирует
`raw_i1`/`raw_i2`; так калибруется вся цепочка **шунт → усилитель → ADC**, а не только
программное преобразование. Ключевое ограничение контракта: **нельзя считать напряжение
на входе ADC равным напряжению на шунте** — сопоставляется `I_ref = V_shunt / R_shunt`
с `raw`, gain операционного усилителя отдельно не угадывается.

## 1. Физический тракт и модель

```text
I_shunt → Rshunt → V_shunt → op-amp gain/conditioning → ADC pin → raw_i1/raw_i2
```

Единая offline-модель на канал (k = 1, 2):

```text
raw_i(k) = round(offset_k + sign_k * gain_k * I_ref)   — для |I_ref| в рабочем диапазоне
I_meas   = sign_k * (raw_i(k) - offset_k) / gain_k     — обратное преобразование
```

Текущая прошивочная модель (`src/adc.c:75`, `calc_dc_shunt_ma`): номинальная шкала
`(raw − offset) * VREF * 1e6 / (4095 * ADC_DC_SHUNT_UV_PER_A)`, `ADC_DC_SHUNT_UV_PER_A = 63000`
(63 мВ/А на входе ADC после conditioning). Пакет **не меняет** эту модель: сначала
измеряем фактические `offset / sign / gain`, решение о подстановке в прошивку — отдельным
ТЗ по данным калибровки.

## 2. Контракт

```text
осциллограф: CH1 → Inv1, CH2 → Inv2 (щупы на шунтах, земли прибора и платы согласованы)
    → последовательность токовых точек: 0 A, ~0.5 A, ~1 A, ~2 A, ~3 A
    → на каждой точке ОДНО окно: среднее V_shunt по каналу за окно (мВ), среднее raw_i за то же окно, VBUS
    → offline: за окно V_shunt → I_ref = V_shunt_окно / R_shunt; регрессия I_ref от (raw − offset) → offset, sign, gain, R²
    → отчёт + прошивочные коэффициенты mA/raw при решении о подстановке
```

Знак берётся **из фактической полярности V_shunt**, не из предположения о разводке.
Точки тока — только на **контролируемом токе**; zero — только при PWM OFF и отсутствии тока.
На каждой точке фиксируются PWM/CCR-условия; PWM в конкретном режиме включается только
после явного решения по безопасности (первый пакет — шаги 0 A; токовые точки — после
отдельного подтверждения схемы создания тока).

## 3. Firmware: только сбор данных

Команда **`ci`** (`src/cli.c`, свободное имя — конфликтов нет: `c`/`cv`/`ch*`/`iv` заняты):

```text
ci 0  → zero-окно обоих шунтов при PWM OFF, без тока
         → @CI:ZERO:samples=N:raw_i1_avg=…:raw_i2_avg=…:raw_i1_min=…:raw_i1_max=…:raw_i2_min=…:raw_i2_max=…:dt_ms=…:vbus_mv=…
ci 1  → окно сбора данных Inv1 (ADC1, PA0/ADC1_IN1): среднее/мин/макс raw_i1, счётчик сэмплов, VBUS
         → @CI:PT1:samples=N:raw_i1_avg=…:raw_i1_min=…:raw_i1_max=…:dt_ms=…:vbus_mv=…
ci 2  → окно сбора данных Inv2 (ADC2, PA1/ADC2_IN2): то же по raw_i2
         → @CI:PT2:samples=N:raw_i2_avg=…:raw_i2_min=…:raw_i2_max=…:dt_ms=…:vbus_mv=…
ci ?  → текущие offset-и шунтов (видны состояния до/после c): @CI:OFF:offset_i1=…:offset_i2=…
```

Свойства (симметрично принятому VBUS-пакету):

* прошивка **ничего не подгоняет**: `ci` только агрегирует окно и печатает результат;
  коэффициенты считаются offline (`tools/ci_fit.py`);
* гейт: `ci 1`/`ci 2` отклоняются при запущенном PWM/FOC/Vf — как `c`/`cv` (`rc`-легенда в ответе);
* `ci 0` отклоняется при запущенном PWM/FOC/Vf — zero-калибровка только в покое;
* IRQ-пара: сбор под `adc_irq_disable`/`adc_irq_enable`, как у `c`/`cv`;
* измеренный zero **не перепрошивает** `offset_i1/offset_i2` автоматически (поля `c` не трогаются);
  применение результатов калибровки — отдельная команда/ТЗ после offline-анализа;
* форматы `@ADC`, `@ADC:STATUS`, `@ADC:CAL` не изменяются; бюджет телеметрии M-OPT-0 не затрагивается;
* окно сбора: 256 regular-сэмплов (как `ADC_OFFSET_SAMPLES`), два канала не смешиваются
  в одном окне (у них разные ADC и разные окна).

## 4. Offline-инструмент

`tools/ci_fit.py` — принимают CSV строк окон (`channel,point_label,vshunt_mv,raw_avg,vbus_mv`),
считают по каналу: `I_ref = V_shunt_окно / R_shunt`, линейную регрессию `(raw − offset_zero)` от `I_ref`
→ `offset`, `sign`, `gain [raw/A]`, `R²`, при необходимости немонотонность/линейность по точкам.
Выход: человекочитаемый отчёт + строка готовых прошивочных коэффициентов (для будущего ТЗ подстановки).

## 5. Что НЕ входит в пакет

* подстановка измеренных `sign/gain` в `calc_dc_shunt_ma` (и в реконструкцию фазных токов) —
  отдельным ТЗ после первых реальных данных калибровки;
* `Ires` (CT-канал) и замкнутый FOC — не затрагиваются;
* автоматическое определение полярности/фазных соответствий из `ci` — только человек по данным;
* схема создания контролируемого тока на точках 0.5–3 A — отдельно по безопасности.

## 6. Приёмка пакета

1. `make` + `make test-hosted` + QEMU + `cli_test` (включая новые проверки `ci`) — зелёные.
2. Хостед-тест окна сборки: среднее/мин/макс по ровно N сэмплам, гейты PWM, статические окна.
3. CI `build-test` — зелёный.
4. Стенд (после приёмки): 0 A → `ci 0` → подача контролируемого тока → `ci 1`/`ci 2` на точках → CSV → `ci_fit.py` → отчёт (эталон: TAO3104A через шунты).
