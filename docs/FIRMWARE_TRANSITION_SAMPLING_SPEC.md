# Спецификация: firmware transition table + sampling chain (as-implemented)

**Статус:** документ-предусловие для hardware swap-test. Ничего не меняет в коде.
**База:** `origin/main` (см. SHA в конце документа). Источники — только реальный код.
**Назначение:** зафиксировать reference-модель (label → угол → вектор → момент выборки)
до любых аппаратных перестановок, чтобы swap-test проверял известную модель, а не сам себя.

Помечено: **[КОД]** — следует из кода; **[ВЫЧИСЛЕНО]** — арифметика по коду;
**[НЕ ДОКАЗАНО]** — требует измерения на стенде.

---

## 1. Transition table (шесть направлений)

Источник: `src/map_capture_profiles.c:225-230` (immutable allow-list),
TIM8-вектор — циклический сдвиг `(i+1)%3`: `src/map_capture_profiles.c:296-300`.
Соглашение о фазах (проверено по углам, см. §1.1):

```text
(mu, mv, mw) = A · (cos θ, cos(θ−120°), cos(θ+120°)),  A = 9459 Q15 для табличных векторов
```

| label | phase ordering (код) | Q15 (mu,mv,mw) | θ | CCR (MID=500, ARR=999) | TIM8 CCR (сдвиг) |
|---:|---|---|---:|---|---|
| 0 | mu>mv>mw | ( 8192, 0, −8192) | **30°** | 625 / 500 / 375 | 500 / 375 / 625 |
| 1 | mu>mw>mv | ( 8192, −8192, 0) | **330°** (−30°) | 625 / 375 / 500 | 375 / 500 / 625 |
| 2 | mv>mu>mw | ( 0, 8192, −8192) | **90°** | 500 / 625 / 375 | 625 / 375 / 500 |
| 3 | mv>mw>mu | (−8192, 8192, 0) | **150°** | 375 / 625 / 500 | 625 / 500 / 375 |
| 4 | mw>mu>mv | ( 0, −8192, 8192) | **270°** (−90°) | 500 / 375 / 625 | 375 / 625 / 500 |
| 5 | mw>mv>mu | (−8192, 0, 8192) | **210°** (−150°) | 375 / 500 / 625 | 500 / 625 / 375 |

Значения CCR — для `window=0` и `point=0` (формула `board_ccr`: `src/map_capture_profiles.c:266-290`);
TIM8 — тот же вектор со циклическим сдвигом `(i+1)%3` (`:296-300`). Grid-точки добавляют
±4 CCR, window=1 — ±16 CCR по max/min-фазе.

### 1.1 Что это значит для «нестандартных labels»

Labels **не произвольны**: углы выше — точные центры векторов таблицы при стандартном
математическом соглашении (SVPWM-секторы, нечётные кратные 30°). Проверка на реальном
датасете: 12 рядов из 12 дают отклонение **0.00°** от табличных углов
(`tools/verify_boar_geometry_dataset.py`).

**НО** порядок индексов — не порядок вращения: шаги по label
0→1→2→3→4→5 равны **−60°, +120°, +60°, +120°, −60°**. Индекс — ключ по phase ordering,
а не номер сектора вдоль окружности. Любой код/тест/отчёт, который «шагает» по индексу
в ожидании +60° за шаг, неверен by construction. Это и есть настоящий mapping risk,
и он снимается только чтением этой таблицы (см. §7).

## 2. Sector predicate — это НЕ разбиение пространства (количественно)

Предикаты секторов записаны как `mu>0>mv>mw`, `mu>mw>mv`, … —
`src/map_region_certifier.c:36-69`, дублируются в `docs/TZ_MAP_REGION_GEOMETRY_REFACTOR.md` §4.

Сплошной перебор θ (шаг 0.5°) для тройки косинусов даёт:

| sector | θ-область предиката | ширина |
|---:|---|---:|
| 0 | 0.5° … 29.5° | 30° |
| 1 | −59.5° … −0.5° | 60° |
| 2 | 90.5° … 120° | 30° |
| 3 | 120.5° … 179.5° | 60° |
| 4 | −150° … −120.5° | 30° |
| 5 | −120° … −60.5° | 60° |

Перекрытий нет, но покрытие — **74.6 %** окружности. Не покрыто ≈ **91.5°**:
(−180°,−150°), (30°, 90°), 179.5°…180°. Т.е. часть углового пространства не принадлежит
**ни одному** сектору; при этом часть предикатов вдвое уже других.

Следствие: labels точны для шести табличных векторов, но **не задают partition** на
(mu,mv,mw). Certifier в geometry-режиме строит axis-aligned прямоугольники по этим
комментариям, а не семантический предикат. До появления общего классификатора
(TZ §6 Phase 2) или таблицы boundary ownership (TZ §4) вывод «PWM SIX-DIRECTION GEOMETRY
SUPPORTED» корректен только для дискретных 32-точечных кластеров кампании.

## 3. Семантика «window» — двойная, и в датасете неразличимая

1. **Окно как амплитудная полоса.** `window=1` сдвигает кластер на +16 CCR по max-фазе и
   −16 по min-фазе (`MAP_CAPTURE_BOARD_WINDOW_SHIFT`, `src/map_capture_profiles.c:251-262`),
   сумма mu+mv+mw сохраняется. Пороги в `src/map_region_certifier.c:6-9`.
2. **Окно как поле кадра ADC.** `frame.sample_window` — **копия объявленного** значения
   (`ADC_SetExpectedWindow`, `src/adc.c:335-341` → `src/adc.c:123, 392, 547`), а не измеренная
   величина. Кадр не может доказать, в каком окне он снят: он повторяет то, что ему сказали.

Числовой факт по датасету: при замороженных порогах TZ (W0 = 6000…9999, W1 = 10000…14000,
`docs/TZ_MAP_REGION_GEOMETRY_REFACTOR.md` §3) **все 12 рядов** попадают в **window 0**
(mod 7930…9503) — два окна кампании по этой метрике неразличимы. Именно поэтому появился
документ «adjusted zones»; по TZ §3/§5 правильное действие — **rebuild кампании**, а не
переопределение порогов (смена порога = новая qualification revision + recertification).

## 4. Sampling chain (конфигурация, [КОД])

```text
TIM1 (master)   PSC=16, ARR=999, CMS=3 (center-aligned), ARPE, RCR=1,
                CR2.MMS=2 → TRGO = update event (UEV)
   ├─ carrier = 10 MHz / (2·1000) = 5 000 Гц              ← FOC_PWM_FREQ=5000, src/pwm.c:13
   └─ ADC injected: JEXTSEL=0 (TIM1_TRGO), JEXTEN=rising  ← src/adc.c:4-5, 175-183
TIM8 (slave)    те же PSC/ARR/CR1, SMCR=4 → reset от ITR0 (TIM1_TRGO)
```

* PSC/ARR выводятся как `psc_plus1 = tck/10 MHz = 17`, `timer_clk = 10 MHz`,
  `arr_plus1 = (timer_clk + F)/(2F)` → ARR=999 (`src/pwm.c:242-267`).
* ADC clock: CKMODE=11 → HCLK/4 = **42.5 МГц** (`src/adc.c:226-228`).
* Кадры: ADC1 — 1 ранг (SHUNT1); ADC2 — 3 ранга (SHUNT2, CT, VBUS) (`src/adc.c:284-285`);
  dual injected simultaneous, ADC1 — master (`src/adc.c:287-290`);
  **commit-событие кадра = JEOS ADC2** (`src/adc.c:294-297`).
* Sample time: SMPR=111 → 640.5 циклов (`src/adc.c:162-173`, комментарий 239-245).
  **[ВЫЧИСЛЕНО]** 640.5 + 12.5 = 653 цикла/канал = **15.36 мкс**;
  последовательность ADC2 (3 ранга) = **46.09 мкс**.
* Полупериод center-aligned при 5 кГц = **100 мкс** → окно конверсии занимает ~46 % полупериода.
  На малых активных векторах окно может накрыть переключение → искажение SHUNT/CT/VBUS
  (в V/f-треке это уже давало ложные VBUS_LOW).
* Dead-time 1500 нс → `dtg8 = 0xC0 = 192` (`src/pwm.c:14`).
* **Trigger offset НЕ задан:** `trigger_offset_ticks = 0` (`src/map_capture_port.c:218, 288`).
  Ноль здесь означает «не измерено / scope-qualified stage не пройден», а не подтверждённую
  синхронизацию. **[НЕ ДОКАЗАНО]**: в какой именно точке UEV (пик ARR или впадина 0) срабатывает
  JEXTSEL=0 и где эта точка относительно фронтов PWM. Сверка JEXTSEL=0 с RM0440 —
  отдельный пункт (в коде это assertion, не цитата из RM).

## 5. Identity contract

Сравниваются 11 полей (`src/current_map_selector.c:72-87`):
`board_revision, pwm_frequency_hz, timer_arr, adc_trigger_id, trigger_offset_ticks,
deadtime_ticks, adc_clock_hz, adc_sample_cycles_x2, adc_resolution,
adc_config_signature, current_calibration_signature`.

Известные дефекты, попадающие в artifact:

| поле | фактически | в identity | причина |
|---|---|---|---|
| `pwm_frequency_hz` | 5 000 Гц | **294** | `cap_pwm_frequency_hz` делит на (PSC+1) второй раз (`src/map_capture_port.c:109-121` + `src/pwm.c:612-616`); дефект признан в комментарии `:191-197` |
| `trigger_offset_ticks` | неизвестен | **0** | этап timing не пройден (`src/map_capture_port.c:218, 288`) |

Оба поля — часть gate, поэтому «исправить» их можно только новой identity revision.

## 6. Сводка: доказано / не доказано

**Доказано (код + числовая проверка):** таблица переходов и углы; 5 кГц; ADC 42.5 МГц;
rank-структура и commit по JEOS; длительность окна 15.36/46.09 мкс; состав identity-полей;
совпадение датасета с таблицей по углам (0.00°).

**Не доказано:** физическая привязка u/v/w к фазам стенда; реальный момент триггера и его
положение относительно фронтов; попадает ли 46-мкс окно в интервал нулевого вектора;
знак и масштаб шунтов; что `ref`-каналы привязаны к физическим фазам, а не синтезированы (§см. отчёт по датасету).

## 7. Минимальный план доказательства (перед `PHYSICAL MAPPING PASS`)

1. **Непрерывный захват:** несколько полных циклов, seq без структурных пропусков
   (в текущем датасете их 3×2 на ряд — фильтр/сеттлинг, а не физика), cycle closure.
2. **Timing:** осциллограф/ЛА — фронт PWM ↔ маркер ADC (JEOS/GPIO) ↔ окно; записать `toff`
   в тиках от UEV и его разброс; вписать в identity (новая revision).
3. **Независимая привязка фаз:** внешний токовый пробник или контролируемый известный ток
   по фазам; проверить знак и масштаб против ADC.
4. **Baseline:** зафиксировать wiring/polarity/gain/offset до любых перестановок.
5. **Controlled ADC swap:** переставить два ADC-канала; ожидаемый сдвиг углов ±120°
   относительно §1; всё остальное должно остаться неизменным.

`PHYSICAL MAPPING PASS` ставится только если: измеренный `toff` воспроизводим, знак/масштаб
сходятся в пределах квалификации, после swap углы сдвигаются ровно на ±120°, и KCL
подтверждён **независимыми** измерениями (не синтезом refw = −(refu+refv)).

## 8. Блокирующие условия

* swap-test не начинать до фиксации §1–§4 относительно конкретного commit SHA;
* не выпускать firmware-loadable artifact с `use_geometry=1` (TZ §5);
* не менять amplitude thresholds без новой qualification revision (TZ §3);
* не использовать «adjustment порогов под существующие данные» как доказательство геометрии.
