## 1. Что изменено

`tools/map_scope_ingest.py`:

1. `:84` — базис разложен на две явные таблицы и одну выведенную:
   * `BOAR_MOD_INV1_Q15` — абсолютный вектор, поданный на inv1 (измеренный паттерн);
   * `BOAR_MOD_Q15` — **физический** вектор сектора `inv1 − inv8`, углы
     60/0/120/180/−60/−120°, немонотонная привязка ярлыков сохранена
     (`0→60°, 1→0°, 2→120°, 3→180°, 4→−60°, 5→−120°`);
   * `BOAR_MOD_INV8_Q15` — **выведен** как `inv1 − физический` (отдельных констант нет);
   * `BOAR_SECTOR_ANGLE_DEG` — физические углы (для гейта/отчётов).
2. `:117` — `expected_ccr()` теперь физическая модель (`inv1 − inv8`, в записи это
   `ccr1 − ccr8`); добавлены `expected_inv1_ccr()` / `expected_inv8_ccr()`.
   Окно 1 сдвигает собственный max/min **каждого** паттерна (±16 CCR), grid-смещение
   точки для inv8 повёрнуто на одну фазу — это сверено со всеми 48 реальными логами.
3. `check_evidence()` — проверка записи опирается на физическую модель: сверяется
   **пара** (`ccr1` = inv1, `ccr8` = inv8) и её разность. Сообщение содержит `ccr`
   (fail-closed семантика и негативные тесты сохранены).
4. Экспорт сэмпла (`samples.jsonl`, `ccr1..ccr3`) — в датасет уходит **физический**
   вектор. Это третья точка того же дефекта (в §2 не перечислена), без неё карта
   осталась бы в базисе inv1: `map_bench_dataset.convert_campaign()` пишет
   `cell mu/mv/mw` именно из `ccr1/2/3`, а `map_artifact_pipeline_cli` ставит по ним
   ячейки ⇒ центры остались бы на 30/90/150.
5. `manifest.startup.mu/mv/mw` — выводится из `BOAR_MOD_Q15[0]` (физический стартовый
   вектор), иначе стартовая точка оказалась бы вне исправленного региона 0/0.

Тесты: новый `tests/test_map_basis_fix.py` (гейт), фикстуры
`tests/test_map_scope_ingest.py` приведены к реальному формату записи (пара inv1/inv8,
`make_rec_line(..., ccr8=...)`), добавлен тест «в samples уходит физический вектор».

## 3. Находка входа в фазу 2 (не сделана — требует приёмки §3)

Replay `--pipeline` на тех же 384 записях встал **fail-closed**:

```text
map_artifact_pipeline_cli: pipeline failed (status 4, row 0/0)
```

`status 4` = `MAP_PIPELINE_CERT_FAILED` (`tools/map_artifact_pipeline.h`), `row 0/0` =
sector 0 / window 0, т.е. отказ сертификатора.

**Метрика границ установлена по источнику** (`src/map_region_certifier.c`,
`geometry_bounds_for_sector_window()`): это **пофазные Q15-боксы**, а не радиус Кларка —
`switch (sector)`: для sector 0 `mu ∈ [mod_min, mod_max]`, `mv ∈ [−mod_max, −1]`,
`mw ∈ [−mod_max, −mod_min]`; умолчания `6000/10000/10000/14000`.
Проверка `inside()` идёт по клеткам (`cells[i].mu/mv/mw`), значит в физическом базисе
сектор 0 = `(8192, 8192, −16384)`: `mv = +8192` вне `[−10000, −1]` ⇒
`MAP_CERT_VALID_OUTSIDE`. Числа `6000/10000` калиброваны в базисе inv1 (там у сектора
была одна положительная фаза и две отрицательные).

Вывод для фазы 2: **не переносить** `6000/10000` и не считать их радиусом — пересчитать
пофазные границы окна под физические вектора (окно 0: `(8192, 8192, −16384)`,
окно 1: `(9241, 9241, −18482)`), с явным обоснованием в diff фазы 3.
Плюс известная ловушка §3: каталог `<out>/../work/pipeline` создавать заранее.
