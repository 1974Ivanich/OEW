# ТЗ: калибровка аддитивного смещения канала VBUS

Ветка: `ai2/vbus-offset-cal-v1` (от `origin/main` `103c17b`). База для правок:
исходники `src/adc.{c,h}`, `src/cli.{c,h}`, `main.c`, `Makefile`, `tests/`.

Источник требования — контракт заказчика от 28.09.2026 (порядок работ: сначала VBUS,
потому что он затрагивает semantics protection/no-HV и влияет на интерпретацию всех
последующих V/f-измерений).

## 1. Объект и обоснование

Канал VBUS (PC4 / ADC2_IN5, делитель 1:125) имеет **аддитивное смещение** порядка
20…23 отсчёта (~2.2 В), которое прошивка не вычитает:

* `src/adc.c:85` (до правки) — `mV = raw * VREF * DIVIDER / MAX_CODE`, без смещения;
* двухточечная проверка на стенде (28.09.2026): 0 В (DMM) → 20…23 отсч;
  40.0 В (БП) → 412…422 отсч; gain = 40000 / (419 − 22) = 100.76 мВ/отсч при
  номинале 100.7 (+0.06 %), делитель 1:125.03 при номинале 1:125.
* следствие: все абсолютные напряжения читаются на +2.2 В выше, а порог
  `PROTECT_VBUS_MIN_MV = 8000` сравнивается с уже преобразованным `vbus_mv`
  (`src/protect.c:84`, `:186`), то есть срабатывает при raw ≈ 79, что физически
  ~5.8 В вместо номинальных 8.0 В.

## 2. Контракт (что требуется)

```text
0 V на входе
    -> измерить raw-смещение канала VBUS
    -> mV = (raw - offset) * номинальная шкала
    -> перепроверить PROTECT_VBUS_MIN_MV, PROTECT_VBUS_MAX_MV, гейт no-HV
    -> физическая проверка при известном VBUS
```

`raw < offset` решается контрактом явно: **знаковое промежуточное + насыщение снизу в 0**
(unsigned underflow недопустим).

## 3. Реализованные решения

| решение | почему так |
|---|---|
| новое статическое `offset_vbus` + флаг валидности | калибровка токов (`c`) идёт при поданном звене, поэтому смещение VBUS измеряется отдельно |
| отдельная команда `cv` (не расширение `c`) | разные условия: `c` требует нулевого тока, `cv` — нулевого напряжения; смешивать нельзя |
| `cv` отказывается (`rc = -2`), если max raw > `ADC_VBUS_OFFSET_MAX_RAW` (40 отсч ≈ 4 В) | fail-closed: при поданном звене калибровка не «зашьёт» реальное напряжение в смещение; ранее измеренное значение при отказе не изменяется |
| `cv` отказывается при запущенном PWM (как `c`) | калибровка только в покое |
| пока смещение не измерено — преобразование идёт с `offset = 0` | поведение бит-в-бит совпадает с прежним; protection остаётся работоспособным до калибровки |
| насыщение снизу в 0 | ниже смещения физический ноль; отрицательное напряжение смысла не имеет |
| единая точка преобразования `ADC_VbusMvFromRaw(raw, offset)` | одного места достаточно для всех путей: injected-кадр, `ADC_StartConversion`, `ADC_ServiceReadVbus`, `ADC_ReadVbusRegularMv` |
| **смещение VBUS не входит в `adc_config_signature` / `current_calibration_signature`** | эти сигнатуры — часть identity карты (`CurrentMapSelector`); смещение VBUS к реконструкции токов не относится, а любое изменение сигнатуры обнулило бы действующую карту |
| формат `@ADC` / `@ADC:STATUS` / `@ADC:CAL` не изменён | бюджет телеметрии (`TZ_MOPT0_TELEMETRY_BUDGET.md`) и существующие проверки не трогаются; значение смещения видно в ответе самой команды |

## 4. CLI-контракт

```text
cv
  -> @ADC:CV:OK:offset_vbus=<raw> (raw at 0 V)
  -> @ADC:CV:FAIL:rc=<0|-1|-2>
       0  = OK
      -1  = ADC занят/не сошёлся (как у c)
      -2  = вход не на нуле (max raw > ADC_VBUS_OFFSET_MAX_RAW)
```

Порядок работы со стендом:

```text
звено обесточено (0 В, подтверждено прибором)
    -> cv
    -> @ADC:CV:OK:offset_vbus=NN
    -> подать известное напряжение (например БП 40.0 В)
    -> @ADC (raw) и @FOC:VBUS (мВ) должны дать ~40.0 В
```

## 5. Что проверяет пакет

* `tests/adc_vbus_scale_test.c` (hosted, парный к `ADC_VbusMvFromRaw`):
  тождественность прежней формуле при `offset = 0`; вычитание измеренного смещения
  22 отсч; ноль при `raw <= offset` (без underflow); монотонность; состояние
  «до калибровки» (getter 0, флаг снят).
* `make` + `make test` (hosted/QEMU/py) — полный прогон.
* CI `build-test` — обязателен.

## 6. Что пакет НЕ делает

* не меняет пороги `PROTECT_VBUS_MIN_MV` / `PROTECT_VBUS_MAX_MV` (только делает их
  значение тем, что записано: 8.0 В вместо фактических ~5.8 В);
* не меняет формат периодической телеметрии и бюджет;
* не трогает карту, `region_contains`, map selector, `margin`, V/f и FOC;
* не меняет `src/protect.c` вообще: сравнение идёт по `vbus_mv`, который теперь
  приведён к реальному напряжению.

## 7. Что остаётся за пакетом (отдельными шагами)

1. **Гейт no-HV** (host-инструменты стенда): критерий становится
   `median(raw − offset) ≤ 9` вместо `median(raw) ≤ 9`. В сырых отсчётах при
   смещении 22 он недостижим в принципе — это и было зафиксировано как находка.
2. **Физическая проверка** на стенде (ПК-3) при известном VBUS: 0 В → `cv`,
   затем 40.0 В → `@ADC`/`@FOC:VBUS` ≈ 40.0 В, и контроль `f` (сброс fault) при
   реальном напряжении звена.
3. Пересборка commissioning-образа после приёмки и повторная проверка identity
   карты (`adc_config_signature` / `current_calibration_signature` обязаны совпасть
   с текущими: 0x26B9B97B / 0x13552B12).
