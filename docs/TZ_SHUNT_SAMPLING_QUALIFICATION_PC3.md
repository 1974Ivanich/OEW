# ТЗ: квалификация ADC sampling window для closed-loop FOC (Уровень 2, аппаратная синхронизация)

Ветка-основа: `ai2/shunt-cal-campaign-v1`. Статус: РЕАЛИЗОВАНО (v2 спеки после
приёмки архитектуры заказчиком; реализация в этой же ветке).
Родитель: `TZ_SHUNT_CAL_CAMPAIGN_PC3.md` (Уровень 1 — mean/RMS калибровка без
синхронизации; окно усреднения >> PWM-периода делает фазовое несовпадение
несущественным). Этот документ — следующий, более узкий gate: квалификация
**timing** выборки ADC.

## 2. Решение: синхронизация через один экран прибора

Вместо попытки завести TRGO на отсутствующий EXT TRIG:

```text
один SCREEN-кадр TAO3104A, 4 канала:
  CH1 → шунт Inv1        CH2 → шунт Inv2
  CH3 → PA5 (ADC JEOS)   CH4 → PA4 (TIM1 TRGO/UIF)
```

Прибор сэмплирует все 4 канала в один и тот же момент (одна апертура SCREEN) →
временная привязка шунт-тока к моменту выборки ADC получается **самим кадром**,
без программных timestamp и без проводов синхронизации. Период PWM =
расстояние между фронтами CH4; момент выборки = фронт CH5..CH3 (toggle PA5
привязан к JEOS); offset маркеров (длина ISR-хвоста) фиксируется константой
и калибруется один раз.

Условие применимости: timebase прибора должен покрывать ≥3-5 PWM-периодов
с достаточным разрешением ripple (при 5 кГц: 500-1000 мкс/дел на 1520 точек
→ 3.3-6.6 мкс/точка — ripple на 200-мкс периоде разрешён).

## 4. Инструмент (`tools/sampling_qual.py`, stdlib-only + lazy pyusb)

Режим `capture`: readback-гейт расширяется условием **CH3/CH4 DISPLAY=ON**
(те же шаги, что в `shunt_cal_campaign.run_capability_gate`, + 2 канала);
захват: HEAD + CH1..CH4 в один кадр, N кадров (default 32) для repeatability.
Режим `analyze` (offline, stdlib):

1. период PWM: фронт-фронт CH4 (toggle, 2 фронта/период), `f_pwm`, разброс;
2. момент выборки: восходящий фронт CH3 → привязка к фазе PWM-периода
   (`t_sample_in_period`, статистика по N кадрам — джиттер выборки);
3. ток в точке выборки: CH1/CH2, интерполяция к моменту фронта CH3;
4. ripple: pp/rms CH1/CH2 внутри одного PWM-периода, доля ripple/средний ток;
5. repeatability: разброс `t_sample_in_period` и межкадрового мгновенного тока;
6. сверка с прошивкой: `ci`-окно/`@ADC` значение vs мгновенный ток в точке
   выборки vs средний ток — заключение, что именно измеряет ADC
   (мгновенное/среднее/смещённое по фазе);
7. вердикт: `SAMPLING_QUALIFIED` / `SAMPLING_SUSPECT` (джиттер/фазовый сдвиг/
   ripple-зависимость за пределами порогов; пороги — параметры CLI, не константы).

Артефакты: CSV всех 4 каналов каждого кадра + отчёт с provenance
(IDN, firmware_sha256, f_pwm, N) — формат и принципы provenance наследуются
от `shunt_cal_campaign`.

## 5. Границы и формулировка результата (v2, после приёмки заказчиком)

* Результат — временнАя привязка **«ADC event → ISR marker»**: PA5 — ISR-маркер
  ПОСЛЕ аппаратного JEOS, с измеренным/зафиксированным хвостом ISR как константой
  сборки. НЕ искусственная субмикросекундная точность момента выборки.
* **Никакой подгонки фазы**: геометрия следует ТОЛЬКО из PA4/PA5/waveform
  (пороги вердикта — параметры CLI; результат не «улучшается» настройкой).
* **A/B-разделение утверждений** (закреплено в отчёте инструментом):
  - **A. Timing qualification**: событие выборки ADC стабильно в ожидаемой части
    PWM-периода, джиттер (внутрикадровый + межкадровый дрейф фазы) в порогах.
    Это доказывает данный 4-канальный capture — вердикт SAMPLING_QUALIFIED/SUSPECT.
  - **B. Current reconstruction qualification**: пригодность single-shunt
    измерения для используемого FOC reconstruction/map — требует ещё
    sample timing + PWM state/sector/window + фактический shunt current.
    Инструмент фиксирует `current_reconstruction.claim = NOT_CLAIMED` —
    Level 2 НЕ превращается автоматически в «FOC current reconstruction
    qualified» (урок qualification map: валидность апертуры ≠ пригодность карты).
* Измеряется **аппаратная** цепочка TIM→ADC→ISR-маркер; абсолютная привязка —
  с точностью одного SCREEN-сэмпла (µs).
* Для квалификации нужен статичный/медленный режим тока (точки уровня 1);
  роторная динамика — отдельный вопрос.
* FOC при bench-aperture-образе остаётся default-deny: маркеры — наблюдение
  ISR-событий, не силовой выход.
