## 1. Корневая причина (уточняет вывод фазы 1)

Фаза 1 экспортировала в `samples.jsonl` **«сырую» разность** Δ = `ccr1 − ccr8` в поля
`ccr1/ccr2/ccr3`. Конвертер (`tools/map_bench_dataset.py`) и конвейер
(`MapMeasurement_CcrToQ15`) читают эти поля как **абсолютный CCR**:

```text
q15 = (ccr − mid) · 32768 / mid,   mid = (ARR + 1) // 2 = 500 при ARR = 999
```

Для фаз без смещения Δ = −250 → `q15 = −49152` → сатурация `INT16_MIN` (наблюдалось
`mw=[-32768..-32768]`) ⇒ разброс строки `0 < 2·guard_q15` ⇒ `MAP_CERT_DEGENERATE`
(сертификатор вернул **cert = 6 на всех 12 строках**, `status 4` = `MAP_PIPELINE_CERT_FAILED`,
row 0/0 — вход в фазу 2). Диагностическая сборка того прогона:
`DIAG regionq min_valid=4 guard=1 min_margin=110 use_geom=0` + 12× `cert=6`.

**Уточнение к §3 фазы 1:** пофазные границы `6000/10000` (w0) / `10000/14000` (w1) **не были
причиной** отказа: они принадлежат geometry-пути (`geometry_bounds_for_sector_window()`), а
кампания BOAR v2 идёт статистическим путём — `DIAG: use_geom=0`. Поэтому пороги сертификации
**не менялись и не переносились**; в `src/map_region_certifier.c` добавлен только
комментарий-семантика (пофазное окно модуляции, не радиус Кларка; знаковая структура
физического базиса — две фазы одного знака, агрегатная отрицательная = `−(mu+mv)`), чтобы
числа не были перенесены «попутно» при включении geometry-пути.

Ключевые наблюдения:

1. **recon (`m00/m01/m10/m11`, `phase_a/b`, `valid`) — 12/12 без изменений**: правка касается
   только базиса/фрейма **сетки** (регионов) и стартовой точки; матрицы реконструкции
   по-прежнему выводятся из измеренных токов `idc1/idc2` того же датасета кампании — физика не
   «переподгонялась».
2. У baseline у каждого сектора **одна положительная фаза** (интервал `±262` вокруг нуля) —
   это базис одного инвертора. У исправленного — **две фазы одного знака** и агрегатная фаза
   `≈ 2A` (открытые обмотки, `inv1 − inv8`), т.е. та же знаковая структура, что у `BOAR_MOD_Q15`
   и стартового вектора.
3. Все 12 регионов `valid=1`, `min_margin_ticks=110` (= VfcApertureContract), `cert=0`;
   overlap-контроль пройден (иначе `CurrentMap_LoadMeasured` отверг бы артефакт и CLI вернул бы
   ошибку) — 66 пар регионов попарно непересекаются, стартовая точка внутри своего региона.
4. Бокс региона = hull клеток строки, сжатый на `guard_q15 = 1` LSB с каждой стороны
   (клетки `mu ∈ [7930..8716]`, бокс `[7931..8715]`) — поведение записи не менялось.

## 6. Не сделано / открытые вопросы

1. **Geometry-путь** (`geometry_bounds_for_sector_window`, `6000/10000`) не менялся: он
   дормантен (`use_geom=0` на собранной кампании). Если его включат, числа обязаны быть
   выведены отдельным ТЗ под физическую амплитуду (окно 0 `(8192, 8192, −16384)`,
   окно 1 `(9241, 9241, −18482)`); сейчас в `src/map_region_certifier.c` зафиксирована
   семантика метрики и явный запрет переноса старых чисел.
2. **`tool_build_id` повышен** `0x20260902 → 0x20260930` (формально §3 этого не требует, но
   иначе provenance лжёт о сборке инструмента). Если приёмщик сочтёт это лишним — откат
   локален (2 строки в `tools/map_scope_ingest.py`), артефакт изменится только в этом поле.
3. Ловушка §3 (`<out>\..\work\pipeline`) исправлений инструмента не получила: каталог по-прежнему
   создаёт вызывающий (в отчёте — явная инструкция), т.к. §3 называет это ловушкой приёмки, а не
   дефектом инструмента.
4. Multi-ARR: `mid` берётся из `rec["arr"]` каждой записи, поэтому фрейм корректен и при
   `ARR ≠ 999` (в кампании BOAR ARR = 999 везде).
