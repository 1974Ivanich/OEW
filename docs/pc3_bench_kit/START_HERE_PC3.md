## Первые команды сессии (сделать до всего остального)

```bat
chcp 65001
set PYTHONIOENCODING=utf-8
cd /d <корень этого комплекта>      :: буква носителя не важна: все пути в инструкциях относительные
```

Все команды в документах комплекта записаны **относительно корня комплекта**
(`TOOLS\..`, `SESSION_1_SIGN_BREAK\..`). Абсолютных путей с буквой диска в инструкциях нет
намеренно: на ПК-2 и ПК-3 носитель может быть разной буквой (`E:`, `F:`, `I:`), и это уже
приводило к ошибкам в v1. Проверка этого правила автоматическая.

## Правило сессии (главное)

> **Не исправлять обнаруженное до измерения.**

Порядок жёсткий: **измерение → гипотеза → подтверждение → отдельное fix-ТЗ**. Никаких правок прошивки,
параметров V/f (`vmag`/`fslip`/boost) и порогов защиты посреди физического эксперимента — даже если
аномалия выглядит очевидной и «чинится» одной строкой.

## Порядок работ

```text
Сессия 1 (этот комплект): SESSION_1_SIGN_BREAK/
    шаг 0  безопасное состояние: p? / dump / dump8 / pdump / breakdiag (+reset)
    шаг 1  БЕЗ питания: enc + вал рукой            → конвенция энкодера
    шаг 2  обесточить, поменять 2 моторных провода,
           короткий vf=50                          → фазы или энкодер?
    шаг 3  один силовой прогон: CH1−CH2 + триггер по спаду SD + 15 В рейл,
           dump/pdump ДО и ПОСЛЕ, breakdiag в файл → break + A3/A4
        ↓
    возврат по SESSION_1_SIGN_BREAK/RETURN_TEMPLATE.md
        ↓
    решение приёмки (ПК-2): что именно дефект → fix-ТЗ, или VF-2A закрыт
        ↓
Сессия 2 (только после этого): SESSION_2_VF2_VF3/
    VF-2B (vf=40) → VF-3 (40/100/200/300 → обязательно vf=0 → проверить PWM закрыт)
```

**В сессию 1 не запускать:** VF-2B/VF-3, `c`, `ch`, `iv`. `c`/`ch`/`iv` на этом образе недостижимы
fail-closed (`@AT:ERROR:POWER_BLOCKED`), а семантика `iv` не установлена — интерпретировать нечем.

## Как проверить комплект (2 команды, PowerShell)

```powershell
Set-Location <корень этого комплекта>
Get-Content SHA256SUMS | ForEach-Object { $p = $_ -split ' \*'; if ((Get-FileHash $p[1] -Algorithm SHA256).Hash.ToLower() -ne $p[0]) { "РАСХОЖДЕНИЕ $($p[1])" } }; "проверка манифеста завершена"
```

Ожидаемо: печатается только «проверка манифеста завершена». Любая строка «РАСХОЖДЕНИЕ …» —
комплект повреждён при копировании: сообщить на ПК-2 и по такому комплекту не работать.


## Аборт немедленно

`fault≠0` · `sd1/sd2≠1` · VBUS < 8 В (по осциллографу/БП, **не** по колонке лога) · шум/вибрация/нагрев ·
непрерывный `commit=0` · на SD импульс **без** предшествующего роста тока (значит UVLO драйвера или помеха).

## Минимальный набор команд сессии 1

| Шаг | Команда | Ожидаемый ответ |
|---|---|---|
0 | `p?` | `@PWM:CR1=…:CCER=0:BDTR=…:CNT=…`, `CCER=0`, MOE=0 |
0 | `dump` / `dump8` | hex `BDTR` каждого таймера (сохранить в файл) |
0 | `breakdiag` | `@BRK:valid=0` либо `valid=1` (тогда сохранить и `breakdiag reset`) |
1 | `enc` (×5, покой; затем при вращении рукой) | `@ENC:angle=…:speed=…:period_us=…:pulse_us=…:err=0` |
2 | `vf=50` до/после перестановки двух моторных проводов | знак `meas`/`eangle` в `@VFLOG` |
3 | `vfk=15,50`, `vflog=40`, `vf=50` | `@VFLOG` 25 Гц + осциллограф; после события `breakdiag` в файл |

Команды платы подаются через захватчик из комплекта:
`py -3 TOOLS\vf_raw.py COM4 <команда> [секунды]` (вывод сохранять в файл: `> dump_before.txt`).
Подробности и разбор ответов — `SESSION_1_SIGN_BREAK/TOOLS/HOWTO.md`.
