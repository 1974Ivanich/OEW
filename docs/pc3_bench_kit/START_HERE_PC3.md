**Что нового в v3 (по возврату сессии 1 от 26.09.2026):**

1. **`c` обязателен** после каждой перезагрузки/обесточивания и до первого `vf=` (в v2 он был
   ошибочно назван недопустимым — оператор вынужденно отклонился от протокола). Без `c`: `rc=-7`,
   затем мёртвый CLI-цикл и только SWD-reset.
2. Гейт перед `vf=` обязан проверять **`VBUS ≥ 400`** (0.1 В = 40 В) — иначе «пустой» прогон
   проходит гейт и даёт мусорный вердикт сторожа.
3. Захват evidence — через `cmd /c "… > файл"`: PowerShell `>` пишет UTF-16 и ломает разбор.
4. `breakdiag_parse.py`: таблицы бит BDTR/SR/CCER — из CMSIS-заголовка (ложное «противоречие» на
   штатном `0x1CC0` устранено), код возврата учитывает отсутствие обязательных битов, самотест
   проверяет реальные состояния платы.
5. `vf_raw.py` принимает многословные команды (`breakdiag reset` без кавычек); `audit_vf2a.py`
   разворачивает 14-битный угол и не падает на строках без полей.
6. Гейт VF-2A/2B: оговорка рампы (за 5 с рампа доходит ~до 90 %, период сверять с текущим
   значением) и требование мерить дифференциал на **5 В/дел** (при 25 В/дел 12 В ≈ 0.48 деления).
7. `CONTEXT/FINDINGS_SESSION1_SIGN_BREAK_20260926.md` — вердикт сессии 1 (знак: инвертирован
   порядок фаз; break не воспроизведён) и связь `FAULT_R=18` с известным ложным FAULT_N
   STEVAL-2 (SD2/PD2).

**Что нового в v4 (по решениям от 27.09.2026):**

1. **Два образа вместо одного** и профили в инструментах: `breakdiag_parse.py` знает, что для
   диагностического образа `BKE=0` — норма, а не противоречие (иначе инструмент обвинял бы
   намеренную конфигурацию). Провенанс каждого образа — `IMAGE/PROVENANCE_<профиль>.txt`.
2. **Сессия 3 «A/B по знаку»** (`SESSION_3_SIGN_AB/`): знак измеряется повторяемым A/B (2 прогона на
   конфигурацию) + осциллограф на 5 В/дел с совмещёнными нулями. Обоснование и ловушки —
   `CONTEXT/DESIGN_SIGN_AB_20260927.md`.
3. **Сессия 4 «характеризация SD/FAULT_N»** (`SESSION_4_FAULTN_CHARACTERIZATION/`): на
   диагностическом образе низкий SD больше не останавливает привод и не латчит `FAULT_R`, поэтому
   событие можно наблюдать и классифицировать. Доказательство по коду (где латчится, что осталось
   защищено, разрешающая способность 25 Гц) — `CONTEXT/DESIGN_FAULTN_CHARACTERIZATION_20260927.md`.
4. Новые инструменты: `sign_ab_report.py` (вердикт A/B по знаку, код 0/3/4) и `faultn_report.py`
   (события SD, амплитуды по ВАЛИДНЫМ кадрам, классификация; код 0/3/4). Оба прошли самотесты и
   проверены на реальном возврате сессии 1.
5. **Невалидный кадр больше не портит выводы.** Кадр, у которого `i1=i2=ires=vbus=0` одновременно,
   исключается из оценок: на возврате сессии 1 такой кадр давал ложный «размах 26 А» при реальной
   амплитуде 1.2 А.
6. `CONTEXT/DESIGN_*_20260927.md` — обоснования обеих сессий (что докажет, что нет, чем платим).

## Первые команды сессии (сделать до всего остального)

```bat
chcp 65001
set PYTHONIOENCODING=utf-8
cd /d <корень этого комплекта>      :: буква носителя не важна: все пути в инструкциях относительные
```

Все команды в документах комплекта записаны **относительно корня комплекта**
(`TOOLS\..`, `SESSION_1_SIGN_BREAK\..`). Абсолютных путей с буквой диска в инструкциях нет
намеренно: на ПК-2 и ПК-3 носитель может быть разной буквой (`E:`, `F:`, `I:`), и это уже
приводило к ошибкам в v1. Проверка этого правила автоматическая.

## Правило сессии (главное)

> **Не исправлять обнаруженное до измерения.**

Порядок жёсткий: **измерение → гипотеза → подтверждение → отдельное fix-ТЗ**. Никаких правок прошивки,
параметров V/f (`vmag`/`fslip`/boost) и порогов защиты посреди физического эксперимента — даже если
аномалия выглядит очевидной и «чинится» одной строкой.

## Порядок работ

```text
Сессия 1 (этот комплект): SESSION_1_SIGN_BREAK/
    шаг 0  безопасное состояние: p? / dump / dump8 / pdump / breakdiag (+reset)
    шаг 1  БЕЗ питания: enc + вал рукой            → конвенция энкодера
    шаг 2  обесточить, поменять 2 моторных провода,
           короткий vf=50                          → фазы или энкодер?
    шаг 3  один силовой прогон: CH1−CH2 + триггер по спаду SD + 15 В рейл,
           dump/pdump ДО и ПОСЛЕ, breakdiag в файл → break + A3/A4
        ↓
    возврат по SESSION_1_SIGN_BREAK/RETURN_TEMPLATE.md
        ↓
    решение приёмки (ПК-2): что именно дефект → fix-ТЗ, или VF-2A закрыт
        ↓
Сессия 3 (следующая): SESSION_3_SIGN_AB/  — образ monitor-only
    2 прогона на текущей разводке + 2 на исходной + осциллограф 5 В/дел (нули совмещены)
        ↓  sign_ab_report.py --gate → код 0 (знак следует за ФАЗАМИ) или 3 (вопрос к ЭНКОДЕРУ)
        ↓
Сессия 4: SESSION_4_FAULTN_CHARACTERIZATION/ — образ monitor-only
    3 прогона на текущей разводке + 3 на «плохой» + осциллограф: спад PD2, 15 В рейл, ток
        ↓  faultn_report.py --gate → код 0 (чисто) / 3 (события есть) / 4 (линия не вернулась)
        ↓
    решение приёмки (ПК-2): причина FAULT_N и закрытие знака → отдельные ТЗ
        ↓
Сессия 2 (после этого): SESSION_2_VF2_VF3/  — образ production
    VF-2B (vf=40) → VF-3 (40/100/200/300 → обязательно vf=0 → проверить PWM закрыт)
```

**В сессию 1 не запускать:** VF-2B/VF-3, `ch`, `iv` — они недостижимы fail-closed
(`@AT:ERROR:POWER_BLOCKED`), а семантика `iv` не установлена. **`c` — обязателен** после каждой
перезагрузки/обесточивания и до первого `vf=`: без него `vf=` даёт `rc=-7`, а неудачный `vf=`
убивает CLI-цикл (восстановление — только SWD-reset). Это исправление v3: в v2 `c` был ошибочно
назван недопустимым, и оператор вынужденно отклонился от протокола.

**Гейт перед `vf=` обязан проверять VBUS ≥ 400** (в единицах `@ADC … VBUS=` это 0.1 В, т.е. 40 В):
гейт только на `FAULT=0` + `sd=1:1` пропускает прогон без шины и даёт мусорный вердикт сторожа.
Evidence писать через `cmd /c "… > файл"` (PowerShell `>` даёт UTF-16 и ломает разбор).

## Как проверить комплект (2 команды, PowerShell)

```powershell
Set-Location <корень этого комплекта>
Get-Content SHA256SUMS | ForEach-Object { $p = $_ -split ' \*'; if ((Get-FileHash $p[1] -Algorithm SHA256).Hash.ToLower() -ne $p[0]) { "РАСХОЖДЕНИЕ $($p[1])" } }; "проверка манифеста завершена"
```

Ожидаемо: печатается только «проверка манифеста завершена». Любая строка «РАСХОЖДЕНИЕ …» —
комплект повреждён при копировании: сообщить на ПК-2 и по такому комплекту не работать.


## Аборт немедленно

`fault≠0` · `sd1/sd2≠1` · VBUS < 8 В (по осциллографу/БП, **не** по колонке лога) · шум/вибрация/нагрев ·
непрерывный `commit=0` · на SD импульс **без** предшествующего роста тока (значит UVLO драйвера или помеха).
