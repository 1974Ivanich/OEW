# ПК-3, сессия 6: электрические параметры мотора (Rs, Ls/Ld/Lq, ψ, J)

Сессия нужна, чтобы получить параметры для замкнутой модели привода (пункт Б:
plant model + наш контроллер на хосте). Без этих чисел модель — фикция.

## Что сессия докажет и чего не докажет

**Докажет:** Rs (две независимые оценки + симметрия трёх пар фаз), Ls (средняя),
Ls по положениям ротора → Ld/Lq либо доказательство неявнополюсности, ψ (Ke) —
две независимые оценки со сверкой. Всё — на текущем моторе и текущей прошивке,
в одной сессии, с воспроизводимым выводом в UART-лог.

**Не докажет:** насыщение (Ls(I) снимается в 1–2 точках, не кривой), зависимость
от температуры (мотор холодный на старте, тёплый в конце — температура не
логируется), механические потери/трение, корректность FOC-регуляторов, **число
пар полюсов** `p` (прошивкой не измеряется — паспортное значение, вводится через
`mp=`), **момент инерции** `J` (тест не реализован, см. шаг 6). Модель по этим
данным будет линейной — это её потолок.

## Заморозка стека

До первой команды записать в лог и в отчёт:

- `git rev-parse HEAD` прошивки и `git status --porcelain` (должно быть пусто);
- `sha256sum` файла образа, которым прошита плата;
- версии инструментов: `py -3 --version`, `sigrok-cli --version` (если ЛА в работе);
- дату/время старта в UTC и локальное.

После старта сессии прошивку **не меняем**. Если понадобилась правка — сессия
стоп, правка отдельным пакетом, новая сессия.

## Состояние стенда

| Что | Требование |
|---|---|
| DC-link | старт на **30 В**, не 60: запертый ротор греется, токи теста ограничены прошивкой (`AUTOTUNE_MAX_CURRENT_MA`) |
| Оба инвертора | **одна шина DC** (иначе freewheel через диоды пассивного Inv2 заряжает его C без пути разряда — см. предупреждение в `AT_SafetyCheck`) |
| Мотор | разгружен (нет мех. нагрузки на валу), вал доступен для ручного проворота и для запирания |
| Прошивка | свежий `origin/main`, сборка **с силовым путём**: `make EXTRA_CFLAGS='-DOEW_HS1_COMMISSIONING_RELEASE=1'` (без этого флага `PWM_HardwareInterlockHealthy()=false` → все тесты дают `@AT:ERROR:POWER_BLOCKED:PWM enable failed`, а `vf=` → `rc=-8`) |
| Карта секторов/окон | **загружена измеренная карта**: `mapcap build=<профиль>`, иначе `@AT:ERROR:POWER_BLOCKED:no measured OEW sector/window map` — autotune и V/f физически не включат мосты |
| UART | логгер в файл, все строки целиком, без обрезки |
| Осциллограф | 2 канала + щуп; нужен только на шаге 7Б |
| Мультиметр | для сверки VBUS |
| Прочее | `make backup` перед сессией, если ещё не сделан |

Допуск по шине (проверяет прошивка): `12 000 мВ ≤ VBUS ≤ 350 000 мВ`, иначе
`@AT:ERROR:VBUS_LOW` / `VBUS_HIGH`. Предел тока в autotune-тестах —
`AUTOTUNE_MAX_CURRENT_MA = 8000` (8 А), это страховка, не рабочий ток. Перед каждым autotune-тестом — `fault=0`,
V/f остановлен (`vf=0`), остаточный ток ≈ 0.

## Шаг 0. Идентичность и исходное состояние

```
sysinfo
params
stats
```

Ожидаемо: `@SYS:CLK=...`, `@AT:PARAMS:Rs_mOhm=...:Ls_uH=...:Isat_mA=...:Rr_mOhm=...:
Lm_uH=...:Tr_us=...:Ke_mV_rpm=...:p=...:J_x1e6=...:CH=...:VMASK=0x...`.
Зафиксировать как «до». Если `Rs_mOhm=0` — параметры не заполнены, это норма для
чистой платы.

## Шаг 1. Нули (PWM выключен, шина на рабочем напряжении)

```
cv
ci 0
ci 1
ci 2
```

- `cv` — offset VBUS при нулевом входе. **Порядок:** питание шины снять, `cv`,
  вернуть питание. Если шина уже под напряжением — `cv` пропустить и записать в
  отчёт, что offset VBUS взят из прошивки.
- `ci 0|1|2` — окна смещения шунтов: avg/min/max raw + vbus. Ожидаемо
  `@CI:...`. Разброс min/max внутри окна > нескольких отсчётов — отметить.

## Шаг 2. Канал тока

```
ch
```

Ожидаемо: `@AT:CH_DETECT:OK:CH=<n>:I=<мА>:SIGN=<±1>`. Если
`@AT:CH_DETECT:ERROR:NO_CURRENT` — проверить подключение шунта/фазы, дальше не
идти (все последующие тесты используют `current_channel`).

## Шаг 3. Rs — две независимые оценки

```
iv
pairs
```

- `iv` — Rs по точкам I–V: `@AT:RS_IV:POINT:D=..:U=..:I=..`, итог в `stats`.
- `pairs` — все три пары фаз: `@AT:PAIRS:OK:Rs=<мОм>:Ls=<мкГн>:ASYM=<%>:VALID=3`.

**Критерий:** `VALID=3` и `ASYM ≤ 5 %`. Больше — плохой контакт/перекос обмоток;
тогда Rs из `pairs` не берём, берём `iv`, а причину фиксируем в отчёте.

## Шаг 4. Ls (средняя)

```
oew
```

Ожидаемо: `@AT:OEW:OK:Ls=<мкГн>:Isat=<мА>`; пошагово — `@AT:OEW:LS_STEP:...:L=...`.
Если `@AT:OEW:WARN:LS_REJECT` или `ERROR:OVERCURRENT` — повторить один раз на
шине 40 В; два отказа подряд — стоп, разбор.

## Шаг 5. Ls по положениям ротора (Ld/Lq или доказательство неявнополюсности)

```
lspos
```

Прошивка ждёт оператора между точками:
`@AT:LSPOS:WAIT:POS=n/5:TURN_ROTOR` (n = 1…6).

**Процедура поворота (обязательно одинаковые шаги):** от первой точки поворачивать
вал вручную на **36° механических** между точками (всего 180° мех. за 6 точек).
Полоборота покрывает не менее одного электрического периода при любом `p ≥ 2`,
поэтому min/max по шести точкам накрывают оси q и d. Шаг больше или «как
получится» — данные не годятся: min/max перестают соответствовать осям.

Ожидаемо: `@AT:LSPOS:MEAS:POS=n/5:Ls=..:I=..` ×6, затем
`@AT:LSPOS:OK:N=6:MEDIAN=<мкГн>:MIN=<мкГн>:MAX=<мкГн>:SPREAD=<%>`.

Трактовка:
- `SPREAD ≥ 10 %` → машина явнополюсная, **Lq = MAX, Ld = MIN** (магнитный поток
  направлен по d; по d индуктивность меньше из-за насыщения от магнита);
- `SPREAD < 5 %` → Ld ≈ Lq = MEDIAN, саленостью в модели пренебрегаем;
- `WARN:HIGH_SPREAD` при кривых шагах — повторить шаг 5 целиком.

## Шаг 6. Момент инерции — прошивкой НЕ измеряется

`inertia` и `irot` в текущей прошивке отвечают
`@INERTIA:ERROR:NOT_IMPLEMENTED` (заглушка в `Autotune_Inertia`, `src/autotune.c:1559`)
— команду не запускать, время не тратить.

J берётся вне прошивки, в порядке приоритета:

1. паспорт мотора + редуктор/маховик (сумма по формуле `J = J_ротор + J_нагрузки`);
2. оценка по выбегу: разогнать V/f до `vf=60`, затем `vf=0`, записать
   `@VFLOG` с `vflog=10` и по спаду `meas` во времени получить
   `J ≈ T_потерь / |dω/dt|` — оценочно, с погрешностью десятки процентов;
3. если ни то, ни другое — J в модель не ставить (оставить 0) и записать в отчёт,
   что динамика по скорости в модели недостоверна.

## Шаг 7. ψ (Ke) — потокосцепление магнита

Фазные напряжения платой **не измеряются** (`ADC_CH_SHUNT1/2`, `ADC_CH_CT`,
`ADC_CH_VBUS` — фазных каналов нет), поэтому ψ берём двумя независимыми путями и
сверяем их.

### 7А. Из рабочей точки V/f (без разборки стенда)

```
vflog=50
vf=200
```

`vf=<rpm>` — задание механической скорости в об/мин. Прошивка сама считает
`vmag = 100·|fe|/50 + 15` (%), где `fe = p·n/60`; при 30 В шины и `p = 2`
целимся в `vmag` = 40–60 %, это ≈ 400–600 об/мин (`vf=400…600`). Ориентир:
`vmag < 30 %` — поднять задание, `vmag` упирается в 95 % — снизить (это предел
модуляции, дальше форма нелинейна).

Дать выйти в установившийся режим (30–60 с, `meas` стабилен ±2 об/мин), снять
не менее 20 строк `@VFLOG`, затем `vf=0` и `vflog=0`.

`@VFLOG` даёт за один момент времени: `meas`, `fe`, `vmag`, `du/dv/dw` (% скважности
по фазам), `i1/i2` (raw), `vbus` (raw отсчёты), `eangle`, `espeed`, `fault`.

Пересчёт в оффлайне (питоном, в отчёте — код):

```
d  = du/100, dv/100, dw/100                     # скважности
du_ = d_u - mean(d), ...                        # вычитаем общую моду
E_phase_peak = max(|du_|, |dv_|, |dw_|) * VBUS  # В, пик фазы
psi = E_phase_peak / (2*pi*fe)                  # В·с (пик фазы)
Ke_mV_per_rpm = psi * 2*pi*pp / 60 * 1000
```

где `VBUS` — в вольтах: `vbus` из `@VFLOG` — **сырые отсчёты**, перевести по
калибровке `cv` (или по мультиметру: `VBUS_В = отсчёты × k`, k снять на шаге 1).

Оговорка: в V/f часть напряжения уходит на Rs·I и на индуктивность, поэтому это
оценка **сверху** для ψ (на холостом ходу при малом токе ошибка мала — фиксировать
токи и в отчёт).

### 7Б. Осциллографом по ЭДС холостого хода (авторитетный замер)

1. Питание шины снять, дождаться разряда, убедиться мультиметром (< 5 В на шине).
2. Мотор отключён от драйвера.
3. Щуп CH1 → клемма U, CH2 → клемма V (земля щупа на V, дифференциально не
   требуется при отключённом драйвере).
4. Вращать вал вручную (дрелью на низких оборотах) **равномерно**, снять 10–20
   периодов.
5. Из осциллограммы: `V_LL_peak` (пик линейного), `f_e` (частота ЭДС по периоду).
6. Проверить **форму**: плоская вершина → трапеция (тогда формула ниже неверна,
   писать в отчёт «машина трапецеидальная», ψ считать по первой гармонике и
   отметить погрешность); чистая синусоида → расчёт применим.

```
E_phase_peak  = V_LL_peak / sqrt(3)
psi           = E_phase_peak / (2*pi*f_e)          # В·с
n_rpm         = f_e * 60 / pp
Ke_mV_per_rpm = E_phase_peak / n_rpm * 1000
```

**Сверка:** расхождение 7А и 7Б более 15 % — не усреднять, а разбираться: в отчёт
идут оба числа, ψ в модель берётся из 7Б (прямой замер), 7А — контроль.

## Шаг 8. Применить параметры и подтвердить

```
mp=<Rs>,<Ls>,<Rr>,<Lm>,<Tr>,<Ke>,<p>,<J>
params
```

Значения — целые: Rs (мОм), Ls (мкГн), Rr (мОм), Lm (мкГн), Tr (мкс),
Ke (мВ/об/мин, **пик фазы**), p (пары полюсов), J (×1e-6 кг·м²). `params` должен
вернуть ровно переданные числа — это и есть подтверждение записи.

## Критерии немедленной остановки

1. `@AT:ERROR:OVERCURRENT`, `FAULT_R ≠ 0`, `@AT:ERROR:FAULT_CLEAR_FIRST` после
   `breakdiag reset` — стоп.
2. `VBUS` выше 45 В при шине 30 В (выброс/регенерация) — стоп.
3. `@AT:LSPOS:ERROR:BAD_CURRENT` дважды подряд — стоп (ток не устанавливается,
   значит канал/шунт врёт).
4. Корпус мотора или модуля горячее ~50 °C на ощупь — пауза 10 мин.
5. `@AT:ERROR:POWER_BLOCKED:*` — это не отказ железа, а не выполненные
   предусловия (нет флага сборки или не загружена карта): остановиться, проверить
   сборку и `mapcap build`, не «обойти».
6. Любое расхождение с ожидаемым форматом строки (`@AT:*`) — стоп и в отчёт,
   не «додумывать» ответ.
