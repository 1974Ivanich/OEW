# TOOLS: как пользоваться

## 0. Консоль: кодировка и рабочий каталог (один раз за сессию)

```bat
chcp 65001
set PYTHONIOENCODING=utf-8
cd /d <корень этого комплекта>
```

Инструменты v2 сами переживают консоль cp1251 (их вывод целиком кодируется в cp1251, плюс
страховка `errors='replace'`), но с UTF-8 вывод читается без замен символов. Все команды —
**относительно корня комплекта**; абсолютных путей с буквой диска в документах нет намеренно
(на ПК-2 и ПК-3 носитель может быть `E:`, `F:` или `I:`).

## 1. `enc_sign.py` — знак конвенции энкодера

Захватить поток `enc` в файл (подойдёт любой способ записать вывод COM-порта):

```bat
py -3 TOOLS\vf_raw.py COM4 enc 3 > enc_stream.txt   :: команда платы, 3 с приёма, поток @FOC/@VFLOG отфильтрован
```
`vf_raw.py` входит в комплект (`TOOLS\vf_raw.py`) и требует `pyserial`:
`py -3 -m pip install pyserial`. Если пакета нет, инструмент скажет об этом и завершится
кодом 3 (без traceback).


```bat
py -3 TOOLS\enc_sign.py <файл с строками @ENC:...>
py -3 TOOLS\enc_sign.py --selftest
```

Что печатает: число строк, `err!=0`, Δ`angle` в отсчётах и оборотах, диапазон `speed`, вердикт
«ПЛЮС/МИНУС (angle растёт/убывает)». Учитывает переполнение 14-битного угла.
Если `err!=0` или смещение < 8 отсчётов — вердикт не выдаётся (это правильно: данных мало).

## 2. `breakdiag_parse.py` — разбор сырого `@BRK:` в флаги

```bat
py -3 TOOLS\vf_raw.py COM4 breakdiag 5 > breakdiag_raw.txt
py -3 TOOLS\breakdiag_parse.py breakdiag_raw.txt
py -3 TOOLS\breakdiag_parse.py --selftest
```

Коды возврата `breakdiag_parse.py` (важно для отчёта):

| Код | Значение | Что делать |
|---|---|---|
| 0 | разбор полный, противоречий с правилом прошивки нет (или `valid=0`) | зафиксировать вывод |
| 1 | найдено противоречие (например `BKP=1` при успешном пуске) | сохранить вывод, это находка для fix-ТЗ |
| 2 | строка **усечена** (нет `cyc`/`ce`/`cnt`/`cap`) | непременно снять полный дамп: `breakdiag` в файл, цитаты недостаточно |
| 3 | в файле нет строки `@BRK:` | проверить, что захват шёл по команде `breakdiag` |

Усечённая строка больше не роняет разбор (в v1 был traceback `ValueError` на строке
`@BRK:valid=1:seq=1:src=TIM1:…:sr=81,81:sd=1,1:bd=1CC0,1CC0` из возврата ПК-3).

Что печатает по каждому таймеру: `SR` (BIF/B2IF/UIF…), состояние линий SD на момент захвата,
`CCER` (CC1E/CC1NE/…), `BDTR` в виде флагов MOE/AOE/BKE/BKP/OSSR/OSSI/LOCK + DTG-кодировка, и
**сверку с правилом прошивки** (`src/pwm.c:37-38`: обязательны BKE/OSSR/OSSI, запрещены BKP/AOE).

Зачем: это и есть сырое доказательство break вместо цитаты из документа. Если `BDTR` покажет
`BKP=1` или не покажет `OSSI=1`, скрипт прямо напишет, что такое состояние `pwm_bdtr_healthy()`
отверг бы, то есть дамп не может описывать момент успешного пуска — и нужен повторный захват.

Полезно сохранить **до** и **после** прогона: `dump`/`dump8` (hex BDTR обоих таймеров) — тогда
сравнение «до/после» само показывает, что hardware снял MOE (`BDTR` бит 15 = 0).
