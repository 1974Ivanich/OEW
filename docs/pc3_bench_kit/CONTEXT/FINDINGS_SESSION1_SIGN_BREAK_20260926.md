⇒ Перестановка двух моторных проводов меняет знак при той же команде и том же энкодере
(`err=0`, канал цел) ⇒ **причина — порядок фаз (`du/dv/dw` ↔ обмотки), а не знак A/B энкодера.**
Фикс: разводкой (оставить перестановку) **либо** прошивкой (порядок фаз в PWM-маппинге) —
отдельным ТЗ, не в физической сессии. Правок в разгар эксперимента не делалось — правило соблюдено.

## 3. Связь с историей проекта: `FAULT_R=18` — это известный ложный FAULT_N STEVAL-2 (SD2/PD2)

`FAULT_R=18` = `PROTECT_FAULT_HARDWARE_BREAK` (enum `src/protect.h`). В истории проекта это уже
разбиралось:

* merge `fbce551` / `3e00b57`: «ложный FAULT_N STEVAL-2 (SD2/PD2) не должен убивать V/f; BKE=0 только
  в bench-сборке, стенд 10/10»;
* статус `cfcbeae`: «ложный FAULT_N STEVAL на старте ~1 с останавливал разгон … мотор ~1200 RPM»;
* merge `93df357`: принятый V/f-прогон, стенд v7 10/10;
* `TZ_VF_START_RELIABILITY.md` (критерии): «стенд, 60 В, **MONITOR-ONLY ОБРАЗ**: 10/10 стартов `vf=300`
  … НИ ОДНОГО fault (`FAULT_R=18`/`STOPPED`)»;
* `b499d83` (01.09): после фикса `pp=3` «ложный FAULT_N (возникал при vmag=95) не воспроизводится —
  стенд ведётся со штатной защитой», сборки с `-DOEW_SD_MONITOR_ONLY=1` из ТЗ убраны.

Наш образ — штатный (под током `BKE=1`, `BKP=0`, монитор-онли НЕ включён). Значит повтор ложного
FAULT_N при `BKE=1` (утренняя сессия 26.09, `FAULT_R=18`) — **открытый дефект канала SD2/PD2**,
а не «непонятный аппаратный break». Решается квалификацией входа (фильтр/дебаунс/диагностика линии
+ замер SD2 осциллографом синхронно с latch), отдельным ТЗ; ослабление защиты нормой не считается.

## 6. Телеметрический дефект `@VFLOG` (кандидат в ТЗ, не в этот пакет)

Поля `i1/i2/ires/vbus` публикуются как **сырые отсчёты без проверки кадра**: в сессии 1 последняя
строка прогона содержит `i1=0:i2=0:ires=0:vbus=0`, из-за чего «размах/2» даёт 13 А вместо ≈0.2 А
(проверено на `vf_vf2a_reg.log`, `i1` 2041…2054 отсч. без нулевой строки). Требование: публиковать
эти поля только из валидированного кадра либо не публиковать вовсе (для VBUS уже есть
`ADC_ReadVbusRegularMv()`, для токов — API в мВ/мА).
