# Провенанс образов этого комплекта

Провенанс **генерируется сборочным скриптом** и лежит рядом с образами, по одному файлу на профиль:

* `production` → `IMAGE/PROVENANCE_production.txt` (образы `firmware_production.bin` / `.elf`)
* `monitor-only` → `IMAGE/PROVENANCE_monitor-only.txt` (образы `firmware_monitor_only.bin` / `.elf`)

В каждом файле: `SOURCE_COMMIT`, `SOURCE_BRANCH`, `MAIN_AT_BUILD`, `MAIN_UNTOUCHED`,
`COMMISSIONING_RELEASE`, SHA256 и размер каждого файла, флаги сборки, **ожидаемые значения BDTR**,
`BREAKDIAG_PROFILE`, `USE` (для каких сессий) и `SAFETY` (что этот образ отключает).

Общее для обоих образов (база сборки): `SOURCE_COMMIT=ab1274d3506587303672325089d58a72bb941564`,
ветка `ai2/vf-telemetry-rate-fix`, `MAIN_AT_BUILD=11ad97da`, `MAIN_UNTOUCHED=YES`,
`COMMISSIONING_RELEASE=1`, `MAIN_MERGE=PENDING`, `PHYSICAL_SESSION_STATUS=BASELINE / NOT YET QUALIFIED`.

Единого `IMAGE/firmware.bin` в комплекте v4 больше нет: образов ДВА. Перед прошивкой определите
нужный профиль по `START_HERE_PC3.md` — сессии 3 и 4 идут на `monitor-only`, сессии VF-2B/VF-3
и всё, что проверяет штатную защиту, — на `production`.

Проверка дампа BDTR под прошитый образ:

```bat
py -3 SESSION_1_SIGN_BREAK\TOOLS\breakdiag_parse.py --profile production <файл с @BRK>
py -3 SESSION_1_SIGN_BREAK\TOOLS\breakdiag_parse.py --profile monitor-only <файл с @BRK>
```
