# ПК-3, сессия 7: первый запуск FOC на асинхронном двигателе (схема OEW)

## Что эта сессия доказывает и чего не доказывает

**Докажет:** что прошивка проходит все ворота допуска (`FOC_Start` → `rc=0`), что карта
реконструкции токов принимается на этой плате, что машина выходит из open-loop I-f в
замкнутый RUN и держит скорость на холостом ходу.

**Не докажет:** правильность настройки контуров на нагрузке, момент на валу (динамометра
нет), тепловой режим под нагрузкой, корректность карты токов за пределами проверенных
точек. Всё это — следующие сессии.

## Пакет (передаётся на ПК-3 одним каталогом)

| Файл | Что это | sha256 |
|---|---|---|
| `firmware_energize.bin` | прошивка с силовым путём и mapcap/mapload | `bfd5f240e154f31b0a8e9450c63188ad352e8d276e2244647b9ca1d420727a52` |
| `oew_map_v2.bin` | измеренная карта реконструкции токов, 497 Б | `ddb2cd6091236c5c2563ee94b86ab8f7fb1821b8b00e0923bdeef2e79e363d83` |
| `mapload_hex.txt` | готовая строка `mapload <994 hex>` | — |
| `MANIFEST.txt` | как собрано, сверка identity | — |

Образ собран из `main` (`39f25de`) командой:

```
make clean
make -j8 EXTRA_CFLAGS='-DOEW_HS1_COMMISSIONING_RELEASE=1 -DOEW_MAP_CAPTURE=1 \
                       -DOEW_MAP_L3=1 -DPWM_OEW_BOARD_REVISION=7u'
```

Размер `text 88092 / data 516 / bss 13668`. **Default-deny сборка (78260) для этой сессии
не годится:** в ней нет команд `mapcap`/`mapload`, а `PWM_Enable` вернёт отказ.

## Заморозка

До первой команды записать: `git rev-parse HEAD` (ожидается `39f25de`), sha256 образа,
дату/время старта, версию `py -3 --version`. После старта прошивку не менять: правка →
сессия стоп → отдельный пакет → новая сессия.

## Предусловия стенда

| Что | Требование |
|---|---|
| Шина | 30 В на старте (не 60): первые прогоны на малом токе |
| Инверторы | обе платы на одной шине DC; SD-линии высокие, латча нет |
| Мотор | разгружен, вал свободен, доступен для ручного проворота |
| Энкодер | AS5048A подключён, направление проверено (`ENC_INVERT_DIR=1` в этой сборке) |
| UART | логгер пишет всё в файл, без обрезки; `@FOC:` идёт автоматически 10 Гц |

Допуски прошивки: autotune требует `VBUS` 12…350 В, защита — 8…350 В, `fault=0`,
V/f остановлен.

## Шаг 0. Прошивка и идентичность

1. `make backup` (если ещё не сделан для этой платы).
2. **Сверить образ до записи:** `sha256sum firmware_energize.bin` должен совпасть с полем
   `sha256 bin` в `MANIFEST.txt`. Не совпало — не прошивать.
3. Прошить `firmware_energize.bin`.
4. **Проверить шапку загрузки** после сброса: `CORDIC OK`, затем `PROTECT OK:IMAX_MA=8000`,
   затем `FOC init OK`. Другое значение `IMAX_MA` означает, что прошит не тот образ
   (например, старый с порогом 12000).
5. В терминале: `sysinfo`, `params`, `stats` → зафиксировать в лог.
6. `mapcap identity` → записать все поля и сверить с таблицей:

| Поле | Ожидается |
|---|---|
| `board` | 7 |
| `pwm` | 5000 |
| `arr` | 999 |
| `trig` | 0x4F455731 |
| `dt` | 192 |
| `adc_clk` | 42500000 |
| `sample_x2` | 1281 |
| `res` | 0 |

PASS: все восемь совпали. FAIL: любое расхождение — стоп, в отчёт (это значит, что сборка
не та, что описывает MANIFEST).

## Шаг 1. Калибровки (ШИМ выключен)

```
f            # сброс латча, если был
cv           # offset VBUS: питание шины снять, cv, вернуть питание
ci 0
ci 1
ci 2
```

PASS: `f` → «fault cleared» (или его не было), `ci` печатают окна смещений без ошибок.
FAIL: `fault NOT cleared` (Vbus/ток вне диапазона) — не запускать, разбираться с шиной.

## Шаг 2. Параметры машины (обязательно все)

```
ch        # определить канал тока:  @AT:CH_DETECT:OK:CH=..:I=..:SIGN=..
iv        # Rs по точкам I-V
pairs     # Rs/Ls по трём парам фаз: VALID=3, ASYM <= 5%
oew       # Ls (два инвертора): @AT:OEW:OK:Ls=..:Isat=..
rr        # Rr (запертый ротор) -> @AT:PARAMS: Rr, Tr
noload    # Lm/Lr/Tr (свободный ротор)
params    # контроль: Rs, Ls, Isat, Rr, Lm, Tr, Ke, p, J
```

**`rr` и `noload` обязательны.** Ворота RUN требуют, чтобы `Tr` был **измерен**
(`AT_VALID_TR` без `AT_VALID_TR_MANUAL`) и `Tr ≥ 1000 мкс`. Значение, введённое через
`mp=`, помечается как ручное и прямой RUN-старт блокирует.

Проверка ворот параметров (иначе `FOC_Start` вернёт `-6`): `Rs` 10…100000 мОм,
`Ls` 500…500000 мкГн.

Если пары полюсов не те: `mp=<Rs>,<Ls>,<Rr>,<Lm>,<Tr>,<Ke>,<p>,<J>` — но помнить про
пометку `Tr` как ручного (после `mp=` с `Tr` снова прогнать `rr`/`noload`, если нужен RUN).

PASS: `params` заполнен, `Rs`/`Ls` в диапазоне, `p` соответствует шильдику.
FAIL: `@AT:ERROR:POWER_BLOCKED:*` — не выполнены предусловия (сборка/карта/SD), а не отказ
железа; `@AT:ERROR:VBUS_*` — шина; `@AT:PAIRS:ERROR:INSUFFICIENT_VALID` — контакты/шунт.

## Шаг 3. Карта реконструкции токов

1. Вставить строку из `mapload_hex.txt` целиком (8 + 994 символа).
2. Ожидается `@MAP:LOAD:OK` (внутри — decode + commissioning + сверка identity).
3. `mapcap identity` ещё раз — сверить поля (карта загружена, `CurrentRecon_IsReady()=true`).

PASS: `@MAP:LOAD:OK`, identity совпала, `@FOC:` в кадре печатает ненулевой `map_crc32`
(ожидается `F68D948B`).

FAIL: `@MAP:LOAD:ERROR:VALIDATION` или `DECODE` — карта не принята. Тогда два пути:
а) сверить identity из вывода `mapcap identity` с таблицей шага 0 (чаще всего `board`);
б) собрать карту заново: `mapcap run` → `mapcap drain` → `mapcap build=<id>`
   (профиль `BOAR` = 1112490322 + sector*2 + window, 96 точек) — это отдельная кампания,
   на эту сессию не планируется.

## Шаг 4. Запуск

```
1
```

Ожидается: `FOC started`. Если отказ — `@FOC:START:FAIL:rc=N`:

| rc | Причина | Что делать |
|---|---|---|
| -1 | латч fault или clock fail | `f`, `breakdiag`, `sysinfo` |
| -2 | карта не готова / нет валидного стартового контекста | шаг 3 |
| -3 | калибровка смещений не прошла | шаг 1 |
| -4 | не взвелась инжекция АЦП | как правило следствие -2/-3 |
| -5 | `PWM_Enable` (аппаратный interlock) | SD-линии, сборка с `RELEASE=1` |
| -6 | Rs/Ls вне sane-диапазона | шаг 2 |

## Шаг 5. Вращение

```
s=200          # задание скорости, об/мин (диапазон -50000..50000)
```

Наблюдать поток `@FOC:` (10 Гц): `STATE`, `RUN`, `FAIL`, `Id`, `Iq`, `Id_ref`, `Iq_ref`,
`sector`, `window`, `FAULT`, `ADC_STATUS`.

Ожидаемая картина: `STATE=STARTUP` (open-loop I-f рампа), затем выход в `RUN`. Прямой
вход в RUN возможен только если вал уже вращается ≥ 30 об/мин, энкодер здоров и `Tr`
измерен — это ограничение логики запуска (проверка энкодера и наблюдателя), а не физики:
с места двигатель трогается в STARTUP рампой I-f и развивает момент с нуля скорости.

При срыве смотреть `FAIL=`:

| FAIL | Смысл | Что проверить |
|---|---|---|
| `NO_ROTATION` | рампа не создала момент | Tr, параметры, фазировка, шунт |
| `SPEED_MISMATCH` | измеренная скорость не следует за рампой | `p`, энкодер, насыщение |
| `ENC_DIRECTION` | знак скорости противоречит модели | `ENC_INVERT_DIR`, порядок фаз |
| `EMF_INVALID` | наблюдатель не сошёлся | Rs/Ls, токи, окно выборки |
| `ENCODER_LOST` | нет захватов энкодера | провод, питание, AS5048A |
| `TIMEOUT` / `UNSTABLE` | не уложились в окно/колебания | рампа, токовый лимит |

Ограничения. Номинал неизвестен (двигатель перемотан) — шильдик НЕ используется.
Штатный ток старта задан прошивкой: `FOC_STARTUP_IQ = 50` (~5 А) при `FOC_STARTUP_ID = 20`
(~2 А), то есть модуль ≈ 5,4 А на рампе `FOC_VF_RAMP_MS = 4000` мс. Поэтому пороги
разделены по длительности:

- **кратковременно** (STARTUP, ≤ 5 с): `|Idq| ≤ 6 А` — это штатный старт ≈5,4 А;
- **длительно** (RUN): `|Idq| ≤ 2,0 А` амплитуды до теплового теста;
- `FOC_IQ_MAX = 150`, `FOC_MAX_RPM = 5000`.

Длительный порог пересчитать после замера R обмотки и теплового теста (метод
сопротивления), результат — в `S7_PARAMS.txt`.

Останов: `0`.

## Критерии аборта (немедленно)

1. `FAULT=1` или `FAULT_R ≠ 0` — стоп, `breakdiag`, разбор по коду.
2. `VBUS` выше 45 В при шине 30 В (выброс/регенерация).
3. `|Idq| > 6 А` в любой момент; `|Idq| > 3 А` дольше 10 с в RUN; ток растёт без
   задания или рывком.
4. Ротор не двигается, а `Id` растёт до лимита (рампа «в стену»).
5. Корпус мотора или модуля горячее ~50 °C на ощупь.
6. Любое расхождение формата строк (`@FOC:` не парсится) — стоп, не «додумывать».

## Чего эта инструкция не покрывает

- Кампанию карты (96 точек) — только если загрузка готового артефакта будет отклонена.
- Настройку ПИ-контуров под нагрузку и тепловой тест — следующие сессии.
- Работу с B3/EESM — отдельный трек, к этой сессии отношения не имеет.
