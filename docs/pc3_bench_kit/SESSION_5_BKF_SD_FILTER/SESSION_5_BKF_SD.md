# ПК-3, сессия 5: BKIN-фильтр (BKF) против ложных break; попытка V/f на 60 В

## Контекст и гипотеза

Повторяющиеся `FAULT_R=18` (hardware break) сначала трактовались как «программный
предел ~0.5 А». Эта трактовка отвергнута: STEVAL-IPM20 / SLLIMM-IPM — силовой
каскад ~20 А, внешнего токового компаратора нет; пин SD — **внутренний
fault-выход IPM** (OC по CIN / UVLO / перегрев), open-drain, активный low.

`breakdiag` показывал: `src=TIM8`, `sr=…,81/…,DF` (BIF), `sd=1,1` — линия уже
отпущена к моменту ISR → короткий импульс, а не удерживаемый fault. Дополнительно: `FAULT_R=3` (`PROTECT_FAULT_VBUS_LOW`) — ещё 40 кадров, все в `u3.log` (старт `1` при `VBUS=0`, шина ещё не поднята) — к break-событиям отношения не имеет.

## Изменение прошивки

`src/pwm.c`: в `TIM1->AF1`/`TIM8->AF1` добавлен `BKF=0b1111` (fDTS/32, N=8 ≈
1.5 мкс при 170 МГц). BKINE и активный-low BKINP сохранены — удерживаемый low
по-прежнему снимает MOE и латчит `FAULT_R=18`. Fail-closed не ослаблен.

Верификация на железе: `AF1=0xF001` прочитано отладчиком.

## Что зафиксировано

| Эксперимент | Результат |
|---|---|
| Closed-loop FOC при ручном вращении вала, 30 В, до/после BKF | **до**: `FAULT_R=18` за ~0.3–1 с; **после**: `RUN=1` непрерывно ≥3.9 с (`u14`, захват оборван на живом RUN; 12-с окно логами не подтверждено — см. «Открытые вопросы»), `FAULT=0`, SD на LA чистый |
| Самозапуск closed-loop (`1`), i=2000…3000,3000 | Ротор не срывается: поле встаёт в детент, `FAIL=7` за ~0.2–4 с, `FAULT=0` |
| V/f `vf=80` при 60 В | Один прогон разогнался до `meas=−74` rpm, `fe=6 Гц`; перед обрывом `VBUS` вырос до 910 отсчётов (`u19`, тот же кадр, что `meas=-74`); абсолютный максимум сессии — `vbus=934` (≈93 В, `u21`, отдельный прогон vf=80), регенеративный выброс → break |
| V/f `vf=40` при 60 В (повторы) | Break за ~8 мс от старта; `breakdiag` `src=TIM8`, BIF взведён |
| LA-захват SD (D0/D1, 8 МГц) при break на 60 В | **Провала SD не зарегистрировано** — см. открытый вопрос |
| `vfk=30,30` (boost 30 %) | `vmag=33`, ротор не срывается, watchdog-стоп по `meas<5` за окно старта — штатно |

## Открытые вопросы

1. **Парадокс LA/BKF (главный).** UART подтверждает `TIM8 BIF`: `FAULT_R=18` (555 кадров) и `breakdiag` с `sr=…,DF`. Но во всех `sd_cap*` максимальный low-импульс SD — **5 выборок = 0.625 µs при 8 МГц**, SD-low ≥1.5 µs (порог, который обязан пройти BKF, чтобы взвести BIF) **не зарегистрирован нигде**; `sd_probe` (4 МГц) — активности нет вообще, `sd_cap5` — устойчивые переключения ~4 МГц, похожие на неверную точку подключения. Гипотеза «BIF ⇒ SD2 LOW ≥1.5 µs» доказана только частично: код подтверждает BKF=0xF в `TIMx_AF1` (`src/pwm.c:47`, RM0440; не BDTR), но не закрыты пункты: измеряемый LA-канал — тот же электрический узел, что и TIM8 BKIN; достаточен ли уровень/порог LA; попало ли событие BIF в окно захвата.

2. **Следующий эксперимент — короткий, до любых правок прошивки: аналоговый осциллограф, не LA.** CH1 → TP23/PD2 непосредственно у STM32; CH2 → SD2 непосредственно на STEVAL-2; CH3 → VBUS; CH4 → один из токов. Повторить тот же 60-В запуск, где появляется `TIM8 BIF`. Разбор: SD2 low + PD2 low → проблема в IPM/SD2; SD2 low, PD2 чисто → цепь между SD2 и BKIN; SD2 чисто, PD2 low → электрическая проблема BKIN/PD2; оба чистые + BIF → источник break в самом TIM8. Ранее планировавшаяся посадка TP23 при живом LA-захвате заменяется этим. Схема зафиксирована (07.10.2026) двумя короткими записями: **запись A (BIF)** — CH1=TP23/PD2, CH2=SD2, CH3=VBUS, CH4=ток Inv1/Inv2; **запись B (энергетика/ADC)** — CH1=ток Inv1, CH2=ток Inv2, CH3=ACS712-5A (ток от DC БП), CH4=VBUS. STM32 в обеих записях параллельно пишет PA0/PA1/PA6/PC4; канал осциллографа на PA6 (Ires) не тратим. ACS712-5A используется как внешний измерительный эталон, а не как штатный датчик прошивки.

3. **Природа импульса на 60 В** (если он реален): OC-CIN, UVLO драйвера, или регенеративный выброс шины — максимум сессии `vbus=934` (≈93 В при питании 60 В) сделал последнюю версию вполне живой.

4. **Подхват V/f вероятностный:** один прогон пошёл до −74 rpm, два застряли на `fe=2–3 Гц` с охотой на месте.

**Решение (07.10.2026): TIM8 BKIN пока не удалять; пакет P1 (OCP-coverage) не начинать** — до результатов осциллографической сессии из п.2. Сырые данные впервые позволяют проверить связь BIF с SD2, и пока она не подтверждена.

## Исторический профиль успешного разгона (для воспроизведения)

Из `SESSION_2_VF2_VF3/SESSION_VF2_VF3.md` при 60 В:

```text
vf=40 → ~15 с → vf=100 → ~15 с → vf=200 → ~15 с → vf=300 → vf=0
```

Ступенчатое переназначение цели на ходу; ротор шёл против знака команды
(`meas` отрицательный при `vf=+`).

## Сырые данные

`raw/uart/u*.log` — UART-логи всех команд/прогонов сессии (`>>> cmd`, `@FOC`,
`@VF`, `@BRK`, `@ADC`). `raw/la/*.bin.gz` — бинарные захваты fx2lafw
(sigrok-cli, `-O binary`): байты = выборки, бит N = канал DN; `sd_cap*` —
8 МГц, `sd_probe` — 4 МГц. Тайминги старта см. по `@TRIG:tick` в uart-логах.

## Классификация

- Ложные break на 30 В: **PASS** — устранены фильтром, подтверждено LA + непрерывный RUN (≥3.9 с в `u14`, захват оборван на живом RUN; 12-с окно логами не подтверждено).
- Замкнутый FOC при вращении: **PASS** (поле трекает, Iq регулируется).
- Природа BIF на 60 В: **OPEN** — LA не содержит SD-low ≥1.5 µs, точка измерения SD2 не подтверждена (см. открытые вопросы п.1–2).
- V/f-разгон на 60 В: **UNDETERMINED** — до −74 rpm доходит, стабильности нет.
- Самозапуск closed-loop: **FAIL-STOP** при текущей стратегии угла.
