## Открытые пункты (не блокирующие)

1. **VBUS-транзиент**: в M0-R5 — плато 12.89 В длительностью ≈1.4 с (15 строк `@FOC` по 100 мс;
   в ряду `@ADC` один семпл 128 из 20). Контракт `median ≤ 9` / `max ≤ 200` выполнен, аппаратного
   BREAK не вызвало; в предыдущей кампании аномалия привязана к тому же индексу прогона (M0-R5).
   Нужен трейс узла VBUS вместе с SD1/SD2 — отдельный диагностический слой.
2. **`MAP_IDENTITY_RUNTIME_SEMANTICS`** — `map_crc32=00000000` означает «карта не загружена»;
   доказать, что identity-телеметрия отражает реально активный map artifact, отдельным ТЗ.
3. **Версия раннера**: `metadata.json` кампании не содержит blob-SHA инструмента (версия
   подтверждается поведенчески по наличию гейтов). Рекомендация — добавить поле в metadata.
4. **Порог `--min-safety-coverage`** оставлен 0.5: изменение порога — изменение acceptance
   contract, только отдельным решением/ТЗ (фактическое покрытие ~0.95 при этом пороге достаточно).

## Процедурные уроки приёмки

* Штатный `verify --campaign` **дописывает `verify_report.json` в каталог кампании** — запускать
  только на scratch-копии; приёмочная копия обязана оставаться байт-идентичной источнику,
  хеши сверять после любых прогонов инструмента по каталогу.
* no-HV гейт считается по raw-кодам из `@ADC:…:VBUS=`; `VBUS=` в `@FOC` — **милливольты**
  (расхождение ровно ~100× при смешении полей).
* Строки лога резать `splitlines()`: логгер пишет блоки `[utc] META|BOOT|TX|RX`, внутри LF.
* Команды протокола сверять по CLI: `a` — raw-семпл ADC, `c` — калибровка офсетов (отказ при
  работающем PWM), `enc` — статус энкодера.
