# ТЗ M-OPT-0: бюджет пакета `@FOC` (identity-телеметрия baseline)

Статус: **реализовано** в ветке `ai5/m-opt-0-telemetry-budget` (от `ai5/m-opt-0-telemetry`).
Область: только транспорт телеметрии и тесты. Safety-код (`foc/pwm/protect/vf/adc/adc_dispatch`) не затрагивается.

## 1. Проблема

Ветка `ai5/m-opt-0-telemetry` добавила в `@FOC` поля identity (`run_id`, `map_id`,
`map_crc32`) и токи/напряжения (`Id`, `Iq`, `Id_ref`, `Iq_ref`) — строка стала
длинной, а формат отправлялся через `UART_SendTelemetry()`, который форматирует
в **256-байтовый** буфер и при переполнении делает `vsnprintf`-усечение **молча**:
CRLF пропадает, счётчик потерь не двигается, следующий пакет склеивается с
обрезком. Парсеры на стенде (включая `tools/mopt0_capture.py`) видят битую строку
вместо телеметрии.

Замерено компиляцией точного формата (а не прикидкой):

| Случай | Длина |
|---|---|
| холостой no-HV прогон (`run_id=M0-R1`, токи 0) | **244 байта** — влезает, запас 12 байт |
| худший реалистичный (границы `int32` по всем полям) | **314 байт** — в 256 не влезает |

Запас в 12 байт не является контрактом: любое новое поле или реальные токи
(6–7 символов вместо одного) ломают поток без единого признака на шине.

## 2. Требования (обязательные)

1. Выданная строка **всегда целиком** — либо не выдана вовсе (никаких обрезков).
2. **CRLF гарантирован** для каждой выданной строки.
3. **Счётчик/флаг усечения существует** и наблюдаем на стенде.
4. **Hosted-тест на worst-case строку** (не только на no-HV случай) использует
   **тот же** формат, что прошивка.

## 3. Реализация

| Файл | Изменение |
|---|---|
| `src/telemetry_format.h` (новый) | `FOC_TELEMETRY_FMT` — единственный источник истины для строки `@FOC`; подключается и `main.c`, и тестом бюджета |
| `src/uart.h/.c` | `UART_SendTelemetryChecked()`: буфер `UART_TELEMETRY_BUF_SIZE = 512`, при `formatted < 0 \|\| formatted >= sizeof(buf)` пакет отбрасывается целиком, инкрементируется `uart_tx_truncated_count` (+ drops), возвращается `-1`; иначе строка уходит через `UART_SendStr()` как есть (с CRLF) |
| `main.c` | `@FOC` отправляется только `UART_SendTelemetryChecked(FOC_TELEMETRY_FMT, …)`; новый op `cli_uart_health` |
| `src/cli.h/.c` | `CLI_Ops.uart_health(out[2])` → `sysinfo` печатает `:uart_drp=<dropped>:uart_trunc=<truncated>` (NULL-safe для старых интеграторов) |
| `tests/telemetry_budget_test.c` | 16 новых проверок: пиннинги 244 и 314, CRLF, «worst-case не влезает в старый 256-буфер», checked-sender выдаёт строку целиком, при переполнении — ничего + счётчик |
| `tests/cli_test.c` | 11 новых проверок контракта run id: `run=M0-R1` → прямой `@RUN:ID=M0-R1`, переустановка, допустимый набор символов, пустой/с пробелом/24 символа — отказ без изменения состояния |

Диагностические поля **не сокращались** ради влезания в 256 байт: выбран
отдельный буфер + явный учёт, как и требовалось.

## 4. Проверка

```bash
make tests/telemetry_budget_test.exe && ./tests/telemetry_budget_test.exe   # 29 checks, 0 failures
make tests/cli_test.exe && ./tests/cli_test.exe                            # 126 checks, 0 failures
make                                                                       # firmware 70932 text / 82916 dec
make test-hosted && make test-py
```

На стенде потери видны прямо в `sysinfo`:

```text
@SYS:CLK=…:OVR=…:JQOVF=…:uart_drp=<N>:uart_trunc=<M>
```

`uart_trunc > 0` — обязательный стоп-сигнал кампании: это значит, что пакет
`@FOC` не поместился в буфер и был отброшен целиком.

## 5. Приёмка пакета `ai5/m-opt-0-telemetry` (CONDITIONAL PASS)

Обязательная последовательность, после которой возможен физический baseline:

```text
run_id = M0-R1 … M0-R5                     (каждый прогон — свой id)
map_id = M0                                (из firmware, не из скрипта)
map_crc32 = identical в 5 прогонах          (из firmware)
firmware SHA = identical в 5 прогонах
@RUN:ID ACK = точный (@RUN:ID=<id> в прямом ответе)
@FOC = без усечения (uart_trunc=0)
CRLF = присутствует в каждой строке
no-HV VBUS gate = PASS (median ≤ 9, max ≤ 200)
```

До закрытия бюджета `@FOC` железный прогон `M0-R1…M0-R5` не начинать.
