# Офлайн-анализ разрешимости Ls

Пакет не включает подачу энергии, firmware-хуки или работу со стендом. Он отвечает на два отдельных вопроса: достаточно ли информационного бюджета для различения заданного диапазона `Ls`, и соответствует ли уже полученный лог `idle/pairs` объявленным критериям проекта.

## Бюджет наблюдаемости

```bash
python tools/ls_observability_budget.py \
  --log ls_run.log \
  --vstep-mv 100 \
  --tstep-us 10 \
  --ls-min-uh 500 \
  --ls-max-uh 500000 \
  --json ls_budget.json
```

Входной лог должен содержать строки `@AT:LS:FRAME` (или совместимый `@LS:FRAME`) с полями `i1` и `i2`. `vstep` и `tstep` можно передать явно либо дать в кадрах как `vstep_mv`/`tstep_us`. Оценка шума берётся из всех найденных кадров; JSON сохраняет число кадров, диапазон строк, `SD(i1)`, `SD(i2)`, эффективный `SD(Δi)` и реальный 1 LSB DC-link-шунта из `src/adc.h`.

Вердикт является только бюджетным: `DISCRIMINABLE`, `NOT_DISCRIMINABLE_WITH_THIS_NOISE` или `INSUFFICIENT_INPUT` (последний реализуется как exit 2 при неполном входе). Инструмент не выдаёт измеренное значение `Ls`.

## Независимый разбор idle/pairs

```bash
python tools/autotune_idle_analyzer.py \
  --log idle_pairs.log \
  --json idle_analysis.json
```

Парсер требует повторяемые точки `@IDLE:PROG=...:D=...:I=...:L=...:REP=...`, минимум пять повторов на duty и минимум две точки кривой. Для `pairs` требуется ровно три уникальные валидные катушки. Анализатор сохраняет всю кривую `Ls(I)`, медианы по валидным точкам, spread, асимметрию и причины отброшенных данных.

Проверяются `SPREAD_HIGH` при spread не менее 15%, `ASYM_HIGH` при асимметрии не менее 10%, `LS_RISES_WITH_I`, `LS_ZERO` с перечнем возможных причин и `ISAT_UNREACHED`, который не является ошибкой сам по себе. Обрезанный или несогласованный лог даёт exit 2 и не получает verdict; `Ls` не выдаётся при `VALID < 3`.

## Границы доказательств

Эти инструменты не измеряют двигатель, не включают PWM и не проверяют safety. Они не доказывают абсолютную точность ADC, фазовую референцию `y`, готовность карты, корректность силовой схемы, `Lm`, `Rr`, `Tr` или пригодность работы на 60 В. Синтетический `PASS` подтверждает только работу анализатора и не является стендовым PASS.


## Интеграционные правки от 20.09.2026 (ПК-2) и результат на РЕАЛЬНОМ логе

Проверено на возврате `ls` x3: `ls_acceptance_return_20260920_c/logs/ls_x3.log` (180 кадров;
формат `@AT:LS:FRAME:d=..:n=..:ph=..:t=..:I1=..:I2=..:Idiff=..:Vbus=..:CCR1=..:CCR8=..` —
совпадает с прошивочным, строка `src/autotune.c` в ветке `ai2/tz2-ls-standstill-step`).

Исправлено при интеграции — все четыре дефекта найдены на реальных данных, не на синтетике:

```text
1. ШУМ МЕРИЛСЯ ПО ВСЕМУ ЛОГУ: уровни d=5/10/15 % и фазы ph=0/1 дают СИГНАЛЬНЫЙ разброс, порог
   завышался (на этом логе 308.56 мА). Теперь шум — пул ВНУТРИ блоков (d, ph), шумовой пол —
   по блокам ph=0 (нулевой вектор); оценка по всему логу запрещена (только явным
   --allow-ungrouped-noise с пометкой UNRELIABLE). Есть явный --sd-ma с указанием источника.
2. MONTE-CARLO МОЛЧА ОТБРАСЫВАЛ неположительные оценки (1023/2000) — выживальческая ошибка,
   занижавшая ширину интервала. Теперь печатаются non_positive_fraction и reliable=false
   при превышении объявленной доли (--mc-max-nonpositive).
3. required_sd ИГНОРИРОВАЛ ПОЛ КВАНТОВАНИЯ. 1 LSB = 12.7914 мА — совпадает с прошивкой
   (ADC_VREF_MV=3300, ADC_MAX_CODE=4095, ADC_DC_SHUNT_UV_PER_A=63000; src/adc.h:7-14,
   src/adc.c:74-75). Теперь quantization_limited=true и required_sd=null, если цель
   недостижима в принципе, вместо недостижимого числа.
4. LS_ZERO НЕ МЕШАЛ ВЕРДИКТУ PASS — нулевая кривая (то есть ОТСУТСТВИЕ измерения) проходила как
   успех. Теперь LS_ZERO => REJECT; причины остаются перечнем, без выбора одной «наугад».
```

### Бюджет на реальном логе (z=3; объявленные vstep/tstep — снаружи, в кадре их нет)

| блок ph=0 | n | SD эффективный, мА |
|---|---:|---:|
| d = 10 % | 12 | 38.06 |
| d = 15 % | 12 | 86.74 |
| d = 5 % | 12 | 151.52 |

```text
пул внутри блоков: SD(i1)=55.39 · SD(i2)=87.04 · эффективный 103.17 мА · 1 LSB = 12.79 мА
порог = max(z·SD, 1 LSB) = 309.51 мА
ВЕРДИКТ: NOT_DISCRIMINABLE_WITH_THIS_NOISE (для sane-окна 500…500000 мкГн КАК ЦЕЛОГО)
различимый диапазон при d=15 %, tstep=100 мкс: 500 … 2812 мкГн   (при d=5 % — только 500 мкГн)
required_sd = null · quantization_limited = true
  верх sane-окна недостижим В ПРИНЦИПЕ: чтобы 500 мГн дали 1 LSB при 9186 мВ, нужна ступень
  ~16.8 мс (U·t = 1.55e8 мВ·мкс), а не улучшение шума
Monte-Carlo: non_positive_fraction ≈ 0.48…0.49 · reliable=false · CI95 ширина/окно = 0.23…1.05
```

Числа, на которых строятся выводы:

```text
· шум ЗАВИСИТ ОТ УРОВНЯ: 38 мА (d=10 %) против 151 мА (d=5 %) — единого шумового пола у тракта нет;
  лучший блок (38 мА) согласуется с независимой оценкой B1 (~36 мА), что подтверждает корректность
  внутриблочного способа и ошибочность прежнего (по всему логу);
· разрешима только нижняя часть sane-окна (~0.5…2.8 мГн); верх ограничен КВАНТОВАНИЕМ, а не шумом —
  усреднение там не помогает, помогает только рост U·t (длительность/напряжение ступени);
· MC-инверсия при таком шуме вырождена: половина оценок неположительна, reliability=false.
```

Чего это НЕ доказывает: что Ls нельзя измерить вообще (инструмент считает бюджет, а не измеряет);
что при разрешённой энергоподаче получится верное значение; что тракт достаточен для карты FOC.
Стендовая часть E1..E6 и вопрос выбора метода остаются открытыми — бюджет лишь сужает выбор числами.
