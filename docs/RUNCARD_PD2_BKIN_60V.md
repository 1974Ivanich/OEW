## Два разных break-события: класс A ≠ класс B

Порядок полей в `@BRK` (`src/cli.c:264`): `sr=<TIM1>,<TIM8>`, `sd=<SD1>,<SD2>`, `bd=<TIM1>,<TIM8>`,
`ce=<TIM1>,<TIM8>`, `cnt=<TIM1>,<TIM8>`. `BIF` — бит 7 (`0x80`) каждого `SR`.

| Класс | Логи | `sr` TIM1,TIM8 | `bd` | `ce` | `cnt` |
|---|---|---|---|---|---|
| **A — break в работе ШИМ** | u8, u31 | `3001F`, `300DF` | `9CC0`, `1CC0` | `555`, `555` | 243 / 402 |
| **B — до запуска ШИМ** | u20, u26 | `1`, `81` | `1CC0`, `1CC0` | `0`, `0` | 0 / 0 |

Класс A: `BIF` взведён **только у TIM8** (у TIM1 бит 7 = 0), `MOE` у TIM1 ещё поднят
(`bd` TIM1 = `9CC0`), у TIM8 уже снят (`1CC0`) — асинхронный hardware break по `TIM8_BKIN`,
в середине PWM-периода (`ARR=999`, center-aligned, 5 кГц).

Класс B: `ce=0` и `MOE=0` у обоих таймеров — снимок снят при незапущенных таймерах.
Это BKIN низкий на фронте `PWM_Init()` (BKE выставляется там же, `src/pwm.c:296`), а не
событие V/f 60 В. В u20/u26 `breakdiag` — первая команда лога, то есть остаток предыдущего
пуска. `@BRK:RESET:rc=0` (u28) — сброс диагностики, а не событие.

> **Прогон A обязан воспроизвести именно класс A.** Получен класс B (`ce=0,0` / `cnt=0,0`)
> — остановиться, записать в `metadata.txt` «class B, capture неинформативен» и не считать
> это успешным прогоном A. Класс B нельзя использовать как доказательство OCP при 60 В.

## Шаг 0 — подтяжка PD2 (без высокого напряжения, до прогона A)

На BKIN **нет внутренней подтяжки MCU**: `src/pwm_board_pins.c:30` явно чистит `PUPDR`
(«no MCU pull on external SD net»), пин в AF-режиме. Высокий уровень держит **только внешняя
подтяжка на стороне STEVAL-2** (в `pinout.md:58` для SD1 назван R28; для SD2/PD2 точка
подтяжки в репозитории не указана — уточнить по схеме платы). Отсюда проверка, которая
ничего не стоит и не требует силовой части:

1. STEVAL-2 полностью обесточить (силовая и логика).
2. Мультиметром: **PD2 (TP23) → GND**, зафиксировать число.
3. Прозвонить шлейф SD2 (разъём → дорожка → ножка MCU).

```text
STEVAL-2 обесточен ──подтяжка на стороне платы──► PD2 ≈ 3.3 В
```

| Результат | Вывод |
|---|---|
| PD2 ≈ 3.3 В | подтяжка цела; класс B — артефакт последовательности включения, идём к прогону A |
| PD2 < 2 В или «плывёт» | обрыв шлейфа / нет подтяжки / сажает сам узел. Сначала чинить это: без этого прогон A бессмысленен |

Число (В) и вердикт шага 0 обязательны в `metadata.txt`.

## Разводка

Основные измерения — **аналоговым осциллографом TAO3104A**, не логическим анализатором:
порог цифрового входа LA (~1.6 В) и верхний порог переключения GPIO G4 близки, поэтому
«чисто на LA» не является доказательством отсутствия импульса.

| Канал | Точка | Прибор | Зачем |
|---|---|---|---|
| CH1 | **PD2 / TIM8 BKIN как можно ближе к ножке MCU** (TP23 на плате) | TAO, аналог | что реально приходит на BKIN |
| CH2 | **SD2 на стороне STEVAL-2** (FAULT-выход) | TAO, аналог | дёргает ли FAULT сам IPM |
| CH3 | **DC-link VBUS на силовой части, щуп 10:1** | TAO, аналог | реален ли выброс ~91 В |
| CH4 | **SD1** (PB12-сторона) | TAO, аналог | бьёт ли когда-нибудь первый инвертор |

### CH3 VBUS — решение принято: сторона DC-link, щуп 10:1

Мерить на **стороне высокого напряжения** (колодка питания / конденсаторы DC-link), коэффициент
щупа **10:1**, вертикальная шкала — прямо в вольтах. На **PC4 не вешать**: там VBUS через делитель
1:125 (`src/adc.c:12`, `ADC_VBUS_DIVIDER`), т.е. 60 В = 0.48 В, и транзиент в несколько вольт на шине
превращается в десятки милливольт — разрешение не позволит его увидеть.

**Обязательное подтверждение перед подачей 60 В** (иначе — КЗ по земле осциллографа):

1. Всё обесточить.
2. Прозвонить мультиметром **минус DC-link ↔ земля ПК/земля корпуса TAO3104A**. Связь обязана быть
   непрерывной (оммы, не «сотни килоом через изоляцию»).
3. Если continuity **не** подтверждена — CH3 не подключать к минусу шины вообще; варианты:
   дифференциальный/изолированный щуп, либо перенос CH3 на PC4 как сознательно грубого маркера.
4. «Крокодил» щупа — только на подтверждённую минусовую точку, одну и ту же во всех прогонах.
5. Повторить ровно ту же точку, что в `sd_cap4` (`A3 VBUS`), иначе новый захват несопоставим с историческим.

**Маркер момента команды уже есть в прошивке — менять её не нужно.** `PB6` (`TRIGGER_PIN`,
`src/pwm_board_pins.c`) поднимается `trig_high()` ровно в момент обработки `vf=<rpm>` и опускается
при `vf=0` (`src/cli.c:451`, там же печатается `@TRIG:tick=`). Это готовый аппаратный триггер и для LA,
и для осциллографа: **фронт на PB6 = момент команды**, с точностью до такта, без ручного запуска вслепую.

Логический анализатор — цифровой дубль, ровно **4 сигнала на `D0–D3`**:

| LA | Сигнал | Роль |
|---|---|---|
| `D0` | **PB6 (TRIG)** | фронт вверх = момент `vf=`; он же источник запуска LA |
| `D1` | PD2 / BKIN у ножки MCU | искомый импульс |
| `D2` | SD2 на плате STEVAL-2 | дёргает ли FAULT сам IPM |
| `D3` | **PC6** = TIM8_CH1 (HIN U, AF4) | маркер «ШИМ жив» (гибель ШИМ видна как пропадание меандра) |

Нога `D3` — **PC6** (`src/pwm_board_pins.h:9`: `TIM8 PWM: PC6/PC7/PC8 = CH1/2/3 AF4`). Номер разъёма
на колодке Nucleo по репозиторию не восстановить — взять из схемы платы и прозвонить со следом на
ноге MCU **до** подключения. LA — только параллельно дорожке: PC6 идёт напрямую на вход INV2.

- `sigrok-cli --driver fx2lafw --config samplerate=24MHz --channels D0/D1/D2/D3 …`
- 24 МГц доступны **только в 8-канальной конфигурации** (`D0–D7`). Прежние захваты писались в
  `Channels (13/16)` @ 8 МГц — в 16-канальном режиме 24 МГц недостижимы, каналы сверх четырёх не включать.
- `EN1/EN2` (PB4/PB5) в каналы **не** брать: они штатно снимаются в `PWM_Disable` и дают ложную «гибель PWM».

## Прогон A — single-shot по фронту

Триггер: **falling edge на CH1 (PD2)**, обычная (не auto) развёртка, single-shot, memory depth на весь буфер.

1. Поднять 60 В, `f` (снять latch), дождаться `@BRK:RESET` / чистого состояния.
2. Вооружить осциллограф в single.
3. Подать `vf=40`, одновременно вести UART-лог в файл.
4. После срабатывания — не трогать конфигурацию, сразу сохранить waveform + uart-лог.

Срабатывание A = «импульс существует». Сохранить: уровень, до которого провалился PD2, длительность,
положение относительно CH2 и CH3.

## Прогон B — запуск по моменту команды (обязателен, даже если A сработал)

Нужен, чтобы отрицательный результат A не превратился в ложное «ничего не было»: при чистом PD2
триггер по фронту на PD2 не сработает никогда, и без B нельзя отличить «импульса не было» от
«не туда смотрели».

1. LA: запуск по **rising edge на `D0` (PB6)**, post-trigger 20–50 мс, pre 1–2 мс. Осциллограф:
   5-го канала у TAO3104A нет (прибор 4-канальный, все заняты), а источник single-edge триггера
   по протоколу прибора **не переключается с CH1** (`SOURce CH2` → `SOURce?` остаётся CH1 —
   проверено в `tools/OWON_TAO3104A_PROTOCOL.md`). Поэтому TAO в прогоне B — в single по CH1 (PD2)
   либо с ручным запуском непосредственно перед командой; сам момент команды фиксируют LA (`D0`)
   и `@TRIG:tick` в uart-логе.
2. Порядок: `f` (снять latch) → вооружить LA и TAO → подать `vf=40`. Фронт PB6 возникнет сам,
   внутри обработки команды, отдельных действий не требуется.
3. В uart-логе тем временем появятся `@TRIG:tick=…` (тот же момент), строки `@VFLOG` и, при событии,
   `@BRK`. Свести по времени: PB6-фронт ↔ `@TRIG:tick` ↔ последняя активность ШИМ на `D3` ↔ `@BRK`.

У `fx2lafw` нет внешнего и последовательностного триггера, поэтому «запуск от команды» = трассировка
самого PB6 как одного из каналов; это штатный сигнал прошивки, а не самоделка.

## Что зафиксировать из телеметрии (штатными средствами, без новой прошивки)

- `@BRK:…:bd=%lX,%lX` — полный BDTR обоих таймеров. `BDTR` пишется только в `PWM_Init`, поэтому `bd=`
  после события доказывает `BKF=0` (`BDTR[19:16]=0`) для всего прогона. Отдельная печать BDTR не нужна.
- `@BRK:…:cnt=%u,%u` и `cyc=%lu` — фазовая привязка break к точке PWM-периода. Заносить в каждую строку
  журнала прогона: стабильное `cnt` = событие синхронно переключению вектора; разбросанное = случайный глитч.
- `@VFLOG:…vbus=…` — **сырой код АЦП, не милливольты** (`ADC_GetRawVbus()`); милливольты — только
  `VBUS=%ld` в `@FOC`. Скачок 610→910→604 raw ≈ 61→91→61 В по калибровке делителя, не путать единицы.

## Decision tree: H1 / H2 / H3

Гипотезы — это имена трёх веток таблицы ниже, не новые категории.
Порядок проверки фиксирован: сначала покрытие, затем PD2, затем сравнение с CH2.

```text
0. Класс события = A?  (нет, ce=0,0 / cnt=0,0 → НЕ вердикт, прогон неинформативен)
1. Окно покрывает событие?  (нет → НЕ вердикт: нет @TRIG:tick, нет гибели ШИМ на D3, нет @BRK)
2. CH1 (PD2) проваливается?
   ├─ да  → 3. CH2 (SD2) проваливается одновременно?
   │        ├─ да  → H1 Real OCP: FAULT действительно генерит IPM
   │        └─ нет → H2 наводка/монтаж на пути SD2→PD2 (прошивка видит то, чего на плате нет)
   └─ нет → H3 BIF без драйва на BKIN: питание/земля MCU, подтяжка,
              входная структура ножки, ложный BIF внутри таймера
```

| Гипотеза | Признак | Следующий шаг (не в этом прогоне) |
|---|---|---|
| **H1 Real OCP** | CH1 провал, CH2 провал одновременно | смотреть CIN/даташит IPM, снижать команду; потом сравнение BKF |
| **H2 Glitch/EMI** | CH1 провал, CH2 чист | монтаж шлейфа, подтяжка, разводка; потом сравнение BKF |
| **H3 No-drive BIF** | CH1 чист при покрытом событии | электрический путь к BKIN; IPM-OCP теряет приоритет |

**Ограничение разводки.** Для прямого подтверждения H1 (Real OCP) нужно видеть, что ток
инвертора действительно превысил порог, — то есть канал Tok. В текущей 4-канальной разводке
(§«Разводка») **CH4 = SD1, а Tok не снимается ни на одном канале**. Поэтому H1 подтверждается
только косвенно — по совпадению провалов CH1 (PD2) и CH2 (SD2) — без прямого измерения тока.
Нужен ли 5-й канал под Tok (или замена CH4 = SD1 на CH4 = Tok) — выносится в вопросы по стенду,
а не решается по умолчанию.

## Классификация результата (H1/H2/H3; писать именно так, три случая не смешивать)

| Вердикт | Признак | Что это значит / следующий шаг |

| **импульс обнаружен** | CH1 проваливается | сравнить с CH2: одновременно → FAULT-OCP IPM, смотреть CIN/даташит и снижать команду; CH2 чистый → путь SD2→PD2 (монтаж, подтяжка, наводка) |
