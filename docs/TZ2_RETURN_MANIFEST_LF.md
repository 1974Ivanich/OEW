# Hygiene finding: переводы строк в манифестах возврата (`SHA256SUMS.txt`)

Статус: **hygiene-находка, отдельная от calibration-governance** (addendum C). Не изменяет
ни протокол сессии, ни intake-правила; закрывает переносимость проверки целостности.

## Наблюдение (факт со стенда)

Первый возврат ПК-3 (`E:\pc3_identity_20260918\`) пришёл с манифестом, записанным **CRLF**.
В POSIX-окружении штатная сверка падает на каждой строке:

```text
$ sha256sum -c SHA256SUMS.txt
sha256sum: 'flash_dump.bin'$'\r': No such file or directory
flash_dump.bin\r: FAILED open or read
```

Инструмент intake (`tools/identity_intake_check.py`) строки триммит, поэтому его вердикт
корректен (I1 PASS, 3 записи). Но **любая независимая проверка на POSIX-машине** ломается:
файл с завершающим `\r` в имени не существует, и результат выглядит как «пакет битый»,
хотя содержимое целое.

## Почему это не косметика

Проверка целостности — часть evidence trail: манифест читают разные инструменты и разные ПК
(`sha256sum`, `certutil`, `Get-FileHash`, python). CRLF делает результат **зависимым от платформы
проверяющего**, то есть создаёт класс «ложный FAIL» и провоцирует сверку «глазами» или
нормализацию руками — ровно то, чего мы избегаем.

## Решение

1. **Инструмент** `tools/verify_manifest.py` — переносимая сверка:
   * терпим к CRLF/CR/mixed, к разделителю из одного/двух пробелов и к бинарному маркеру `*`;
   * сообщает три класса дефектов по отдельности: отсутствующие файлы, несовпавший sha256,
     файлы на диске, **не покрытые** манифестом;
   * `--normalize-lf` переписывает манифест в LF с каноническим форматом `sha256␠␠путь`
     **только если манифест сначала успешно проверен** (сломанный манифест — это дефект
     содержимого, а не переводов строк, и «лечить» его нельзя);
   * коды: `0` — сходится, `1` — нарушение/отказ нормализации, `2` — манифест не найден.
2. **Контракт возврата**: манифест пишется с LF. Нормализация допускается как явная операция
   над **копией** пакета (оригинал возврата не редактируется — тот же принцип, что для raw-логов).

## Проверено фактами

```text
python tools/verify_manifest.py <копия возврата ПК-3>            → MANIFEST PASS, переводы строк: crlf
python tools/verify_manifest.py <копия> --normalize-lf           → crlf -> lf, повторная проверка PASS
sha256sum -c SHA256SUMS.txt (после нормализации)                 → 3/3 OK
оригинал E:\pc3_identity_20260918\SHA256SUMS.txt                 → не изменён (CRLF, sha256 прежний)
```

Тесты: `tests/test_verify_manifest.py` — 13 проверок (CRLF/LF/mixed, форматы строк, три класса
дефектов, нормализация + повторная проверка, отказ нормализации на сломанном манифесте,
JSON-отчёт, явное имя манифеста).

## Что НЕ входит в эту находку

* Правило `I12` и включение `c` в preflight — это calibration governance
  (`ai2/tz2-protocol-calibration`, addendum C). Смешивать нельзя: здесь — переносимость
  проверки целостности, там — prerequisite калибровки.
* Поведение intake-гейта не меняется: он остаётся терпимым к CR (иначе ломался бы на
  исторических возвратах).
