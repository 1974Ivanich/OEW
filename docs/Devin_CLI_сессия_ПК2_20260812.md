# Devin CLI на ПК2 — отчёт о неудачной сессии (12.08.2026)

## 3. Блокеры и обходы (пополнение к чек-листу)

1. **Онбординг при уже выполненном логине** — меню «Connect GitHub as App» вылезает всегда при первом `-p`. Обход: PTY + ↓↓ + **`\r`** (Carriage Return; `\n` из submit() не подтверждает — это была причина «зависания» в прошлой сессии).
2. **Workspace trust** — `Refusing to run in an untrusted workspace`. `respect_workspace_trust: false` в конфиге **не помогает** (проверено: `%APPDATA%\devin\config.json`, не `~/.config/devin/`!). Только интерактивно: `devin` → «Yes, trust ~\...».
3. **Permission mode** — в `-p` по умолчанию write-инструменты **отклоняются**. Нужен `--permission-mode accept-edits` (правки) или `dangerous` (всё). Диагностика цикла отказов: grep по «rejected a tool call».
4. **Производительность** — даже с accept-edits CLI на FREE-плане (модель SWE-1.6 Slow) за 20 минут не выдал ни одной записи: только стартовая строка. Это не зависание — модель просто очень медленная. **Практический вывод: для ревью-задач на ПК2 Devin Desktop в разы продуктивнее** (см. п.1 строка 9).

## 4. Выводы для ПК1

- CLI пригоден только для **коротких** задач (1-2 файла, явная правка) с `--permission-mode accept-edits` и запасом **30+ минут** на модель Slow.
- Для цепочек ревью (несколько модулей, доказательства, правки) — **Devin Desktop** (интерактивное подтверждение, быстрее, видно прогресс).
- Онбординг/trust — одноразовые, после прохождения не возвращаются (у нас уже пройдены на ПК2).
- Если на ПК1 CLI «висит» на меню — это почти наверняка `\n` вместо `\r` (см. п.3.1).
