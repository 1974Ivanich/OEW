# ТЗ: гейт 1 — `dc_current` (первый замкнутый контур по модулю тока), ПК-3

Ветка: `pc3/dc-current-gate`. База: `main` @ `d3bcbc4`.
Источник политики: `docs/TZ_ALIGN_CHECK_AND_TWO_GATE_FIRST_START_PC3.md`, §3 (первый closed-loop —
`dc_current`, затем §4 гейт 2 `dq/foc_current`).
Заявка на файлы: `docs/AGENTS_STATUS.md`.

## 1. Зачем этот шаг

Между «V/f без обратной связи по току» и `dq/foc_current` политика проекта ставит промежуточный шаг:
замкнуть **модуль** тока при **фиксированном** угле вектора напряжения (лестница SimpleFOC:
voltage → estimated_current → dc_current → foc_current). Гейт 1 требует только откалиброванного
масштаба I1/I2 и **не** требует карты реконструкции — именно поэтому он стоит до гейта 2.

## 2. Что установлено чтением кода (10.10.2026, не предположения)

- Путь кадровый: `ADC1_2_IRQHandler` (`main.c:180`) → `adc_dispatch_run(frame)` (`main.c:178`) →
  `FOC_RunFrame(const AdcFrame *frame)` (`src/foc.c:690`). Свежие отсчёты приходят **в кадре**.
- `FOC_RunFrame` **начинается** с `Current_Reconstruct(frame,&phase)` и при отказе вызывает
  `FOC_Stop()`. `Current_Reconstruct` требует доказанной строки карты (`src/current_reconstruct.h`).
  ⇒ Гейт 1 **не может** быть встроен в `FOC_RunFrame`: его погасит реконструкция. Нужен собственный
  потребитель кадра.
- Геометрия шунтов: I1 — фаза U, I2 — фаза V, третья из KCL (так в `TZ_ALIGN_CHECK…`, и это же
  подтвердил опыт `al`: вектор u = −6%, v = w = +3%).
- Армирование (**вектор → `ADC_SetControlAdmission(true)` → `ADC_InjectedStart` → `PWM_Enable`**)
  уже реализовано в `VFC_Start` (`src/vf_control.c:130-166`) и переиспользуемо.
- Базис мостов: TIM1 = PWM mode 1, TIM8 = PWM mode 2; дифференциал образуется **одинаковыми** CCR
  при противоположных режимах (`Vdiff/Vbus ≈ 2·CCR/ARR − 1`).
- Регулярный отсчёт шины во время контроля **портится вверх** (стендовый опыт 10.10.2026: до +58%
  при исправной шине, прибор показывал 59.2…61.6 В). См. §6, вопрос 3.

## 3. Границы (предлагаемые)

| Параметр | Значение |
|---|---|
| DC-link | **≤ 60 В**, предел источника 3 А |
| Вектор | фиксированный угол из разрешённого набора; модуль ≤ 30% VBUS |
| Уставки | 300 / 600 / 1000 мА, по 2 с на уставку |
| Углы | 0° и 90° (по ТЗ-источнику), если §6.2 подтвердит измеримость |
| Не входит | `dq`-контур, карта реконструкции, автотюн, любые изменения admission и протекта |

## 4. Команда и телеметрия (предлагаемые)

```
dc <target_ma> <angle_deg>   → включить и замкнуть |I| по модулю при заданном угле
dc 0                         → снять режим (аналог vf=0)
```

Гарды — **все до поднятия MOE**: `PROTECT_IsFault()` чисто; clock ok; hardware interlock (SD1/SD2,
BIF/B2IF, break-config); VBUS в диапазоне; явное подтверждение оператора о выполненном `al` и
Level-1 (см. §6.1).

Телеметрия: `@DC:i_meas_ma=…:i_target_ma=…:v_alpha=…:v_beta=…:vbus_mv=…:vbus_source=…`
(`vbus_source` — из какого канала взято значение, см. §6.3).

## 5. Критерий приёмки гейта

Устойчивая стабилизация |I| в пределах **±5%** цели в течение 2 с при трёх уставках и двух углах;
знак управления совпадает с ожидаемым (рост уставки → рост модуля тока); катастрофического дрожания
нет. Провал любого пункта → стоп, разбор, возврат к `al`/`ci`.

## 6. Открытые вопросы (решаются чтением кода, не догадкой)

1. **Как в прошивке выражается «Level-1 PASS» и `align=0`.** Если никак — предложить минимальную
   честную форму (например флаг, выставляемый явной командой оператора после `al`) и **не выдавать
   её за автоматическую проверку**. Сейчас `al` вердикта не хранит вовсе.
2. **Измеримость.** При каких углах гарантировано, что обе измеряемые фазы попадают в свои окна
   выборки. Проверять по разводке окон (`src/adc.c`, `src/adc_dispatch.*`), а не предполагать.
3. **Шина во время контроля.** Гард по шине и поле `vbus_mv` опираются на канал, который в контроле
   даёт завышенные отсчёты. Решение: либо брать шину из канала, не конкурирующего с контролем, либо
   явно записать ограничение и **не** делать гард по шине единственной защитой. Связать с
   `docs/TZ_ADC_VBUS_MISMATCH*.md` и `docs/TZ_ADC_REGULAR_READ_WHILE_INJECTED.md`.
4. **Разбивка на пакеты.** Порядок: (а) режим + потребитель кадра + hosted-тесты (независимо
   проверяемо, ничьих файлов не требует) → (б) команда в `src/cli.c` → (в) стендовый опыт.
   Это позволяет не держать `src/cli.c` до готовности всего.

## 8. Тесты и CI

- hosted: PI по модулю, ограничение вектора, отказы гардов, поведение при невалидном кадре.
- CI: триггер **только push в main**, плюс `paths-ignore: docs/**`. Поэтому **до вливания** —
  либо ручной `workflow_dispatch` (клик владельца), либо локальное воспроизведение job'а;
  после вливания — прогон на main. Это не дефект, а осознанное решение проекта (замер в шапке `ci.yml`).
