## Почему карта не собирается (измерено)
`tools/map_artifact_pipeline_cli.exe` → `pipeline failed (status 3, row 2/0)`.
`MapPipelineStatus`: 0 OK, 1 BAD_ARGUMENT, 2 ACCUM_FAILED, **3 SOLVER_FAILED**, 4 CERT_FAILED,
5 BUILD_FAILED. Падает **решатель** на строке sector 2 / window 0.

Решатель (`src/map_measurement_solver.c`) строит по строке матрицу 2×2 `(idc1,idc2) → (refu,refv)`
и гейтит её: `det/(S00*S11) ≥ 10000 ppm`, `trace²/det ≤ 100000`, `|m00|,|m11| ≥ min_abs_diagonal=100`
(в единицах реконструкции), затем невязки rms≤1000, max≤2000, bias≤1000, holdout≤1000, KCL≤100.

Определитель, обусловленность и невязки проходят с большим запасом везде. Упирается в
**порог по диагонали `|m00|,|m11| ≥ 100`**: строка 2/0 даёт m00≈0.10 при единицах
реконструкции порядка 10³ (строка 0/1 идёт на m11≈0.15 и проходит) — то есть значение
**граничное**, а не грубый дефект данных. Физически: для режима sector 2 / window 0 токи
шунтов (idc1,idc2) почти не объясняют измеренные фазы U и V — при той же паре фаз, что и во
всех строках (формат требует одинаковую пару `phase_a/phase_b` для всех строк).

## Что нужно решить (для приёмщика)
1. **Ослабить объявленный порог** `min_abs_diagonal` (сейчас 100 в квалификации кампании) с
   обоснованием — решение приёмочного уровня, а не правка «чтобы прошло».
2. **Пересмотреть выбор пары опорных фаз**: формат датасета запрещает разную пару на строку,
   поэтому «подобрать пару под сектор» нельзя без правки контракта (нужно ТЗ).
3. **Переснять строку** sector 2 / window 0 с другой парой щупов INA240 — пары фаз остаются
   одинаковыми для всех строк, но покрывают другой набор режимов.

Кампания при этом валидна: `ingest_out/{manifest.json,samples.jsonl,scope_omissions.json,`
`campaign_qualification.json}`, `work/dataset.txt` — вход конвейера. Диагностика:
`diag_solver.py`, `diag_m.py`, `diag_region10.py`, `diag_pulse8.py`, `diag_edges.py`.
