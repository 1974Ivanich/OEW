# Отчёт по TZ_ADC_VBUS_MISMATCH.md

## 1. Вердикт по коду

Прошивная часть в порядке:

- `PWM_BoardPins_Init()` (`src/pwm_board_pins.c`, строки 56–78) включает тактирование `GPIOA/C` и переводит `PA0/PA1/PA6/PC4` в аналоговый режим.
- `ADC_Init()` → `ADC_InjectedInit()` (`src/adc.c`, строки 183–261) настраивают ADC2 dual injected, каналы 1/2/3/5, CKMODE=3 (HCLK/4).
- Порядок в `main.c` (строки 497–503): `ADC_Init()` выполняется до `PWM_Init()`, но `PWM_BoardPins_Init()` вызывается внутри `PWM_Init()`, поэтому пины настроены к моменту старта основного цикла.
- Формулы совпадают с ТЗ:
  - `I_mA = (raw − offset) · 3300 · 1000000 / (4095 · 63000)`
  - `VBUS_mV = raw · 3300 · 125 / 4095`
- FAULT_R=18 и отказ `f` при `VBUS=201 мВ` логичны, потому что `PROTECT_RequestClear()` требует `VBUS ≥ 8000 мВ` (`src/protect.c`, строки 177–187).

**Код не виноват. Проблема физическая — сигнал не доходит от разъёма Nucleo до вывода MCU.**

## 2. Корневая причина

Симптомы указывают на разрыв цепи между измерительным проводом и входом АЦП:

| Сигнал | Пин MCU | Разъём Nucleo | Solder bridge | Нужное состояние |
|--------|---------|---------------|---------------|------------------|
| I1     | PA0     | ARD_A0 / CN9-1 | **SB21** — альтернатива User button | **OFF** (default); если ON, PA0 подтянут к VDD, raw=4095 |
| I2     | PA1     | ARD_A1 / CN9-3 | в UM2505 Table 12 не указана | проверить проход до PA1 |
| Ires   | PA6     | ARD_D12 / CN7  | в UM2505 Table 12 не указана | проверить проход до PA6 |
| VBUS   | PC4     | **CN10-34**    | **SB33**      | **ON** — default **OFF**, поэтому PC4 не подключён к CN10-34 |

Источники:
- UM2505 Table 12: SB33 — PC4 ↔ CN10 pin 34, default OFF.
- UM2505 Table 17: PA0 — ARD_A0 / User Button (SB21); PA1 — ARD_A1; PC4 — IO; PA6 — ARD_D12.

Если `Ires` читается ~2048, это подтверждает, что АЦП и прошивка работают, а неисправность — в трассировке/перемычках `PA0/PA1/PC4`.

## 3. Пошаговая диагностика на стенде

> Безопасность: паять при отключённом 60 В. DC-link подаётся только после запайки и прозвонки.

1. **`a=200`** — запустить поток raw. Ожидаемый нормальный ответ при 60 В и нулевом токе:
   ```
   @ADC:I1=2048:I2=2048:Ires=2048:VBUS=595:...
   ```
   - `VBUS` raw ~595 при 0.48 В (60 В / 125).
   - `I1/I2` raw ~2048 при 1.65 В.
2. **Проверить перемычки на обратной стороне Nucleo:**
   - **SB33 = ON** (запаять 0 Ω / каплю припоя). Это главный подозреваемый для VBUS.
   - **SB21 = OFF**. Если ON — убрать, иначе PA0 подтянут к VDD и raw будет 4095.
   - SB12/SB13 (PC4 ↔ USART1 TX) должны быть **OFF**.
3. **Прозвонка континuity** (мультиметр в режиме прозвонки):
   - CN10-34 → вывод PC4 MCU (ножка 22 LQFP-64).
   - ARD_A0 / CN9-1 → PA0 (ножка 12).
   - ARD_A1 / CN9-3 → PA1 (ножка 13).
   - ARD_D12 / CN7 → PA6 (ножка 20).
4. **Проверка напряжения на самом выводе MCU**:
   - PC4 должен быть ~0.48 В.
   - PA0/PA1 должны быть ~1.65 В.
   Если на разъёме правильно, а на выводе нет — проблема в перемычке/трассе.
5. **Проверка регистров в рантайме** (если есть ST-Link / SWO):
   - `GPIOA->MODER` биты 0, 2, 12 = `11`.
   - `GPIOC->MODER` биты 8, 9 = `11`.
   - `RCC->AHB2ENR`: ADC12EN, GPIOAEN, GPIOCEN.
   - `ADC2->JSQR` содержит каналы 2, 3, 5.
   В CLI уже есть `dumpa`, `pdump`, `sysinfo`.

## 4. Исправление

- **VBUS:** запаять **SB33** (PC4 ↔ CN10-34).
- **I1 (PA0):** убедиться, что **SB21 OFF**; проверить ARD_A0/CN9-1 → PA0.
- **I2 (PA1):** проверить целостность ARD_A1/CN9-3 → PA1. Перемычки в UM2505 для PA1 нет, поэтому либо обрыв кабеля, либо провод не в том ряду CN9/CN10.
- **Ires (PA6):** проверить ARD_D12/CN7 → PA6, если raw отличается от 2048.

После исправления `a=200` должен дать:
```
I1≈2048  I2≈2048  Ires≈2048  VBUS≈595
```

## 5. Порядок повторного взвода после FAULT_R=18

1. Включить 3.3 В/15 В логику STEVAL.
2. Подать DC-link с ограничением тока (1–2 А) и плавным нарастанием 0→60 В, чтобы заряд C-банка не просадил 15 В/3.3 В ниже UVLO.
3. Убедиться, что обе SD-линии высокие (`em_stop1=1:em_stop2=1`).
4. Убедиться, что `VBUS` raw ≈ 595 (60 В).
5. `f` — FAULT сбросится.
6. Только после этого можно `1` / `vf=...`.

Если UVLO всё равно срабатывает — использовать внешний precharge (резистор + реле) или взводить DC-link с токоограничением.

## 6. Примечание

Этот отчёт — только документация. Изменений в исходный код не внесено. Если после запайки SB33 и прозвонки `a=200` всё ещё не сходится, следующий шаг — добавить диагностический dump `GPIOA->MODER`, `GPIOC->MODER`, `RCC->AHB2ENR` в CLI и зашить.
