# AGENTS_WORKFLOW.md — правила работы (упрощено 28.08.2026)

Проектом работают агенты на 3 ПК. Главное — **скорость и результат**, не процесс.
Основной remote — **GitHub** (`origin`, 1974Ivanich/OEW), CI — **GitHub Actions**.

## 1. Единственный источник правды — main на GitHub

- **Рабочий поток:** правь, коммить, пуши в `main` напрямую.
- Одна ветка на задачу — **только** если задача крупная (несколько дней,
  несколько файлов) или требует итераций с проверкой.
- Именование веток (если нужны): `ai<N>/<кратко>`.
- Перед push в main: `git pull --rebase` (свежий main) — конфликты решает автор.

## 2. Публикация

```bash
git push origin main            # или ветку
git ls-remote origin refs/heads/main   # подтверждение SHA (если нужно)
```

Проверка SHA — только при споре/приёмке крупного пакета. Для рутины не требуется.

## 3. Приёмка (только для крупных пакетов)

- **Критерий приёмки — зелёный CI на ветке.** Всё остальное — слова.
- Приёмщик (Hermes ПК-1): `git merge --no-ff <ветка>` в main + push.
- Для мелких правок (доки, фиксы, одна функция) — приёмка не нужна, прямой push.
- Никаких worktree, py_compile, проверок CRLF, diff --check — CI сделает своё дело.

## 4. Самопроверка агента

- Перед push: `make && make test` — если правка касается кода (не доков).
- Всё остальное проверит CI. Не дублируй CI вручную.

## 5. CI (GitHub Actions, .github/workflows/ci.yml)

- **CI на main — обязателен зелёным** перед прошивкой/приёмкой крупного.
- CI на ветках — по желанию, не блокер.
- **Официальный образ — артефакт зелёного CI на main** (`firmware.bin/.elf/.map`).
  Для стенда допустимо использовать локальную сборку при недоступности CI
  (SHA фиксировать в отчёте), но образ main — приоритет.

## 6. Координация

- **`docs/AGENTS_STATUS.md`** — одна строка на активную работу (кто/что).
  Пишется перед началом, обновляется по завершении. Не раздувать историей.
- Зоны ответственности — как раньше (main.c/cli — интегратор; safety-модули
  по согласованию).

## 7. Запреты (жёсткие, немного)

- Не менять default-deny (`OEW_MAP_CAPTURE`/`OEW_MAP_L3`/`RELEASE`) без явного
  согласования.
- Не пушить секреты и стендовые артефакты (RECORD.csv и т.п.).
- Не переписывать запушенную историю без нужды.
- Safety-approval **не существует** (убрано 28.08.2026): стендовые этапы
  (Test №2/3, Stage A, снятие карты) выполняются по обычной процедуре,
  оператор отвечает за безопасность по локальной практике.
