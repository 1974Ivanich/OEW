# Тестовый план для ветки ai2/vf-overshoot-stability (ПК-2)

## Цель
1. Уменьшить overshoot при разгоне V/f до <=10% от целевой скорости (целевая 300 rpm -> максимум 330 rpm).
2. Обеспечить стабильную эмиссию @VFLOG: непрерывный поток ~200 кадров за 8 секунд (частота ~25 Гц) без обрывов.
3. Сохранить fault=0 во всех тестах.

## Оборудование
- Стенд v6, напряжение 60 В
- Двигатель с энкодером AS5048A
- Подключение PB12/PD2 к осциллографу/ЛА для проверки BKIN и fault
- UART телеметрия с логированием @VFLOG

## Этапы тестирования

### 1. Базовый тест (без изменений)
- Запушить текущую ветку ai2/vf-overshoot-stability (которая пока равна main после merge трёх веток).
- Выполнить 10 запусков V/f с vf=300, 8 с, 60 В.
- Записать max_meas, t_spin, среднее число кадров @VFLOG за 8 с, наличие fault.
- Ожидаем: overshoot ~298% (как ранее max_meas 1195), обрывы @VFLOG в 8/10 запусков.

### 2. Внедрение регулирования overshoot
- В src/vf_control.c добавить ограничение выходного напряжения V/f в зависимости от ошибки скорости (PI регулятор скорости с анти-windup).
- Пример: если measured > target * 1.1, то уменьшить vmag или увеличить boosting отрицательно? (Требует обсуждения, но для теста можно просто жёстко ограничить vmag в процентах).
- Собрать и прошить.

### 3. Тест после внедрения регулирования overshoot
- Повторить 10 запусков.
- Записать те же метрики.
- Цель: max_meas <= 330 rpm, @VFLOG стабилен (200±20 кадров за 8 с), fault=0.

### 4. Стабилизация @VFLOG
- Если после регулирования overshoot эмиссия всё ещё нестабильна, проверить:
  - Приоритет UART передач в прерываниях (не блокируются ли длительными вычислениями).
  - Размер буфера UART TX и обработку прерывания TXE.
  - Возможно, добавить таймаут Watchdog для восстановления UART при зависании.
- Внести правки в src/uart.c и/main.c при необходимости.
- Повторить тесты.

### 5. Итоговая приёмка
- После достижения целевых показателей подготовить запрос на merge:
  - Запушить ветку на GitHub.
  - Подтвердить публикацию через `git ls-remote origin ai2/vf-overshoot-stability`.
  - Обновить AGENTS_STATUS.md: перевести задачу в «ждут приёмки» после успешного CI и стендовых тестов на ПК-2.
  - Уведомить приёмщика (ПК-1) для проведения финальной проверки на стенде v7.

## Критерии успеха
- Оvershoot <=10% (max_meas <= 330 rpm при целевой 300 rpm).
- @VFLOG emits непрерывно ~200 кадров за 8 секунд (допустимо ±20 кадров) в 10/10 запусков.
- fault=0 во всех запусков.
- hosted V/f тесты: ALL PASS.
- QEMU V/f тесты: ALL PASS.
- CI зелёный.
