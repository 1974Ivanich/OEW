## 3. Диагноз CT-канала (PA6 / ADC2_IN3) — уточнено пользователем
- `raw_ct=0` стабильно — **это штатное поведение подключения**: CT подключён напрямую к PA6, БЕЗ ОУ (в отличие от I1/PA0 и I2/PA1, которые идут через ОУ со смещением ~1.65 В). При нулевом токе на PA6 реально 0 В → raw=0. Это НЕ обрыв.
- Программная часть АЦП работоспособна: `JSQR=0x00A18482` (каналы 2/3/5), `GPIOA pin6` analog-режим, ADEN=1, VBUS-канал читается (DR≈598).
- **`protect.c` не использует `raw_ct`/`ict_ma`** — CT/Ires НЕ участвует в защите (защита по I1/I2/VBUS).
- **Мнимая «проблема» — программное требование прошивки**: `adc_frame_status()` (adc.c) считает raw_ct на краях шкалы (`<=1` / `>=4094`) насыщением кадра (`ADC_FRAME_ADC_SATURATED`) и блокирует контрольную admission, хотя для диагностического CT (zero-sequence) raw=0 при нуле токе — корректное значение.
- **Квалификация CT = решение для этой топологии**: либо аппаратно довести сигнал до биполярного (добавить ОУ/смещение 1.65 В), либо программно разрешить «0-уровень» для Ires (канал не участвует в защите) — по согласованию с приёмщиком, fail-closed для I1/I2/VBUS сохраняется.
- **Fail-closed сейчас работает**: Ires не квалифицирован → `offsets_valid=0` → FOC `rc=-2 map_unverified`; energise заблокирован. Это заложенное поведение, но причина — топология, а не обрыв.

## 4. Что дальше (energise)
1. **Решение по квалификации CT (два пути, согласовать с приёмщиком):**
   - **Аппаратный**: добавить смещение ~1.65 В на PA6 (ОУ/делитель), чтобы нулевой ток давал raw≈2048 — тогда калибровка пройдёт штатно;
   - **Программный**: в `adc.c` разрешить диагностический нулевой уровень Ires (канал не участвует в защите по `protect.c`) при сохранении fail-closed для I1/I2/VBUS — это новое ТЗ (safety-модуль).
2. После квалификации: `c` → offsets валидны, `f`→STATUS=0 (если latch), energise по BENCH_FIRST_SESSION §5 (DC-link 60 В с токоограничением).
