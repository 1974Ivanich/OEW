# ТЗ: align-check (команда `al`) и первый closed-loop FOC-пуск в два гейта (ПК-3)

Ветка: `ai2/shunt-cal-campaign-v1`. Реализация в этой ветке: PWM-апертура
`PWM_AlignAperture*` (`src/pwm.c`), команда **`al`** (`src/cli.c`), тесты
`tests/pwm_align_test.c`, `tests/cli_test.c`, `tests/bench_aperture_test.c`.

Источник рецепта — SimpleFOC (MIT, docs.simplefoc.com): `driverAlign()` подаёт
известный вектор напряжения на каждую фазу неподвижного ротора и сверяет
направление тока. Это ловит два класса ошибок тракта тока: **перепутанные
каналы** (I1/I2 инвертированы местами) и **инвертированный знак gain**.
Лестница torque-режимов SimpleFOC: voltage → estimated_current → dc_current →
foc_current; dc_current управляет **модулем** тока без dq-реконструкции, то есть
требует только откалиброванного масштаба I1/I2 (наш Level 1), и потому легитимен
как первый closed-loop гейт до qualification реконструкции (Level 2+).

## 1. Команда `al`: report-only align-check

```text
al → гард: FOC/Vf не активны (иначе err: stop FOC/Vf first); останов - `al off`
   → апертура недоступна (default-deny сборка) → err: al unsupported
   → PWM_AlignApertureStart(999): TIM1+TIM8 center-aligned, 10 кГц, MOE=0, CCER=0
   → admission (тот же гейт, что PWM_Enable): PROTECT fault, clock fail,
     hardware interlock (SD1/SD2 + BIF/B2IF + break-config), ADC arming -
     проверяется ДО MOE и ПОВТОРНО после его подъёма; при отказе - Stop
   → PWM_AlignApertureSetVector: дифференциальный вектор в production-базисе
     (TIM1 = PWM mode 1: avg ~ CCR/ARR; TIM8 = PWM mode 2: avg ~ 1 - CCR/ARR;
     Vdiff/Vbus ~ 2*CCR/ARR - 1 при одинаковых mid-scaled CCR):
        TIM1: CCR1=470, CCR2=515, CCR3=515
        TIM8: CCR1=470, CCR2=515, CCR3=515
     (u = -6%, v = w = +3% от VBUS; фаза U ниже V/W)
     MOE=1, CCER=все шесть каналов
   → @AL:OK:code=0:u=…:uu=…:v=…:vv=…:w=…:ww=…:i1_ma=…:i2_ma=…:align=0 (1=v1_rev 2=v2_rev 3=both; report-only)
```

Физика вектора: TIM1 настроен в PWM mode 1, TIM8 — в PWM mode 2, поэтому
**дифференциальная составляющая создаётся ОДИНАКОВЫМИ CCR на обоих таймерах**
(зеркальные CCR при противоположных режимах, наоборот, дают ~0: именно эта
ошибка была в первой реализации `4cd540f`). При mid-scaled CCR:
`Vdiff/Vbus ≈ 2·CCR/ARR − 1`. Вектор `u = −6%, v = w = +3%` (сумма ≈ 0, ротор
неподвижен): TIM1=TIM8 = 470/515/515 при ARR=999, PSC=16, счётчик 10 МГц,
f_PWM = 10МГц/(PSC+1)/(2·(ARR+1)) = **5 кГц** — та же частота, что и
production-путь (identity 5000 Hz). Ток течёт через обмотки U-V/U-W, шунты
фаз U (I1) и V (I2) его видят; ротор не должен провернуться (проверяется
оператором по оси/метке).

Интерпретация (оператор, offline; **прошивка вердикт не выносит и коэффициенты
не принимает** — политика репо):

| Наблюдение | Вывод | Код |
|---|---|---|
| i1_ma и i2_ma положительные (по модулю близки) | тракт согласован | 0 |
| один из токов отрицательный при ожидаемом направлении | инвертированный gain канала | 1 (v1_rev) / 2 (v2_rev) |
| оба инвертированы | оба gain инвертированы | 3 (both) |
| ток ≈ 0 при подтверждённом напряжении | канал не тот (перепутаны ADC-пины) | 0 + отдельное расследование |

Отчёт-only: прошивка **не меняет** `ADC_DC_SHUNT_UV_PER_A`, не пишет offsets и
не «чинит» ничего автоматически. Решение — по данным, отдельным ТЗ.

## 2. Апертура: физика и fail-closed

`PWM_AlignApertureStart/SetVector/Stop` (`src/pwm.c`):

- admission как у `PWM_Enable` (любой путь, поднимающий MOE, обязан его
  проходить): `arr != 0`, PWM выключен, ADC injected не заряжен,
  `PROTECT_IsFault()`, `g_clock_fail`, `PWM_HardwareInterlockHealthy()`
  (SD1/SD2 high, BIF/B2IF чистые, break-config валиден); повторная проверка
  fault/interlock ПОСЛЕ подъёма MOE, при отказе — немедленный Stop; всё под
  `__disable_irq`/восстановление PRIMASK;
- Start: останавливает счётчики, `CCER=0`, `MOE=0` (выхода нет до вектора),
  `ADC_SetControlAdmission(false)`, `PWM_InvalidateSampleContext()`, настраивает
  PSC/ARR/CNT, EGR_UG, включает UIE и `ADC_InjectedStart()`; при отказе ADC —
  полный откат и `-1`;
- SetVector: только в активной апертуре, CCR в пределах ARR, затем CCER/MOE;
- Stop: гасит CEN/DIER/CCER/MOE, `ADC_InjectedStop()`, сброс admission/context —
  вызывается CLI до/после и при отказах, а также явной командой `al off`;
  состояние после Stop эквивалентно состоянию до Start. Вектор не остаётся на
  выводах между командами оператора.

Default-deny: **без** `OEW_HS1_COMMISSIONING_RELEASE=1` функции существуют, но
fail-closed — Start → `PWM_ENABLE_INTERLOCK_OPEN`, SetVector →
`PWM_ENABLE_CONTEXT_INVALID`, Stop → no-op. В bench (no-output) образе
(`OEW_BENCH_APERTURE=1`, MOE принудительно низкий) align-апертура не
компилируется вовсе — `tests/bench_aperture_test.c` фиксирует, что стабы
fail-closed и выход не поднимается.

Код в бинарнике: штатный образ ПК-3 собирается с
`OEW_HS1_COMMISSIONING_RELEASE=1` (ci.yml:63) — апертура присутствует; её
безопасность та же, что у bench-апертуры: короткая сессия, ручной Stop,
гарды PWM/ADC/PROTECT на входе.

## 3. Гейт 1: первый closed-loop — dc_current (модуль тока, без dq)

Цель: замкнуть ток по **модулю** I = f(I1, I2) при фиксированном векторе
напряжения — рецепт dc_current из SimpleFOC. Нужен только откалиброванный
масштаб I1/I2 (Level 1: `ci`-кампания PASS) — реконструкция не требуется.

Предусловия (все — фиксируются в стендовом отчёте):

1. `c` после включения (offsets), `cv` (vbus offset) — `sysinfo` подтверждает
   `acs/ccs` эталонных значений;
2. Level 1 кампания `shunt_cal_campaign.py`: вердикт PASS
   (scale-константы подтверждены);
3. `al` → `align=0` (тракт согласован по знакам и каналам);
4. силовое подключение по регламенту стенда, ротор застопорен НЕ требуется
   (режим статического вектора), но начальный угол зафиксирован меткой.

Процедура (новая команда — отдельное ТЗ/ПР, не входит в этот коммит):

```text
dc <target_ma> <duty_angle_deg>  → замкнуть |I| на target при заданном угле вектора
  → гард: Level-1 PASS + align=0 + vbus в диапазоне + PROTECT чист
  → PI по модулю ошибки тока, выход = амплитуда вектора напряжения
  → телеметрия @DC: i_meas_ma=…:i_target_ma=…:v_alpha=…:v_beta=…:vbus_mv=…
  → критерий гейта: устойчивая стабилизация |I| ±5% в течение 2 с
    при трёх значениях target (300/600/1000 мА) и двух углах (0°/90°)
```

Критерий прохождения гейта 1: регулятор держит модуль тока на цели, знак
управления совпадает с ожидаемым (рост target → рост модуля), катастрофического
дрожания нет. Провал любого пункта → стоп, разбор, возврат к `al`/`ci`.

## 4. Гейт 2: dq/foc_current после qualification реконструкции

Второй гейт открывается только после `sampling_qual.py` →
`A=SAMPLING_QUALIFIED` (Level 2: ≥32 кадров CH1–CH4, окна без WINDOW_INVALID,
`current_reconstruction` по факту кадров) **и** подписи reconstruction
qualification (отдельное ТЗ): `iα/iβ` восстанавливаются из I1/I2 с проверенной
геометрией.

```text
foc_current: id/iq-регуляторы на reconstructed iα/iβ
  → гард: гейт 1 пройден + SAMPLING_QUALIFIED + reconstruction qualified
  → критерий: стабилизация id=0, iq=target; поведение при ступени iq;
    отсутствие расходимости при провороте ротора вручную на малой скорости
```

Скорость/позиция в гейте 2 не замыкаются — это следующий гейт после
первого устойчивого dq-тока.

## 5. Безопасность (обоих гейтов)

- малые токи (≤1 А цели), питание через лабораторный БП с токоограничением;
- `PROTECT`-гарды активны; при срабатывании — стоп и разбор;
- каждый шаг фиксируется в стендовом отчёте (PWM-режим, CCR/вектор, VBUS, показания @ADC);
- любая нештатная реакция (ток ≠ 0 при нулевом векторе, рост без команды,
  нагрев) → немедленный Stop/сброс БП.

## 7. Стендовая процедура ПК-3: align → параметры → первый пуск FOC (сверено с кодом 4507983)

Все команды и ack-строки ниже проверены по фактическому коду коммита `4507983`
(`src/cli.c`, `src/autotune.c`, `src/protect.c`, `src/telemetry_format.h`).

### 7.1 Пре-чек

```text
c → cv → a → sysinfo   (эталонные acs/ccs, VBUS в норме)
```

### 7.2 Align: инварианты знаков (конвенционно-независимые)

Вектор u = −6%, v = w = +3% при равных фазных импедансах даёт iU = −2·iV.
Три инварианта по `@AL`/`a`:

1. **|I1| ≈ 2·|I2|** — отношение ровно 2 при равных усилениях каналов;
2. **sign(I1) = −sign(I2)** — при согласованных конвенциях каналов
   (одинаковый тракт шунт+ОУ, середина ≈ 1.65 В, offset ~2040 отсч);
3. **Ires ≠ 0 ожидаемо** — это канал реконструкции, он видит фазный ток
   такта коммутации; требовать от него нуля на `al` нельзя.

Развилка по знаку: отношение ≈2 и относительный знак верны, но абсолютный
знак противоположен ожиданию → **глобальная** конвенция (одно место на входе
Clarke), а не проводка. Отношение ≠ 2 или одинаковые знаки → **локальная**
причина (канал/offset/gain): локализовать, ничего не инвертировать.

Состав возврата по align: дословный `@AL`, затем `al off` (→ `@AL:OFF`),
`dump`, `dump8`, `sysinfo`, `a` до и после.

### 7.3 Параметры машины (маршрут A или B)

Парсер `mp=Rs,Ls[,Rr,Lm,Tr,Ke,p,J]` (минимум 2 поля, опциональные применяются
только при >0; `mp=200,0,5000` с Ls=0 невалиден — Kp/Ki требуют Ls > 0):

- **A (есть журнал измерений):** `mp=<Rs_mOhm>,<Ls_uH>` → `@MP:OK:…:Kp=…:Ki=…:Lsig=…:AP=1`;
- **B (журнала нет):** `ch` → `iv` → `oew` → `pi=<bw>` → `piapply`.
  Успешные ack-строки: `@AT:RS_IV:OK:Rs=<mOhm>`, `@AT:OEW:OK:Ls=<uH>:Isat=…`,
  `@PI:APPLIED:Kp=…:Ki=…:AP=1`. Все команды имеют собственные
  overcurrent-выходы (`@AT:…:ERROR:OVERCURRENT`).

Юниты токовых референсов — **мА**: `i=<Id>,<Iq>` (пара обязательна,
`FOC_SetIdRef(int32_t ma)`), ack `@I:OK:Id=…:Iq=…`; `Iq=0` = контур скорости.

### 7.4 Первый пуск FOC (окно 5–10 с)

```text
(пред-проверка энкодера: провернуть вал рукой → поле TH в @FOC меняется;
 @FOC печатает STATE/SPD/TH и при STATE=0)
1  → "FOC started" | @FOC:START:FAIL:rc=… (0=OK -1=clock/fault -2=map_unverified
     -3=calib -4=arm -5=pwm_enable -6=params_out_of_range)
окно 5–10 с → наблюдение @FOC: STATE, TH, SPD, FAULT/FAULT_R, Id/Iq
0  → "FOC stopped"
dump, dump8, sysinfo, a
```

`rc=-2` (map_unverified) и `rc=-3` (calib) — это **fail-closed гейты входа**,
а не авария: без действующей карты токов/калибровки первый closed-loop FOC
законно не стартует; симптом фиксируется, план корректируется отдельно.

Защита в окне: `PROTECT_CheckFrame()` выполняется на каждый кадр по **сырым**
`idc1_ma/idc2_ma/vbus_mv` (protect.c) — магнитудные рейлы активны и при
инверсии знака, слепнут только при неверном масштабе усиления. Поэтому
аппаратный лимит источника остаётся единственным гарантированным
ограничителем первого окна.

Стоп-критерии (без изменений): любой FAULT, рост тока к лимиту источника,
шум/вибрация/нагрев, просадка шины → немедленно `0`, затем питание вниз,
разбор по факту телеметрии.
