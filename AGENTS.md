# OEW — правила для ИИ-агентов

Прошивка STM32G474RE: CMSIS, C99, arm-none-eabi-gcc. Цель — работающий код, а не
отчётность. Процесса ровно столько, сколько нужно, чтобы не сломать железо и не
потерять чужую работу.

## Поток работы

Правь → `make` (если код) → push в `main`. Всё. Ветка `ai<N>/<кратко>` от свежего
`upstream/main` — только если задача больше дня или трогает много файлов. CI
(`build-test`) — единственный гейт: красный CI = не вливать. Приёмка — только для
крупного пакета.

## Технические правила

1. **Только CMSIS, без HAL** — регистры напрямую, никаких `HAL_*`.
2. **Регистры — по RM0440** (STM32G4), не по памяти.
3. **Изменил периферию →** `python scripts/cubemx_check.py` (сверка пинов, TIM,
   ADC2, PLL с `OEW_Motor.ioc`). Правил только код/тесты/доки — не запускай.
4. **Проверка на плате — сценарием**: `tests/target/` + `make hwt-run`, отчёт в
   `build/hwt/`; «проверил, всё хорошо» в чате — не проверка. Перед рискованным
   опытом — `make backup`. Без железа: `make hwt-preflight`, `make hwt-sim`.
5. **Зависание — локализуй принтами** (UART/SWO), а не догадками.

## Безопасность (не сокращается)

- `ERROR ≠ PASS`: «плата не ответила» — это не «проверено». Повторный прогон ради
  PASS и сокрытие ошибок запрещены.
- Инъекции в МК (запись значений, принудительный возврат) — только на no-HV.
- Не менять default-deny (`OEW_MAP_CAPTURE`/`OEW_MAP_L3`/`RELEASE`) без явного ТЗ.
- Не пушить секреты и стендовые артефакты (RECORD.csv и т.п.).
- Не переписывать запушенную историю; `reset --hard`/force-push на общую ветку — нет.
- Safety-модули (`src/foc*`, `src/pwm*`, `src/protect*`, `src/vf*`, `src/adc*`,
  `.ioc`) — только по явному ТЗ.
