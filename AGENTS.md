# OEW — правила для ИИ-агентов

Прошивка STM32G474RE: CMSIS, C99, arm-none-eabi-gcc. Цель — работающий код, а не
отчётность. Процесса ровно столько, сколько нужно, чтобы не сломать железо и не
потерять чужую работу.

## Поток работы

Правь → `make` (если код) → push в `main`. Всё. Ветка `ai<N>/<кратко>` от свежего
`upstream/main` — только если задача больше дня или трогает много файлов. CI
(`build-test`) гоняется на push в `main`; на ветке гейт — локальные `make` и
`make test`, а CI при нужде запускается вручную (Actions → Run workflow).
Приёмка — только для крупного пакета.

## Что считается работой

Без явного ТЗ разрешено ровно три вещи: правка прошивки/скрипта, без которой не
идёт прогон; прогон сценария на стенде (`tests/target/` + `make hwt-run`); разбор
результатов прогона. Всё остальное — только по явному ТЗ.

Запрещено заводить без ТЗ: пакеты приёмки, provenance/G0/route-проверки, новые
шаблоны и регламенты, отчёты «что сделано» без прогона, ветки под не-стендовую
работу, новые `.md`-документы. Любая новая сущность (файл, ветка, док) должна быть
нужна для ближайшего прогона — иначе её не создавать.

## Технические правила

1. **Только CMSIS, без HAL** — регистры напрямую, никаких `HAL_*`.
2. **Регистры — по RM0440** (STM32G4), не по памяти.
3. **Изменил периферию →** `python scripts/cubemx_check.py` (сверка пинов, TIM,
   ADC2, PLL с `OEW_Motor.ioc`). Правил только код/тесты/доки — не запускай.
4. **Проверка на плате — сценарием**: `tests/target/` + `make hwt-run`, отчёт в
   `build/hwt/`; «проверил, всё хорошо» в чате — не проверка. Перед рискованным
   опытом — `make backup`. Без железа: `make hwt-preflight`, `make hwt-sim`.
5. **Зависание — локализуй принтами** (UART/SWO), а не догадками.

## Безопасность (не сокращается)

- `ERROR ≠ PASS`: «плата не ответила» — это не «проверено». Повторный прогон ради
  PASS и сокрытие ошибок запрещены.
- Инъекции в МК (запись значений, принудительный возврат) — только на no-HV.
- Не менять default-deny (`OEW_MAP_CAPTURE`/`OEW_MAP_L3`/`RELEASE`) без явного ТЗ.
- Не пушить секреты и стендовые артефакты (RECORD.csv и т.п.).
- Не переписывать запушенную историю; `reset --hard`/force-push на общую ветку — нет.
- Safety-модули (`src/foc*`, `src/pwm*`, `src/protect*`, `src/vf*`, `src/adc*`,
  `.ioc`) — только по явному ТЗ.

## Где что искать

Карта, а не пересказ: подробности — в самих файлах.

- постановки и ТЗ — `docs/tz/`; `archive/` — историческое, не источник истины;
- проверки на цели (HWT/DDTT) — `docs/HWT_DDTT.md`; протоколы сессий стенда — `docs/pc3_bench_kit/`;
- прошивка и отладка — `docs/agents/FLASH_DEBUG_OPENOCD.md`, `docs/agents/STM32_FW_DEBUGGING.md`;
- знания по FOC и разбор ошибок — `OEW_FOC_KNOWLEDGE_BASE_V3.9.md`;
- занятость файлов — `docs/AGENTS_STATUS.md`.

Эталоны, по которым писать новое:

- карта токов, её загрузка и границы — `src/current_map_selector.c`;
- адреса регистров и константы для проверок на цели — `tools/hwt_stm32g4.py`;
- организация сценария HWT — `tools/hwt.py`, `tests/target/hw_safety_idle.py`;
- формат находки — `docs/FINDING_MAP_PLACEHOLDER.md`.
