## 1. Корень — подтверждён исходником (цитаты из `ai2/tz3-mapcap-rec-fields`, идентично в `ai4/foc-first-start-pc3`)

`src/foc.c:1054–1066` (из `FOC_RunFrame`, дословно):
```c

                                     (int16_t)mod_w, &next_context) ||
```

Никакого сообщения — `FOC started` остаётся последней строкой. Это место полностью согласуется с
GATES.md («молчаливый `FOC_Stop()`», `src/foc.c:1058-1066`) и с механикой отказа `matches != 1` в
`src/current_map_selector.c:264`.

Дополнительно из кода:
- масштаб: `V_фазы ≈ mod·Vbus`, `mod = vu·98/100`, клэмп ±32112 (98% Q15) — `foc.c:1049–1053`;
  для I-f в STARTUP (Rs≈15 Ω, Id≈2 А → ~30 В при Vbus 40 В) PI вернёт mod к ~0.75 после первого кадра;
- регионы 6×2=12 — `src/current_reconstruct.h:9-10` (`CURRENT_RECON_MAX_SECTORS 6u / WINDOWS 2u`);
- стартовый вектор карты `mu=8192, mv=0, mw=-8192` (MAP/NOTE.md) лежит в `region[0][0]`
  (полуш-ширина ≈262) — поэтому Старт **принимается** (кадр 1), а любой уход PI — Стоп;
- recovery per-frame: при выходе из бокса PI держит интеграл (сброса нет) — модуляция вернётся в бокс
  сама, так что даже режим «пропуск кадра» даёт следующий шанс;
- проверка перекрытия регионов (`map_regions_sane` + тест `map_region_overlap_test`) — доказывает,
  что **клэмп в селектор закладывать нельзя** (см. §3, решение D).

### Почему карту нельзя сделать управляющей (исправленный расчёт)

Полное пространство в рамках 8-октантного пояса SVPWM: 8 октантов × (радиальный ход ≈ 15 516 Q15 от
r=8192 до r≈23 708). Регионы покрывают 12 боксов: угловой шаг 60° при ширине ≈524 Q15 → ≈10.5%
хода по углу на бокс, ≈3.4% по радиусу → суммарно **≈ 2.5% пространства**, и всё — в узком поясе
r≈8192 (амплитуда 0.25). Управляющей карты из этого не получится никак; ENFORCE-гейт в current-виде
оставляет FOC внутри 12 дискретных векторов, т.е. непрерывное (и вообще какое-либо длительное)
управление невозможно. (Прошлая оценка «≈1%» относилась к сетке 48 — суть та же.)

## 2. Решение: режим-слой в `foc.c`, селектор не трогаем по политике

Заголовок селектора (`current_map_selector.c`, блок над `SelectNextContext`) прямо запрещает
приоритеты/замену контекста: «the next vector must select exactly one physical measurement
aperture», и это требование страхуется CI-тестом перекрытия. Значит:
- **клэмп/overlay внутри `CurrentMap_SelectNextContext` запрещён** (сломает инвариант «ровно один
  апертуры» и тесты);
- вся политика — **выше, в `foc.c`**: решать, что делать с кадром, чей вектор не попал в бокс.
  Селектор при этом остаётся честным датчиком «вектор вне измеренной апертуры», и телеметрия
  `@FOC:VEC:OUT` продолжает фиксировать каждое такое событие — это ровно то, что нужно
  сертификации: не молчать и не подменять измеренное.

### Режим работы (зашит на сборке, не командой)

```c
#define FOC_MAPVEC_MODE  1   /* 0=ENFORCE (как сейчас), 1=SKIP_FRAME (пропуск кадра), 2=ZERO_VECTOR */
```
- **SKIP_FRAME — рекомендуемый дефолт**: кадр без управляющего вектора пропускается (PWM удерживает
  предыдущий CCR), вектор телеметрируется; PI recovery вернёт модуляцию в бокс. Никаких подмен.
- ZERO_VECTOR — запасной (обнуление vu/vv/vw на этом кадре), включать только если на стенде будет
  видно, что пропуск кадра дёргает ток.
- ENFORCE остаётся доступным для верификационного прогона «как было».

Режим командой не переключается и в доках/CI не упоминается → **все рантайм-гейты GATES остаются
нетронутыми** (доп. команды = новые поверхности отказа, а это уже отдельная сертификация).

## 4. Геометрия для GATES.md (заменить абзац «Механизм»)

- Карта: 12 регионов (сечение 6×2), бокс ≈524×524×524 Q15 (полуш ≈262), пояс r≈8192 (0.25);
  стартовый вектор (8192, 0, −8192) внутри `region[0][0]` — поэтому старт принимается.
- Модуляция I-f (PI держит ~0.75 шкалы ≈ mod≈24500) вне пояса → `matches=0` → стоп молча.
- Покрытие 12 боксами ≈ 2.5% пространства 8-октантного пояса (10.5% по углу × 3.4% по радиусу × 12).
- Гейт стоит и в ТЗ-ветке `ai4/foc-first-start-pc3` — образ из CI run 35713510120 сам по себе
  воспроизведёт то же поведение.
