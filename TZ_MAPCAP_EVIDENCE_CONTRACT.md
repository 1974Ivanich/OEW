## 1. Установленные факты ревизии (со ссылками)

| связь | статус | почему |
|---|---|---|
| `sample ↔ CCR` | **PROVEN** | `cap_snapshot()` снимает живые `TIM1/TIM8->CCRn`, `ARR`, `BDTR` в колбэке кадра (`map_capture_port.c:213-225`), равенство запросу обязательно (`map_capture.c:93-107`) |
| `sample ↔ sector/window` | **NOT PROVEN** | метка = кандидат из запроса (`map_capture.c:177`), проверка «метка == кандидат» тавтологична (`:118-123`); в шапке: «diagnostic label only; no control admission» (`map_capture.h:78`) |
| `sample ↔ timing` | **NOT PROVEN** | `trigger_offset_ticks` принудительно 0, «not measurable from timer registers (scope qualification required)» (`map_capture_port.c:220-224`); профиль: `MAP_CAPTURE_BOARD_OFFSET 0 /* scope-qualified stage */` (`map_capture_profiles.c:212`) |
| trigger identity | **PROVEN** | `trigger_revision` = конфигурационная идентичность (не per-sample счётчик) |
| sector/window → UART | **MISSING** | поля есть в `AdcFrame` (`adc.h:54-56`), в `@MC:REC` (`main.c:530`) их нет |

Дополнительно, из кода:

```text
pwm.c:284        TIM1->CR2 = (2u << TIM_CR2_MMS_Pos)   → MMS = 2 (UEV): TRGO = событие UPDATE,
                 т.е. апертура инжектированной группы СТАРТУЕТ НА ГРАНИЦЕ ПЕРИОДА —
                 в том же событии, где перегружаются CCR (preload → active).
                 Следствие: положение апертуры НЕЛЬЗЯ сдвинуть, не меняя MMS (§5.3).
adc.c:164-165    SMPR = 7 (640.5 такта) на всех каналах с комментарием
                 «Use long sampling initially. It must be shortened only after measuring
                 source settling and trigger-window timing on the physical board.»
                 → длинное время выборки — признанная заглушка.
adc.c:4-5, :175  инжектированный триггер: JEXTSEL=0 (TIM1_TRGO), фронт rising.
adc.c:275        ADC1 rank1 и ADC2 rank1 снимаются ОДНОВРЕМЕННО (I1/I2 парны внутри апертуры).
pwm.c:302        TIM8->SMCR = 4 (reset mode, TS=ITR0 TIM1_TRGO) — TIM8 фазово привязан к TIM1.
```

Оценка ширины апертуры (для §5.3): 3 ранга × 640.5 такта @ 42.5 МГц ≈ **45 мкс при периоде 200 мкс**
(≈22 % периода); при этом апертура начинается на границе периода, где происходят переключения.

## 2. §5.1 Evidence schema (контракт `@MC:REC`)

Каждая запись обязана нести нижеперечисленное; существующие поля **не удалять и не переименовывать**.

```text
cap=<capture_id>            идентификатор сессии
seq=<frame.sequence>        монотонный счётчик опубликованных кадров      ← ordering marker
ts=<frame.timestamp_cycles> CYCCNT кадра                                   ← ordering marker
sector=<frame.tim1_sector>  метка И одновременно (после §7b) производная от живых CCR
window=<frame.sample_window>
ccr1=<TIM1 CCR1,CCR2,CCR3>  живые регистры (§7a: снимок на кадр — уже есть)
ccr8=<TIM8 CCR1,CCR2,CCR3>  живые регистры (должны быть неизменны внутри сессии)
arr=<TIM1 ARR>
trig=<trigger_revision>
raw_i1/raw_i2/raw_ct/raw_vbus   сырые коды
i1/i2/vbus                      масштабированные значения
status=<AdcFrameStatus>     fault=<MapCaptureStatus>
```

Честное замечание по ordering marker: `ADC_GetJeosCount()` — **глобальный** счётчик, поэтому
per-record JEOS не заявляется. Per-record маркерами являются `seq` и `ts`; дополнительно
(`§7a`) в запись добавляется снимок счётчика периодов сессии `per=<periods_elapsed>` —
он даёт проверяемый инвариант непрерывности: в статическом burst счётчик обязан расти на 1
на принятый кадр.

## 3. §5.2 Association proof

Требуется доказать **три** звена, а не одно:

```text
sample ↔ exact CCR snapshot         (уже доказано, §1 — сохранить)
sample ↔ sector/window identity     (сегодня НЕ доказано: label only)
sample ↔ конкретный trigger/frame   (сегодня НЕ доказано)
```

**`label == candidate` доказательством НЕ принимается.** Минимальный способ превратить метку в
измерение (не требует железа и не меняет физику):

```text
§7b: sector/window/point ВЫВОДЯТСЯ из живого CCR-снимка по таблице профиля:
     sector — по строгому порядку модуляции (mu>mv>mw …)              (profiles.c:226-233)
     window — по сдвигу кластера (+16 max / −16 min)                  (profiles.c:253-291)
     point  — по смещению сетки (±4)                                  (profiles.c:245-250)
     → exact match CCR-триплета одному из 4 утверждённых векторов ряда
     → derived == candidate требуется; расхождение = terminal СЕССИИ, не warning
```

Тогда проверка становится фальсифицируемой. Обязательный **негативный контроль** (host test, без
стенда): запрос с намеренно неверной меткой (например `sector+1`) обязан привести к отказу
приёмки кадра — если проходит, значит проверка по-прежнему тавтологична и контракт не выполнен.

## 4. §5.3 Timing qualification (HARD-предохранитель)

**Без этого пункта `sector/window physical qualification = NOT PROVEN`,** и утверждение

```text
window=1  →  ADC физически снят в sampling window #1
```

**запрещено** как в отчётах, так и в критериях. `window` сегодня означает три разных понятия
(выбор профиля/сдвиг CCR, `AdcFrame.sample_window`, «sampling window» в шапке
`map_capture.h:79`) — их нельзя считать эквивалентными без измерения.

Что должно быть установлено:

```text
1. TRGO → начало инжектированной апертуры      (текущее значение: НЕИЗВЕСТНО, offset=0)
2. положение апертуры внутри периода           (сегодня: апертура начинается на UEV по MMS=2)
3. ширина апертуры                             (сегодня ≈45 мкс по расчёту, требует подтверждения)
4. отношение к переключениям PWM               (не пересекает ли фронты; и где именно)
```

Метод (осциллограф в проекте не авторитетен — G0 v4 waiver), поэтому **без осциллографа**:

```text
4.1 sweep положения: MMS = OC4REF (7) + устанавливаемый CCR4 = offset, шаг 1…N тактов
    по всему периоду; на каждом offset снимать сигнатуру (i1,i2) в статическом векторе.
    Признак правильного положения: сигнатура перестаёт зависеть от дальнейшего сдвига
    внутри «плато» периода и скачком меняется на переключениях.
    Требует: правку MMS/CCR4 в pwm.c (§7d), проверку, что CH4 не выведен на пин (CC4E=0),
    и cubemx_check после правки.
4.2 sweep ширины: SMPR из утверждённого набора значений (например 640.5 → 247.5 → 92.5 → 24.5
    такта) при неизменном положении; контроль — не «плывёт» ли сигнатура и появляются ли
    признаки недозаряда источника (короткая выборка = меньше заряда, шум больше).
4.3 регистрация результата: измеренный offset и принятый SMPR фиксируются в identity
    (adc_trigger_id / trigger_offset_ticks), после чего конфигурация ЗАМОРАЖИВАЕТСЯ.
```

**Ограничение порядка (критично):** любая правка MMS/JEXTSEL/SMPR меняет ADC config signature и
trigger id → меняется identity карты. Значит §5.3 выполняется и замораживается **ДО** выдачи
identity карты; иначе квалифицированную карту придётся делать заново.

## 5. §5.4 Identifiability criterion (определения заранее)

```text
PHASE_CONVENTION_ESTABLISHED
    существует отображение наблюдаемой матрицы (sector × window × point × канал) в три
    физических фазных состояния, которое одновременно:
      (i)   инъективно — два разных физических состояния не дают неразличимой пары (I1,I2)
      (ii)  воспроизводимо между повторами (в пределах диагностического конверта)
      (iii) согласовано с моделью реконструкции (KCL/вектор)
      (iv)  подтверждено ПРЕДСКАЗАНИЕМ: отклик на не измеренное ранее состояние предсказан
            и затем подтверждён измерением

PHASE_CONVENTION_NOT_IDENTIFIABLE
    два разных физических фазных состояния дают неразличимый отклик (в пределах квантования
    и диагностического конверта) → объявляется NOT_IDENTIFIABLE; выбор «наиболее похожей» фазы
    ЗАПРЕЩЁН

UNREADABLE / INVALID
    отсутствует хотя бы одно HARD-звено доказательства (неполное покрытие, нет CCR-снимка,
    нет ordering marker, метка оказалась echo запроса, есть fault)
```

## 6. Критерии будущего стендового прогона

```text
HARD (PASS только при ВСЕХ):
 1. полное покрытие sector × window (12 рядов) и утверждённых points
 2. для каждого sample присутствует точный CCR-снимок (живые регистры)
 3. TIM8-инвариант подтверждён (неизменность внутри сессии и соответствие утверждённому вектору)
 4. каждый sample имеет однозначный sequence/ordering (seq + ts + per)
 5. sector/window получены из ЖИВЫХ CCR (derived), а не являются echo запроса
 6. trigger → ADC association доказана (§5.3 закрыт: известны положение и ширина апертуры)
 7. UART содержит все поля §5.1, ни одно не потеряно (uart_drp=uart_trunc=0)
 8. нет safety/UART/capture fault (CCER=0 · MOE=0 · @BRK:valid=0 после каждой команды)

DIAGNOSTIC (никогда не HARD):
  повторяемость внутри sector/window · межповторная дисперсия · raw и масштабированные значения ·
  знаки · величины · вариация sector-to-sector · вариация window-to-window · выбросы/пропуски ·
  Ires/ZSV (HW-0, в конвенции не участвует)

INTERPRETATION:
  фазная конвенция объявляется установленной ТОЛЬКО при §5.4(i)-(iv);
  иначе PHASE_CONVENTION = NOT_IDENTIFIABLE.
```
